# 不依赖硬编码的项目约束

## 核心原则

LegalSkillEvolve 的任务效果不得依赖针对特定案件、法域、隐藏标签或预期答案写入代码的特殊
分支，也不得依赖散落在实现中的无来源“魔法数字”。律师在每次咨询中询问什么、何时结束，
应由冻结律师策略根据当前可见状态和会话技能文档自主决定，不能由案件编号或固定对话
模板决定。

“不依赖硬编码”不等于取消所有确定性代码。数据可见性、结构校验、隐私和法律安全约束、
实验资源上限、哈希冻结与统计计算必须由确定性代码执行；否则实验既不可复现，也无法保证
两个比较臂处于同一条件。

## 禁止项

- 按 `case_id`、案件文本片段、数据划分或隐藏 rubric 选择问题、技能、答案或分数。
- 在提示或技能中预埋某案事实、法院认定、正确法律结论或测试集措辞。
- 为使测试通过而对某一法域或样本增加未声明的特殊分支。
- 把没有理论依据、数据依据或敏感性分析计划的阈值直接散落在业务代码中。
- 用 fallback、默认答案或规则分数掩盖模型、教师、评审或执行链失败。

## 允许但必须显式管理的确定性约束

- JSON/schema、权限与泄漏检查、证据来源约束、不可编造和安全停止规则。
- 只读公开opening、所有实验臂共享的非绑定事实议程；它只能初始化可见未知维度，不能按技能、人格、案件答案或实验臂改变内容，也不能选择下一动作。
- 同一冻结律师只对结构、目标身份、隐私边界等会使动作不可安全执行的错误作有界重采样。复读、`unavailable`重问、复合提问或向客户索要法律判断是可评分的律师行为，必须真实调用客户并计入成本和收益，不被程序暗改或拦截。
- 所有实验臂一致的有限对话地平线、采样预算、重试上限与并发上限。
- 奖励公式、案件聚类统计、候选的来源/静态/安全/去重/提示容量硬门，以及周期性库级维护约束。

上述可调参数必须集中配置、写入 `run.json` 并随运行冻结；论文中说明选择依据。会影响结论的
参数必须预先指定敏感性或消融分析，不得观察正式测试结果后再选择。

两个本地模型服务的KV字节、最大上下文、并发序列数、共同运行时余量和启动后空闲下限集中在
`configs/models/roles.yaml`；启动脚本只读取该契约（环境变量仅用于显式实验性覆盖），不再按
模型名称散落硬编码分片名或显存比例。

## 对话轮数的具体约束

- 在线输入不含固定轮数、剩余轮数或“必须问满”的目标。律师策略在每个可见状态上选择继续询问、
  `final`或`abstain`；正式学习文档可改善事实询问、证据缺口识别和信息保持的安全停止，但只作为冻结Qwen的提示工作记忆。逐轮输入回放此前完整律师问题与客户回答，并附紧凑状态账本；共享opening-only议程不规定问题顺序或最低轮数。系统不按规则替换目标或代写问题，实际轮数因此应随案件、技能文档和轨迹变化。
- 客户调用前的有界修正仍由同一冻结律师完成，但只修正不可执行的契约/安全错误。所有可执行的低质量问题由客户正常回答并进入评分；工程失败的`contract_fallback`不建立已问/不可得结论，可由同一策略在后续回合干净重试。
- `emergency_turn_ceiling=24`是所有比较臂共享、且不向律师展示的应急安全上限，不是咨询地平线或训练
  目标。它只防止失控策略无限占用资源；命中上限本身仍是冻结律师的真实、可评分失败结果。
- 命中上限必须明确记录为`max_turns_forced_memo`；强制memo只完成安全收口，不得伪记为律师自主结束。
  全部真实问答、提问成本、收益和终止状态继续进入评分、组内优势与教师证据；该轨迹不是健康成功，但也不得被当作执行完整性故障判废或重采样。
- 熔断值随实验配置和run manifest冻结；不得根据训练、开发集或官方30案结果调整，也不通过
  预设4/6/8轮模板制造“多轮提升”。

## 启动门禁

正式主实验开始前必须有自动化测试证明：opening议程只看公开开场且跨臂一致；律师可见此前完整问答和与轨迹状态一致的在线账本，但看不到隐藏事实编号；充分状态可自主提交；存在有价值可问目标时仍能继续；同模型动作修正不改实验干预；可执行的差问题必须真实计入提问、重复、收益和教师证据；`contract_fallback`不污染对话且不阻止干净重试；应急上限不进入律师可见输入；一旦命中上限，轨迹状态、停止门裁决和强制memo标记必须一致，且该策略失败仍可评分、可归因并进入教师证据。当前实现若不满足这些条件，预检必须失败，不得靠人工解释后继续。
