# 不依赖硬编码的项目约束

## 核心原则

LegalSkillEvolve 的任务效果不得依赖针对特定案件、法域、隐藏标签或预期答案写入代码的特殊
分支，也不得依赖散落在实现中的无来源“魔法数字”。律师在每次咨询中询问什么、何时结束，
应由冻结律师策略根据当前可见状态和会话技能文档自主决定，不能由案件编号或固定对话
模板决定。

“不依赖硬编码”不等于取消所有确定性代码。数据可见性、结构校验、隐私和法律安全约束、
实验资源上限、哈希冻结与统计计算必须由确定性代码执行；否则实验既不可复现，也无法保证
两个比较臂处于同一条件。

## 禁止项

- 按 `case_id`、案件文本片段、数据划分或隐藏 rubric 选择问题、技能、答案或分数。
- 在提示或技能中预埋某案事实、法院认定、正确法律结论或测试集措辞。
- 为使测试通过而对某一法域或样本增加未声明的特殊分支。
- 把没有理论依据、数据依据或敏感性分析计划的阈值直接散落在业务代码中。
- 用 fallback、默认答案或规则分数掩盖模型、教师、评审或执行链失败。

## 允许但必须显式管理的确定性约束

- JSON/schema、权限与泄漏检查、证据来源约束、不可编造和安全停止规则。
- 所有实验臂一致的有限对话地平线、采样预算、重试上限与并发上限。
- 奖励公式、案件聚类统计、候选的来源/静态/安全/去重/提示容量硬门，以及周期性库级维护约束。

上述可调参数必须集中配置、写入 `run.json` 并随运行冻结；论文中说明选择依据。会影响结论的
参数必须预先指定敏感性或消融分析，不得观察正式测试结果后再选择。

两个本地模型服务的KV字节、最大上下文、并发序列数、共同运行时余量和启动后空闲下限集中在
`configs/models/roles.yaml`；启动脚本只读取该契约（环境变量仅用于显式实验性覆盖），不再按
模型名称散落硬编码分片名或显存比例。

## 对话轮数的具体约束

- 在线输入不含固定轮数、剩余轮数或“必须问满”的目标。律师策略在每个可见状态上选择继续询问、
  `final`或`abstain`；技能文档只作为模型的会话方法记忆，系统不在模型输出后触发规则、替换目标或改写动作。实际轮数因此应随案件和轨迹变化。
- `emergency_turn_ceiling=24`是所有比较臂共享、且不向律师展示的异常熔断，不是咨询地平线或训练
  目标。它只防止实现循环和失控策略无限占用资源。
- 命中熔断必须明确记录为`max_turns_forced_memo`并由pre-scoring健康门判废；不得把强制memo伪记
  为律师自主结束，也不得让该轨迹进入评分、组内优势或技能教师。
- 熔断值随实验配置和run manifest冻结；不得根据训练、开发集或官方30案结果调整，也不通过
  预设4/6/8轮模板制造“多轮提升”。

## 启动门禁

正式主实验开始前必须有自动化测试证明：充分状态可自主提交；存在有价值可问目标时仍能继续；
熔断数值不进入律师可见输入；一旦命中熔断，轨迹状态、停止门裁决、强制memo标记和健康门判废
保持一致。当前实现若不满足这些条件，预检必须失败，不得靠人工解释后继续。
