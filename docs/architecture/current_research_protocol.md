# LegalSkillEvolve 现役研究协议

> 现役真源，修订于2026-09-26。旧run、旧逐法域文档协议和历史报告不得resume或解释新结果。

## 研究问题

在不更新模型权重的条件下，冻结Qwen3-8B能否从同案K=4法律咨询轨迹的组相对经验中持续改进一份可审计、紧凑的事实调查playbook，并在后续未见案件和官方CN30上以更少提问获得更多关键客户事实。

playbook是提示工作记忆，不是程序规则。它随客户开场、此前完整的律师问题与客户回答以及在线状态直接进入每轮Qwen的完整行动调用。Qwen自主继续、结束、选择已跟踪目标，或用`new_visible_gap`提出新的可观察事实维度；程序不运行技能触发器、领域检索器、技能条件计划器或独立动作改写模型。

选择单一跨法域playbook并不是否认领域知识的价值，而是为了让论文中的干预来源可识别：逐领域文档会同时引入领域元数据、路由正确性、多文档组合和上下文预算四个额外变量，还曾造成训练得到的专用文档在官方外测未被投递。统一文档让跨法域共有的事实询问机制汇聚在同一稳定对象中，以来源绑定的局部编辑持续演化，并保证训练和外测都不依赖案件领域标签。四臂主表为公平投递Luna-Direct等领域型基线而共享的固定路由属于评测基础设施，不是Ours的技能触发器。

为避免“只有历史账本、没有可见下一步调查空间”，同一冻结Qwen在每案开场时只读取公开opening，生成一次共享、非绑定的事实议程。同案K=4及所有比较臂复用同一议程。模型输出仅含opening中的逐字连续`topic_excerpt`和一个闭集`attribute`；Python验证来源与属性是否尚未回答，并确定性渲染目标，所以模型不能把开场外主体、事件、法律概念或数值写入议程。它不读取playbook、人格、隐藏事实、评分或实验臂，不规定顺序、最低轮数和下一动作；显式空议程仍保留`new_visible_gap`。因此它是所有臂一致的环境状态初始化，不是Ours的额外技能或第二策略。

## 顺序训练

1. 自建128案冻结为8块×16案，每案只属于一块。训练使用合作型`P_WD`；四人格只用于最终官方CN30稳健性评测。
2. 每案K=4共享opening、opening-only议程、批首playbook和seed，使用四条独立策略采样流。温度0.7；不升温强造差异，不混入无技能候选，不预生成封闭问题计划。
3. 每个归因健康K组形成一张完整证据卡，保留四路目标、问题、客户回应类型、事实增量、提问数、安全标记和最佳/最差代表对话。差异组提供真实相对成功/失败信号；tie组只提供共同失败，不能伪造成功。含fallback或其他不可归因干预的整组在评分和教师前隔离。
4. 每块全部健康卡确定性分成两个互不重叠的map包。每个map同时接收这些轨迹实际使用的精确父playbook（首批为null），Luna据此区分新机制与纸面已有但仍未执行的条款，并抽取来源绑定的成功/失败机制；第三次Luna调用将两包机制跨案件合并和去重。
5. reduce只输出对同一稳定ID `general.legal_fact_elicitation_playbook` 的精确`ADD/REPLACE/DELETE`操作：首次创建为0—8个，已有版本每批为0—2个。每个操作只承载一个可在未来独立替换的原子规则，禁止用内嵌编号清单或多个分号把若干独立指令打包。可编辑字段只有`procedure`、`question_guidance`、`contraindications`、`failure_modes`；名称、范围、目标和预期效果由系统固定。未命中的旧条款逐字保留；行为证据已支持且现有条款可执行的重复机制应NOOP，但纸面覆盖而同类失败持续出现时允许REPLACE为更可执行的条件—动作规则。禁止以逐条替换方式整份重写。
6. 每个map包必须对每张卡逐项记账：被至少一个机制引用，或明确标注为无新增机制。每个非空操作必须引用map阶段真实提取过的group ID；候选再通过schema、来源哈希、隐藏信息隔离、法律安全和提示容量硬门。通过后直接进入工作库并发布为下一playbook版本；单块效果不拒收或回滚。
7. 第1—7块可创建或更新playbook。第8块教师预算为0，只观察第7块增量并冻结最终库。

## 对话状态与动作执行边界

逐轮律师输入含公开opening、此前完整问答历史和紧凑在线状态。在线状态列出可见事实目标、状态、已问目标、每轮回应类型与信息增量，但不暴露客户隐藏事实编号；opening议程目标与对话中新建目标一样会随回答更新。它不是只看上一轮的无状态问答，也不是由程序替律师排序的封闭清单。

客户端调用前，只有结构、目标身份、隐私或泄漏边界等会使动作不可执行的错误，才交给同一冻结律师在原可见状态和同一playbook上有界重采样。程序只反馈通用违例，不代写问题或挑选替代目标。客户事实路由可匹配问题所问的相关原子属性；状态去重则使用独立的严格完整事实身份判据，时间与时长、复合与原子、不同事件阶段不得互相重绑定。

精确重复、重问已标记`unavailable`的目标、复合提问和要求客户作法律判断都是可执行但低质量的律师行为，不进入修正回路。它们必须真实送达客户，并连同实际客户回应、事实增量和行为警告计入提问数、重复率、收益和教师证据，不得隐藏改写、拦截或免费重采样。会话只由律师自主`final`/`abstain`或不向律师暴露的应急horizon结束。命中horizon是安全上限下真实、可评分的策略失败：完整保留已发生的问答、提问成本、收益和终止状态并进入教师证据；它不是健康成功，也不是需排除或重采样的执行完整性故障。健康的自主终止也不因仍存在可选`new_visible_gap`而被强行改回提问。

客户路由是与律师和裁判隔离的冻结gpt-oss闭集选择。首次得到结构有效的空匹配只触发同一路由器、同一候选集合、既有有限修复预算内最多一次独立复核；代码不恢复候选、不重排候选、不生成回答。第二个空结果立即确定性渲染`unavailable`，不因总预算尚余而继续投票，从而在不把环境变成多数表决的前提下抑制一次偶发漏配，并保留全部尝试供审计。

## 前瞻曲线

若上一块产生新版本，第b块的正常sample-0轨迹与精确父版本影子按同案、同persona、同seed、同sample和同策略流配对；两臂唯一处理差异是逐轮可见playbook。无版本变化时写identity记录。

每点完整报告F/Q、事实数、提问数、事实覆盖、重复、过早结束、unsupported、安全与运行端点，以及案件聚类bootstrap区间。该结果描述上一版本在下一未见块的联合增量，并作为下一次局部编辑的诊断信息；它不是逐条规则的显著性检验，也不控制库指针。

每个版本增量还必须由执行器证明整份全局playbook覆盖下一块全部配对会话。机制报告以文档ID、提示哈希和完整块暴露率为准；现役运行时没有技能触发/选择动作，不报告由模型自述产生的技能激活率。

B8在计算前冻结current、empty及必要的exact-parent臂，同时报告B7版本增量和累计playbook相对empty的诊断。性能非通过照实保留；只有干预隔离失败阻止最终冻结。

## 模型职责

- Qwen3-8B：每案共享opening-only事实议程、逐轮律师行动、最终memo，以及四臂共用的官方opening-only领域标注。议程与律师角色使用隔离提示和权限；它们都不看隐藏belief、court record或评分标准。
- gpt-oss-20b：权限隔离的客户事实选择和离线语义评分；不接触技能身份、教师推理或实验臂。
- gpt-5.6-luna：只在训练阶段从完整K组卡抽取机制并策展playbook；不评分、不回答客户、不决定硬门、不看官方案件结果。
- 确定性代码：状态机、披露渲染、reward、证据卡、来源绑定、精确局部编辑、硬门、版本、配对统计与哈希；不从差轨迹伪造成功，也不替律师行动。

## 最终评测与主张边界

冻结后在官方CN30上由一个控制器运行Base、Luna-Direct、ExpeL-adapted和LegalSkillEvolve，共享模型、客户、裁判、seed和预算。全局playbook不依赖领域元数据，因此训练run自身的Ours-vs-empty诊断固定使用`general`上下文，不创建领域路由角色或报告。四列主表为公平投递Luna-Direct等多领域基线而共享的方法无关固定领域路由；该路由不读取任何方法库，也不属于Ours干预。

论文可以主张：完整K组经验经跨轨迹抽象形成来源可追溯的外部策略文档；文档以有界局部编辑持续演化；下一未见块记录版本增量；最终同案四臂衡量冻结整体方法。不得把提示学习写成权重GRPO，不得把下一块联合增量倒签为单条规则永久有效，也不得虚构不可观测的“技能调用率”。
