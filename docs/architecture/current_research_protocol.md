# LegalSkillEvolve 当前研究协议（128案）

修订日期：2026-09-09。本文是现役执行真源；60案、42+18、固定18案验收池、逐候选后一块配对准入、`provisional/DEFER`生命周期、运行时技能触发器与动作改写器均已退役。历史运行只可用于诊断，不得恢复或计入现行实验。

## 研究问题与唯一学习干预

在冻结Qwen3-8B上，能否从同案K=4独立采样形成的高低收益完整轨迹差异中归纳结构化法律咨询技能文档，使同一模型随工作技能库积累，以更少的有效提问取得更多关键事实，并改善必要证据缺口识别与问题解决，同时不增加幻觉、重复追问或过早结束？

LegalSkillEvolve不微调权重。核心问题是技能库随顺序经验充实后，冻结律师能否提高事实获取效率。会话开始时，程序只按公开法域选择工作库中适用的`general + domain`技能文档，形成排序固定的会话技能包；同一文档包进入同一冻结Qwen的会话前调查规划和之后每轮律师决策。Qwen自主决定如何运用。程序不把文档编译成目标选择规则，模型提交动作后也不会再按技能规则触发、替换目标或改写动作。停止机制负责防止过早定论、无依据结论和异常无限循环，是安全约束而非论文的唯一主线。

## 顺序数据流

1. 自建128案全部属于顺序训练过程，冻结为8个块，每块16案。每案只属于一个块；所有块统一使用合作型`P_WD`，客户只需理解当前问题并如实披露匹配到的有限事实。四人格只在最终官方外测中检验迁移稳健性。
2. 第\(b\)块以块首工作库\(L_{b-1}\)生成16×K4轨迹，第一块的\(L_0\)为空。每案四条轨迹看到相同opening、合作型人格和适用技能包，各自独立采样完整调查计划与逐轮动作；程序不注入指定首问、次问或技能动作。
3. 健康门只判定轨迹能否成为可信训练证据。泄漏、协议损坏、不可归因fallback、非法状态转换或不完整K组失败关闭；事实产率低、问题不理想、重复或健康的提前结束保留为可评分行为，不以“表现差”为由阻断教师。
4. 离线评分形成组内优势，只把在F（新客户事实）、G（外部证据缺口）或信息不损失下提问效率上优于低分轨迹的完整对照形成来源簇。来源见证确认候选来自同案、同人格、同块首技能库的真实分叉，不把来源相关性冒充为最终效果证明。
5. 每块最多向Luna提交3个未尝试且fingerprint不同的合格证据簇。通用与领域证据同时存在时至少各覆盖1簇；剩余席位优先不同的行为机制和法律领域。通用簇即使需要截断教师上下文也必须保留至少两个来源法域，领域簇保留其声明法域。一个领域内真实分叉可以支持边界明确的领域技能，通用技能仍须有跨法域来源。
6. Luna对每个簇输出一个结构化技能文档或`NOOP`。候选依次通过静态合法性、来源因果重放、法律与运行安全、语义去重和工作库联合提示容量硬门。这些门只回答“是否真实、合法、安全且可部署”，不要求候选先在16/18案上取得统计收益。来源分叉轮由系统保存的`ContrastSelection/SourceWitness`决定，不因教师自填诊断轮次或来源数量不同而改变门槛。
7. 通过硬门的候选在本块结束时直接写入\(L_b\)，下一块所有适用轨迹从规划开始自然看到完整工作库。K=4不拆成候选有/无技能臂；没有`provisional`、逐候选`ACCEPT/DEFER/REJECT`或三块等待期。第八块仍可生成并入库，随后冻结最终库。
8. 每块在读取本块结果前已经固定8个合作型观察案。正常K=4使用\(L_{b-1}\)，只为这些案件增加匹配空库影子，以记录整个块首技能库的prequential效果；影子不进入组内优势、教师证据、候选准入或官方测试。第2、4、6、8块后进行库级静态合法性、精确去重、领域覆盖和提示容量复核，并绑定技能暴露及整体效果，不用单个候选的小样本胜负追溯性门控。
9. 最终工作库冻结后，官方DLawBench中文30案×4人格×seed42才进入外测。它不参与运行调试、模型/提示/门槛选择、教师上下文、技能准入、库维护或后续调参。由于它是公开基准，论文主张严格held-out执行边界，不把它夸大为研究者不可见的私有盲测。

## 健康、安全与归因边界

- 轨迹健康和策略效果是两回事。健康门阻止损坏数据污染学习；弱律师没有问到事实、出现有效的优劣差异或某块产量为零，属于结果和诊断，不应靠fallback、强制问题或降低事实真实性去“修复”。
- 候选硬门不读取后一块或官方30案效果，也不按“每块必须入库一个”放宽。只要来源与部署条件合格就直接积累；候选数量0—3是数据驱动结果，不是强制配额。
- 技能文档本身只保存可投递方法、状态与来源，不再携带旧协议的逐候选配对收益或`accepted_at`字段；直接准入、版本提交、整库曲线和维护结论分别保存在不可变报告中，避免把不同证据层混入提示文档。
- 领域技能按其适用法域评估来源边界，不要求它解决婚姻、刑事等所有无关领域；通用技能才要求跨法域证据。主流程在准入时阻止精确重复和容量溢出，周期维护报告只绑定整库状态；若需合并或移除，必须另建有来源与版本记录的维护实验，不能从累计效果倒签单技能结论。
- 教师复用已有`skill_id`但给出不同文档属于可预期命名碰撞：该提案被审计拒收、原文件保持不变，其他候选继续处理；只有同ID且同定义的文件才可作为中断恢复。命名碰撞不能令整块或整个run重启。
- 每条现行轨迹记录`skill_delivery_mode`、`exposed_skill_ids`和`skill_memory_sha256`；每个决策回合记录同一暴露ID集合。任何旧`activated_skill_ids`或带`skill_id`的动作改写都会使轨迹失败关闭。
- 训练客户模拟器只在完整且固定的有限client belief集合中匹配律师当前问题，并如实披露被允许的事实；它不评价律师问题好坏。语义裁判只评分已完成轨迹，不参与客户回答或技能生成。
- 法律相关行为遵循`configs/compliance/china_research_boundary.yaml`：泄漏、无关敏感信息收集和越权法律保证属于硬边界；多问、抽象询问、请求客户法律判断等弱律师行为保留并计分，以便轨迹比较和技能学习，不把效果缺陷伪装成数据损坏。

## 模型与统计角色

- `Qwen/Qwen3-8B`：冻结咨询代理；同一快照的独立调用承担会话前规划、逐轮律师策略、memo，以及仅在四人格外测中启用的披露信号分类。所有调用都不读取隐藏rubric。
- `openai/gpt-oss-20b`：权限隔离的客户闭集路由与离线语义评审；两种调用不共享提示或输入，但论文披露复用同一权重可能带来的相关偏差。
- `gpt-5.6-luna`：只从训练证据簇生成候选或`NOOP`，不评分、不看未来块或外测结果、不自行决定硬门。
- 确定性代码：状态机、客户回答渲染、奖励公式、组内优势、来源绑定、候选硬门、库级维护、哈希和案件聚类统计；奖励中的部分语义标签由冻结评审模型产生。

论文报告每块教师证据簇、候选、硬门结果、工作库规模、文档暴露、事实/证据缺口增量、每次提问事实收益、重复/过早结束/unsupported主张、DLawBench兼容指标和案件聚类区间。结构化文档没有离散工具调用事件，因而不虚构单技能使用率。确定性的“唯一新事实/提问”是主终点，唯一事实总数、Fact Coverage和Resolution共同约束少问早停投机；prequential曲线是顺序开发证据，最终效果结论来自冻结库后的held-out官方30案外测。

## 与相近工作的关系

- [ExpeL](https://arxiv.org/abs/2308.10144)与[Agent Workflow Memory](https://arxiv.org/abs/2409.07429)表明，冻结模型可以从历史轨迹归纳自然语言经验或工作流，并把它们作为后续任务的上下文记忆；这支持本项目把技能定义为可读文档而非隐式动作改写器。
- [SAGE](https://aclanthology.org/2026.acl-long.69/)的Sequential Rollout让先前任务产生的技能在后续任务链中累积可用；本项目采用同样的“先学习、后续块使用”时间方向，但不复制其AppWorld任务、参数训练或Skill-integrated Reward。
- [SkillOpt](https://arxiv.org/abs/2605.23904)说明held-out验证适合约束一个统一技能文档的文本优化。LegalSkillEvolve面对的是同一工作库中0—3个来源各异的新文档；为避免把有限案件反复拆成逐候选小臂并造成产量瓶颈，现役主流程只以来源与安全硬门准入，在prequential与最终外测中评估累计库。这个差异必须在论文中明确，不把文献当作本协议的等价实现。

这些工作提供的是设计依据，不替代本项目自身的消融：最终仍须用相同冻结Qwen比较空库、固定技能和演化技能库，并报告逐块整库曲线，才能判断收益来自何处。

批次唯一真源为`configs/data/main_training_batches.yaml`；实验与角色配置分别为`configs/experiments/main_experiment.yaml`和`configs/models/roles.yaml`。
