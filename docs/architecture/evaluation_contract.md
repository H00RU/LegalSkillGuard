# LegalSkillGuard 当前评估契约

## 谁做什么

- 客户事实路由：冻结gpt-oss-20b只在律师当前问题与有限client_belief之间做闭集匹配；回答文本由程序绑定事实。它不判断律师好坏。
- 语义评审：另一套权限隔离提示下的冻结gpt-oss-20b按DLawBench兼容rubric给出结构化语义标签；程序确定性换算分数。故“公式确定性”不等于“全部评价不依赖模型”。
- 确定性检查：泄漏、重复、协议、fallback、来源见证、技能文档暴露、哈希和安全门。
- Luna：只生成候选，不拥有评分或准入权。

本地单裁判不等价于DLawBench官方多供应商评审团，因此论文声称“DLawBench兼容指标下的内部配对比较”，不冒充官方排行榜结果。

## 训练信号与候选准入

训练语义指标包括Fact Coverage、Inquiry、Fact Resolution、Issue Resolution、Fidelity，并派生Elicitation和Resolution。组内奖励差只用于发现候选来源，不等于技能已经有效。

候选须依次满足：

1. 来源正负轨迹在分叉前共享可见状态，且改进能归为F、G或safe-stop之一；
2. 候选结构无案件专有信息，通过安全检查和全部声明来源的确定性重放；
3. 在紧接的未见16案块中预先分配适用案件，控制与治疗从首轮起分别看到“正式库”和“正式库+候选”；不另跑验收对话；
4. 奖励读取前验证技能提示是唯一干预，轨迹协议健康；
5. 健康配对上平均奖励严格为正，并复现新事实增加、合法证据缺口增加，或不损失信息的提问减少；
6. unsupported、过早结束、把belief写成事实、重复、关键事实召回和各类fallback均不得回归；案件聚类实质负尾率不得超过预声明界限；
7. 通用技能至少覆盖2个独立未见案件和2个法域；领域技能至少覆盖1个新的同领域案件。覆盖不足但安全正向可`DEFER`，最多累计3块。

“暴露”表示候选文档确实存在于治疗会话每轮提示中，不表示规则命中。正式系统没有运行时技能触发/动作改写，因此不会再把“零触发”伪装成收益为0，也不会把独立重采样差异误算成技能收益。

## 学习曲线与最终测试

每批固定8个哨兵案，比较当前正式库与空库，记录：

- 每次提问获得的唯一新事实数（主机制曲线）、唯一新事实总数、F/G有效回合和总提问回合；
- Fact Coverage、Inquiry、Elicitation、Resolution、Fidelity；
- 重复、过早结束、unsupported、关键事实召回与fallback；
- 候选转化和正式库规模。

哨兵曲线只作开发诊断，不参加候选选择。主外测在冻结技能库后使用官方中文30案×4人格×seed42，对`control_no_library`、`ungated_source_grounded_skills`和`legal_skill_guard`做共同随机数配对。未门禁臂不读取候选效果，按来源批次及来源报告顺序在同一冻结提示容量内first-fit，完整记录容量未纳入项且不截断文档，避免到最终外测才因累计候选超上下文失败。主终点是由实际披露事实ID和提问回合确定性计算的“每次提问取得的唯一新事实数”；唯一事实总数、Fact Coverage和Resolution是防止少问早停投机的配套终点，并报告Elicitation、Fidelity、安全指标和案件聚类95%区间。预声明6案seed43/44同时复核主终点与DLawBench兼容指标的方向稳定性。

客户路由和语义评审复用同一gpt-oss-20b权重，但提示、可见字段、schema和缓存完全隔离；这节省了供应商与显存，却仍可能带来相关模型偏差。因此主要行为主张以确定性披露ID为准，judge-heavy的Resolution不再承担唯一主结论，论文把这一复用明确列为限制。

只有活动文档在适用外测会话中确实暴露，且效果、安全和机制指标共同改善，才归因于技能学习。
