# LLM角色与论文归因边界

## 冻结Qwen3-8B

Qwen承担四个隔离角色：共享opening-only事实议程、逐轮律师策略、最终memo和四臂共用的官方opening-only领域标注。

事实议程角色每案只读一次公开opening，不读playbook、人格、隐藏事实、评分或实验臂。它只能返回opening中的逐字连续主题短语和一个闭集事实属性，目标标签由Python确定性生成；自由文本不能引入开场外主题。其输出由同案K=4和所有比较臂共享，只把开场支持且尚未知的客户可回答维度写入状态；它不规定顺序、最低轮数、下一动作或终止条件，显式空议程也不封闭`new_visible_gap`，因此不是技能条件计划器或第二策略。

训练与Ours测试中，一份全局playbook、公开开场、此前完整的律师问题与客户回答以及紧凑在线状态直接进入律师的完整动作决策。Qwen自主提问或结束，也可用`new_visible_gap`提出新事实维度。正式入口没有技能选择器、检索器、技能条件计划器或独立动作改写模型。

空库与Ours的唯一处理差异是逐轮提示中是否含冻结版本的playbook。程序记录暴露ID、版本、提示哈希和实际动作，不要求Qwen自报采用了哪条规则。

客户调用前的结构、目标身份或隐私边界错误不交给另一个模型：同一冻结Qwen在原可见历史、状态和playbook上有界重采样。复读、`unavailable`重问、复合表面或向客户索要法律判断若仍可执行，则不再作为契约错误修复，而是真实送达客户并计入提问、重复、收益和教师证据。健康的自主终止不被可选新维度强行改回提问。

客户有限认知仍由独立冻结的gpt-oss闭集路由器完成，程序不替它选择事实。首次得到结构有效的空匹配时，只在既有有限修复预算内由同一路由器对相同候选集合最多复核一次主体、事件、属性和否定前提；第二个空结果立即作为真实`unavailable`保留，不因总预算尚余而继续投票。该复核不看技能、评分或隐藏法院记录，也不以规则恢复某个候选。

## 本地gpt-oss-20b

- 客户事实选择：只读取案件隐藏事实、当前律师问题和已披露集合，决定本轮可披露事实；不判断律师好坏，不接触技能或reward。
- 离线语义评分：在完整轨迹结束后做事实分区、主张溯源和DLawBench兼容评分；不看技能身份、教师输出或实验臂。

两个角色共享冻结模型服务但提示、输入权限和缓存隔离。

## gpt-5.6-luna

Luna只做训练技能教师。每个健康案件的K=4由代码压缩为完整证据卡；两个map调用覆盖全部卡，并同时绑定该批轨迹实际使用的精确父playbook，以抽取来源绑定的成功/失败机制并识别纸面条款的执行缺口；第三个reduce调用跨案件合并去重并提出对单一playbook的有界局部编辑。

Luna不评分、不回答客户、不决定硬门或库指针，也不看未来块隐藏信息或官方测试结果。tie组只能提供共同失败。reduce不能自由重写文档；系统只执行引用过真实mode来源的精确ADD/REPLACE/DELETE。

## 确定性代码

代码承担状态机、客户披露渲染、reward、K组统计、证据卡压缩、两map包完整覆盖检查、来源轨迹/评分哈希、局部编辑执行、法律安全/泄漏/容量硬门、版本化整库、配对统计和bootstrap。代码不生成技能内容，不从差轨迹伪造成功，也不替律师提问、选择下一目标或提前结束会话。

## 论文方法边界

训练中的K=4提供group-relative经验，但模型权重没有GRPO更新；准确表述是`group-relative trajectory-guided playbook evolution`。四臂的记忆来源分别为空、Luna-Direct静态文档、ExpeL经验和LegalSkillEvolve持续演化playbook。全局playbook不依赖案件领域元数据，避免专用技能在官方外测无法加载的归因漏洞。
