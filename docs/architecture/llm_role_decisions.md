# LegalSkillEvolve 主实验LLM角色决定

正式运行链只有三个唯一模型，但按输入权限拆成七种功能调用。状态、奖励公式、优势、技能文档渲染、来源见证、候选硬门、库级维护、哈希和统计由确定性代码完成；Inquiry、Resolution与Fidelity等语义标签仍来自冻结评审模型，不能把“公式确定性”写成“全部评价无模型参与”。

## 技能教师与准入边界

技能教师不是TF-GRPO律师，也不修改Qwen权重。它不能看未来训练块、官方30案、prequential空库影子或实验臂效果，不能评分，也不能自行决定技能是否入库。每块最多选择3个未尝试且fingerprint不同的合格证据簇；若通用和领域证据都存在，选择器至少各保留1簇，第三席优先不同机制与不同法域。因而八个来源块的最坏教师调用上限是24次，但0—3是数据驱动范围，不是强制产量。

Luna对一个证据簇输出一个边界连贯的结构化文档或`NOOP`。候选随后由确定性代码检查静态合法性、来源因果重放、法律与运行安全、语义去重和工作库联合提示容量；全部通过就在该块结束时直接写入工作技能库，从下一块起按`general + 当前法域`固定提供给Qwen规划和逐轮策略。不再存在后一块逐候选效果验收、`provisional/DEFER`状态或候选控制/治疗臂。来源对照证明的是“这个方法由真实轨迹差异支持”，prequential与最终外测评估的是“累计技能库整体是否有效”，两者不能互相冒充。

项目级Luna调用仍受跨进程共享硬账本约束。现行上限为225次：已有200次记录，加上fresh八块最坏24次教师调用和最多1次预检，不额外预留模糊预算。失败调用计账，缓存命中不重复计数，禁止fallback教师。实际已用量和余量只从硬账本动态读取；预检按未完成来源块每块最多3次核算最坏新增调用，不在文档中硬写易漂移的实时计数。

## 本地模型复用边界

客户路由与离线评审复用同一冻结gpt-oss-20b权重和服务，但不是同一个决策：二者使用隔离提示、输入权限、结构schema及运行缓存。客户路由看不到评分rubric、法院记录、技能和实验臂，不能评价律师表现；其输入中的事实集合与顺序不随披露历史变化，选中后才由状态机区分新事实、重复事实或开场重述。离线评审不参与客户答复。

同权重复用仍可能产生相关模型偏差，隔离接口不能把它证明为统计独立。论文因此以实际披露fact ID计算的“唯一新事实/提问”作为主终点，以唯一事实总数、Fact Coverage和Resolution约束少问早停投机；judge-heavy指标用于兼容比较和配套解释，不单独承担全部效果归因。

Qwen3-8B固定revision为`b968826d9c46dd6066d109eabc6255188de91218`；实际本地快照、权重清单、提示、schema、解码参数和服务身份必须进入run绑定。训练K=4的四条轨迹使用同一合作型客户环境和块首技能库，但各自独立采样；Qwen仍是唯一选择在线咨询问题和自主终止时机的模型。紧急轮数上限只作隐藏熔断，停止策略是安全约束，不是取代“更少提问取得更多事实”的主目标。

本地单裁判不等于DLawBench官方多供应商面板。论文必须披露模型revision、资格结果、确定性行为指标、最终同案配对效应与95%区间；当前没有法律专家标注资源，研究者的盲化事实核对只能作为误差分析，不能冒充法律专家一致性。
