## 固定的数据流

1. 保持原TRAIN128来源、8批、每批16来源；每个来源含EC/EV，共256任务。
   按原顺序逐任务在线处理，先保存该任务的真实8B首答，再释放其原TRAIN标签。
   EC/EV独立空库起步，不导入任何退役运行的库、回答、教师结果或重放缓存。
2. 首答失败时，同一强教师看到原公共任务/格式、原失败输出和当前TRAIN目标，
   生成训练专用reference_answer、简短可核查公开说明及诊断，不在此步骤生成修补。
   reference_answer严格采用原actor公共资产/引用格式。
3. 用原公共标签双射解码参考，调用原评分器和原先固定的native pass合同验证。
   不复制目标来代替教师输出，不修数值、不补引用、不另加语义裁判或fallback。
   每个失败任务生成一次参考，所有K次修补复用同一已验证参考。
   原文未明确报告参考获取预算；一次生成是本适配预先固定的界限，不冒充作者参数。
   若成功返回的参考未通过，保留实际答案/分数并跳过该任务修补，不为分数重新采样参考。
   基础设施重试仍只使用原传输策略，不能将参考错误当作基础设施失败。
4. 只有参考通过，强修补作者才收到原失败轨迹、经验证的参考和实际验证记录。
   最多K=3次修补生成及源案重放，失败时给回上次修补与真实重放结果。
   8B重放只收到原任务和repair_memory，不收到参考答案、说明、诊断或目标。
   contains_instance_solution仍只检查repair_memory；保留真实实例身份/答案泄漏检查。
5. 其后保持原SkillCommit机制：语义短名单R=4，活跃技能兼容阈值2/3，反向见证W=2；
   残余组必须含新到修补、最小规模m=2且有行为锚点，再经共享执行机制判断。
   抽象作者只见匿名修补/父技能与机制，不见原题、目标或来源身份。
6. 高层候选最多L=3版，各版真实重放全部声明来源。全支持才提交；部分支持可选择
   支持数最多的已生成版，范围至少2，再完整重放缩小范围后独立提交split。
   父技能及未覆盖修补按原规则保留。没有我们的方法准入、1pp容差或分量提交。
