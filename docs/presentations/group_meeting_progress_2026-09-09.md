# LegalSkillEvolve 组会进展汇报（5页PPT大纲）

> 日期：2026-09-09  
> 建议汇报时间：5—7分钟。以下数据均注明口径；不要把历史重放称为正式实验结果。

## 第1页：研究问题与核心方法

**标题建议：** LegalSkillEvolve：让冻结小模型从多轮法律咨询经验中持续积累技能

- 问题：冻结的Qwen3-8B在中文法律咨询中容易泛化追问、重复提问或过早结束，难以用较少问题获得足够关键事实。
- 方法：同一案件生成K=4条独立完整轨迹，用组内高低收益差异形成证据簇，再由技能教师归纳为结构化咨询技能文档。
- 技能不微调模型、不运行规则触发器，也不改写模型动作；它作为固定会话文档进入调查规划和每轮律师决策，由Qwen自主运用。
- 主指标：**每次律师提问获得的唯一新事实数**；同时报告事实总量、Fact Coverage、Resolution和安全指标，防止“少问但早停”的投机。

**建议图：** 一条横向流程图：`同案K=4轨迹 → 组内差异 → Luna技能文档 → 工作技能库 → 后续案件`。

**一句话讲法：** “我们的学习对象不是模型权重，而是冻结模型可反复使用、可审计的外部技能文档。”

## 第2页：数据与主实验设计

**标题建议：** 128案顺序训练 + 官方30案最终外测

| 项目 | 当前冻结设计 |
|---|---:|
| 自建训练案件 | 128案，14个法域 |
| 训练语料事实 | 852项 |
| expected inquiries | 699项 |
| memo expectations | 683项 |
| 顺序训练 | 8块 × 16案 |
| 基础训练轨迹 | 128 × K4 = 512条 |
| 训练人格 | 合作型P_WD，控制客户环境噪声 |
| 最终外测 | 官方DLawBench中文30案 × 4人格，冻结库后才运行 |

- 每块从同一个“块首技能库”运行16案K=4，块末可生成0—3个技能；下一块自然看到此前累计技能库。
- 每块固定8案增加匹配空库影子，形成整库prequential开发曲线；影子不参与教师学习或技能准入。
- 最终对照至少为相同冻结Qwen的`无技能库`与`LegalSkillEvolve`，从而隔离技能文档的增益。

**建议图：** 8个连续方框，每个写“16案/K4”，方框上方画逐步增长的技能库；最右侧单独画“CN30 × 4人格”。

**一句话讲法：** “128案全部用于顺序学习，公开30案完全留到最终冻结后测试。”

## 第3页：前期为什么长期出现“0技能”

**标题建议：** 真实瓶颈在技能生命周期，而不只是Qwen能力不足

- 历史运行曾有正常的K4差异，但旧选择器通常只把最强的一类证据交给教师，领域证据没有获得调用机会。
- 候选随后还要经过逐候选16/18案效果验收；少量随机样本的均值为0或不稳定，就会阻断技能入库。
- 一些“问得不好、重复、事实产率低”的**可学习差行为**曾被健康门当作协议错误，反而抹掉TF-GRPO所需的负轨迹。
- 单来源领域候选与多来源通用候选曾使用不一致的来源回合检查，专用技能更容易被误拒。

**实际诊断数据（非正式结果）：**

- 一个历史batch1有64条真实轨迹、15个可评分K4组；用当前算法重算得到20个轨迹对照、23个合格证据簇。
- 另一个曾“前三块0激活”的历史run，仅batch1的64条轨迹、16个可评分组就可重算出9个对照和9个合格簇。

**建议图：** 漏斗图：`真实优劣轨迹很多 → 旧选择只取很少 → 逐候选验收再拒绝 → 0正式技能`。

**一句话讲法：** “旧数据并非没有学习信号，主要是信号在选择和准入链上被过度压缩。”

## 第4页：本轮系统性改动及已有证据

**标题建议：** 从逐候选阻断改为“来源可信后直接积累、整库评估”

- 每块调度0—3个不同fingerprint证据簇；通用与领域证据同时存在时至少各覆盖1个，并优先未尝试机制和新法域。
- Luna一次只处理一个证据簇以保持来源清楚，但一块可进行最多3次独立合成，因此不是“每块只能一个技能”。
- 候选通过结构、来源、安全/泄漏、去重和提示容量硬门后直接进入工作库；不再为每个候选重复跑16/18案。
- 健康门只硬拒泄漏、协议损坏、非法状态、不可归因fallback和不完整K组；弱但合法的律师行为保留评分和学习。
- 下游只在整库层面看prequential曲线和最终外测；不把累计库变化虚构成某一技能的独立因果效果。

**真实历史重放结果（仅证明新选择器可用）：**

| 重放来源 | 当前算法首轮可选3簇 |
|---|---|
| 64轨迹/15个可评分组 | general事实目标选择 + administrative证据追问 + company_commercial证据目标选择 |
| 64轨迹/16个可评分组 | general事实选择 + finance_bankruptcy专用证据技能 + marriage_family专用问法技能 |

**建议图：** 两栏对比：左侧“旧：1候选→逐项验收→0技能”，右侧“新：最多3簇→硬信任门→直接入库→后续整库曲线”。

**一句话讲法：** “现在保留可审计硬边界，但不再让小样本逐候选验收扼杀技能产量。”

## 第5页：当前状态、尚未完成与下一步

**标题建议：** 框架已收口，下一里程碑是新协议端到端技能与曲线

**已经完成：**

- 128案批次、模型角色、信息隔离、结构化技能接口和直接积累事务链已同步到代码、配置和现役文档。
- 静态协议审计23/23通过；当前全量测试检查点为726项通过。
- Qwen3-8B与gpt-oss-20b已从新项目目录部署且正式preflight为`ready=true`；官方CN30没有进入调试、门槛或教师上下文。
- 客户模拟器资格覆盖51案、144个正反对照：事实披露准确率100%、状态转移准确率100%、合同fallback为0；匹配准确率95.14%。

**必须坦白的未完成项：**

- 新直接积累协议尚未产生可作为论文结果的正式技能数量和上升曲线；历史重放不能替代新端到端run。
- 当前没有法律专家标注资源，因此论文只能把语料称为“最高法来源约束的AI构建研究语料”，不能称专家金标。

**紧接着做：**

1. 使用已通过preflight的全新run ID启动正式训练；
2. 连续观察前3块的真实问答、证据簇、Luna候选、直接入库、下一块文档暴露及整库指标；
3. 若链路健康且技能库非空，继续8块并冻结；冻结前绝不运行官方CN30；
4. 再做无技能、固定技能、无组内对照/无教师等消融，形成论文主表与曲线。

**建议图：** 里程碑进度条：`数据✓ → 框架✓ → CPU/GPU资格✓ → 正式端到端（当前） → 消融 → CN30最终外测`。

**一句话讲法：** “今天能证明的是框架和根因修复已收口；接下来要用新run回答最关键的问题——技能是否真的累积并带来可复现提升。”
