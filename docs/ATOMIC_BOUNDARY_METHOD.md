## 一条主链路，无新管理器或推理中间层

1. 每个技能表示一个可复用条件/检查/关系/依据要求，而不是按主题罗列多个互相独立的判断。
   guidance为结构化对象：when、inspection、relation_if_established、evidence_requirement。
   relation使用原三分类名或null；null是只指导检查/完整依据的技能，不强迫每条技能给结论。
   非null仅在律师根据当前原文确认该条件确实成立时有意义，且必须相对于原命题的主体、动作、对象、
   量词、正负方向、触发及例外。不是宿主程序自动判类、标签先验或候选命中即给分。
   没有固定技能数量、主题、长度配额或每批增删要求。
2. 完整库仍一次进入system，所有规则都可见。每个公共命题输入同时含原命题全文、原公共短描述、
   该库已声明适用的技能ID及相同普通工具候选；通过公开ID确定性连接，不做语义路由或选择器调用。
   空匹配不意味着NM。律师仍在一次原生回答中自行给17原题的choice/spans/reason/used_skill_ids，
   可拒绝候选或引用任何原SPAN。完整原文不裁剪，最终答案不拼补或改类。
3. 每次教师只见**同一确切父库和同一普通工具状态**生成的经验：本批全部6案首遇，
   以及上一批全部6案的发布后重答（首批无上一批）。原文/原Gold/全部成功与失败及对应本地8B轨迹均提供。
   不是按错误筛案或按效果回放；每个新案均参与学习，上一批重答也在下一更新参与。
   原始远期历史全部归档，但不在后续教师请求中把不同父状态的全部旧轨迹再次混成当前失败。
   历史知识由完整父库承接，未提及父项逐字保留；旧案保持单独检测且不作准入。
   教师输入来源数6/12/12/12，观察数相同；4次更新总体仍覆盖全部24原TRAIN。
4. 同一差分编辑器执行CREATE/UPDATE/MERGE/DELETE/NOOP。每个修改引用实际提供的训练来源及具体边界。
   合并不能混同不同法律前提，删除不能只因本批未命中。没有额外语义裁判、回滚选库、效果门槛或fallback。
