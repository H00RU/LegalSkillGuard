# 主实验执行说明

## 现役流程

128案分8块×16案，每案K=4，训练人格为合作型`P_WD`，初始库为空。每个健康K组形成完整证据卡；两个Luna map包完整且不重叠覆盖本批卡，并同时绑定这些轨迹实际使用的精确父playbook，第三个reduce调用对同一份全局`fact_elicitation` playbook提出精确局部编辑：首次创建最多8个操作，已有版本每批最多2个操作。候选通过来源、泄漏、法律安全和容量硬门后直接成为下一版本。已有规则确被行为证据支持且本批只重复同一机制时应NOOP；若同类低效行为仍持续出现，纸面已有相似规则不等于可执行，允许用有来源的REPLACE把它改成更明确的条件—动作规则。第8块教师预算为0。

每案先由同一冻结Qwen仅凭公开opening生成一次共享、opening-only、非绑定的事实议程。同案K=4和所有比较臂精确复用同一议程；模型只返回opening逐字主题短语和一个闭集属性，Python验证后确定性生成目标，不接受自由目标文本。议程不读取playbook、人格、隐藏事实、评分或实验臂，不规定问题顺序、最低轮数、下一动作或终止条件；合法空议程也不封闭律师使用`new_visible_gap`提出新维度的能力。它是跨臂一致的可见状态初始化，不是技能条件计划器。

全局playbook以教师原生文档字段逐轮注入：`procedure`用于目标排序和低收益转移，`question_guidance`用于问题组织，`contraindications`与`failure_modes`用于明确禁忌和已观察失败。字段内容逐字保留；现役运行不再把它转换成旧触发卡，也不向冻结律师暴露“额外问题预算”或`exclude_when`开关。律师新建事实维度的可见状态标签保留其`expected_information`语义，运行ID由这一声明维度确定（历史缺失声明时才以问题表面兜底）。若问题与一个既有目标存在严格命题同一性，系统只统一连接ID而不改问题语义；多目标歧义会被退回同一律师澄清，程序不替它选题。

律师每轮都看到公开opening、此前完整的律师问题与客户回答、紧凑在线状态以及本臂playbook；状态账本保留已问目标、回应类型和信息增量，但不暴露客户隐藏事实编号。客户端调用前，只有结构、目标身份或隐私边界等不可执行错误会交给同一冻结律师作有界重采样，程序不替它编写问题或挑选下一目标。复读、重问`unavailable`、复合表面和向客户索要法律判断若仍是可执行问题，均真实调用客户并计入提问、重复、收益与教师证据；健康的自主`final`也不继承可选新维度的强制提问义务。

冻结客户路由器首次给出结构有效的空匹配时，会在既有有限修复预算内对同一有限认知集合最多复核一次；无论总预算尚余多少，第二个空结果都立即按`unavailable`落盘。首个有效空匹配在复核期间保持事务有效：只有另一份结构与文字充分性均合格的模型路由可以替代它，畸形输出或被文字门拒绝的候选不能将它反向变成协议失败。该步骤不得访问playbook、评分、实验臂或法院记录，程序也不得把空结果改写为某个事实编号。

每块顺序如下：

1. 固定块首playbook与运行合同；生成16案×K4训练轨迹。
2. 用本地冻结裁判离线评分并完成组归因健康检查。
3. 若上一块有新版本，对本块sample-0运行精确父版本影子，写配对增量；无变化写identity。
4. 把全部健康证据卡分成两个map包；提取真实成功/失败机制。
5. reduce跨包合并去重，输出局部编辑或显式NOOP；确定性代码应用编辑并验证累计provenance。
6. 发布新playbook版本、写学习检查点和维护报告；下一块从该版本开始。
7. B8另运行累计playbook相对empty的冻结诊断并冻结最终库，不再调用教师。

## 启动与恢复

先运行：

    .venv/bin/python scripts/audit_paper_protocol.py
    .venv/bin/python scripts/audit_training_batches.py
    .venv/bin/pytest -q

协议、提示、代码或配置哈希变化后必须换全新run ID并从空库开始。只有完全相同代码/config哈希下的原子工件可以resume；旧逐法域文档run、旧候选或旧检查点只能留作历史诊断。

Luna预检使用现役`playbook_mode_extraction`结构接口的隔离探针，不再测试旧单候选诊断schema。断点预算只承认本run的`playbook_map_01`、`playbook_map_02`和`playbook_reduce`：工件必须同时通过当前输入/父库绑定哈希、精确响应缓存和项目级硬账本预留项核验；reduce还必须能从Luna原始patch确定性重放出完全相同的系统proposal。历史`proposal_*.json`及`skill_teacher_batch`缓存即使存在也不抵扣剩余调用数。缺失阶段按真实剩余调用计费；已经存在却不可信的不可覆盖阶段会在预检和运行时一致失败关闭，不能以“预算仍足够”绕过。

## 监控重点

- 每块64条主轨迹矩阵是否完整，fallback组是否在教师前整组隔离；
- 两个map包是否覆盖全部健康group且无重叠；
- success mode是否只引用差异组，failure mode是否诚实标记tie局限；
- reduce操作是否引用真实mode、是否局部编辑而非重写、累计来源是否保留；
- 下一块相对父版本的F/Q、事实数、提问数、重复、安全和实际问答变化；
- opening-only议程是否只见公开开场并在同案K=4及所有比较臂间保持一致，律师逐轮输入是否保留此前完整问答；
- 复读、`unavailable`重问、复合或低效问题是否真实送达客户，并一致计入提问、重复、收益与教师证据；
- Qwen每轮是否确实看到相同版本的playbook，空库/父版本影子是否保持唯一干预差异。

低事实率、差轨迹、某块NOOP或开发点负增量是可分析结果，不自动停机。普通重复、低效提问和命中应急horizon同样是应照实记录并保留进入教师证据的策略失败，不是执行链故障。泄漏、臂输入不一致、客户错误披露、评分合同漂移、不可归因fallback进入教师、事务哈希错误或playbook未注入才属于结构故障，应安全停止、修复并换新run。

正式入口：

    .venv/bin/python scripts/run_main_experiment.py --run-id <fresh-run-id>

最终库冻结后才运行官方CN30四臂控制器。主实验训练run自身的current/parent/empty输出是机制诊断，不替代论文四臂主表。
