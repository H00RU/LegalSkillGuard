## 新增定位

1. **上下文的表示会影响执行。** 原生形式减少了额外声明，较解码文本修复24条
   错金额，但也把12条原正确金额改错。语义相同不等于弱模型执行相同。
2. **分类信息确实能帮助覆盖，但没有解决金额。** 原生条件漏列14→3，额外9→4，
   同时错金额18→28。相对父答仍有15条正确→错金额迁移。
3. **不是所有额外声明都来自照抄EC错误。** 解码条件22条额外项只有3条本已在EC
   预测中，原生条件4条有3条本已在EC中。因此不能将前者全部归因于上游分类错误。
4. **明确的事实绑定错误仍在。** 解码条件21条新错金额中，13条超过原事实资产价值，
   全部21条都能从公开事实唯一定位价值。例如18元袜子被填成600。原有技能已经
   要求金额不超过整项资产价值，说明仅补一条同义提醒没有解决执行可靠性。
5. **EC完全正确只是事后定位条件，不能当部署门控。** 原32中25源EC引用集合全对；
   原生上下文在这25源的F1为91.76%，父答85.52%。但这包含无效恢复，且7个EC
   不全对来源下降。不能利用TRAIN金标判断何时向EV提供EC，也不能声称已有可靠门控。

原生条件共9源提高、7源降低、16源原生F1不变。当前下降主要见235、237、238；
232、243改善。不存在只保留改善案例的输出策略。
