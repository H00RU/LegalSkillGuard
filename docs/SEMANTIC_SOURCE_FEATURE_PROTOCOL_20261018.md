# 同一冻结8B执行源语义条件：续接中断工作

2026-10-18。恢复单个Qwen3-8B后实施。不是双实例、换任务、换教师或自动重启旧负收益训练。

## 为什么做这个修改

昨晚的真实末次库是反馈更新后的3程序/37特征，不选较好父库。固定已暴露16来源上，
普通选证器TP171/FP32/FN116/F1=69.7959%，该库176/57/111/F1=67.6923%。
排序mAP也更差，不能只归咎于0.5阈值。代码审阅确认源函数只允许文本/容器/正则，
没有语义操作；实际37列仍主要是词汇及局部上下文匹配。它们的表达力限制是待检验
断点，不是已证明的唯一根因，更不意味着技能进化理论上不可能。

原同模型语义能力检查被服务退出打断。现同名官方模型已重新获取并固定revision/hash，
完整环境及单服务恢复；同一条1-token logprobs请求返回200，不据此断言旧崩溃原因。
普通输出返回READY.而非要求的READY，字面遵循失败原样保留、未重采样，不冒充效果成功。

## 原模块的具体改动

复用`learning/executable_features.py`的锚定选证器、原子CRUD、scope及原有实验入口，
不建立另一套规划器/判官。旧纯函数按原约束执行，不在子进程开放网络或模型。
新增显式表示`guidance.feature_names/source_predicates`，两数组一一对应。教师可将
原条件改为可迁移的语义谓词；保留/新建/更新/删除/合并/NOOP均可，不强制类型或数量。

同一已冻结8B对每份合同一次执行全部已发布语义条件。输入只有完整原文/原跨度及谓词，
无当前Gold、源ID、普通分数、当前答案或其他模型。每列输出对应原SPAN索引，转为
二元事实特征；不是最终证据集合，不直接返回E/C/NM，也不取代最终律师的判断。
所有非空谓词均执行，不按普通分数/案例难度选择；零命中不能推出NotMentioned。
已有纯函数与语义表示由发布内容显式决定，不在失败后互相替代。

复用原普通模型和同样合同外折基分数拟合的局部log-odds项，C10、阈值0.5不调。
无效果准入、较好库回滚、裁剪、去重修答案、失败返回零矩阵或自动重试。
所有语义生成都通过原生请求记录器计费/计数，非“零律师调用”的CPU实验。
过程绑定的调用器不进入pickle；重载后须显式绑定同模型调用器，缺失即停止。
