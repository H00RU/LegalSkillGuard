# 第二方法设计：学习作用域与用量接口，合成可复用技能的正确连接

独立审查日期：2026-11-05。角色：problem-design / adversarial reviewer。本文提出一项完整方法，不将“表示、学习、执行”拆成三项创新。未运行实验、未声称效果已验证，也未将有限检索等同于全球无人做过。

## 1. 可以锁定的研究问题与方法边界

**问题：原语分别正确，组合仍然会错，因为标量输入输出抹掉了“同一个谁、哪一组对象、是否已经聚合完整、某项额度已经用过多少”。** 此时增加技能、筛掉低信用技能或反复重写原语都可能修错对象。错误实际在技能间连接。

**方法：从来源规则与少量可验证区分反例中，学习带实体/集合索引、聚合闭合和用量效应的技能接口；保持已验证原语不变，在有限连接器语言中合成满足这些接口的绑定、连接、分组、归约和额度传递。** 可暂称“作用域与用量效应驱动的技能组合”，英文描述为 scope-and-usage-effect guided skill composition，先不追求缩写。

核心新增决策对象不是“是否用这项技能”，而是：同一组技能在当前规则下，**哪些变量必须共用同一见证、在哪个集合边界才能归约、哪项额度由哪些分支共享且只能消耗指定数量**。学习对象是这些连接限制及可迁移的连接模式，不是领域常数或测试答案。

建议允许确定性执行已验证的连接结果。继续强求所有算术由原生 LLM 执行，会把连接正确性与语言模型执行错误混合，并削弱方法的实际价值。冻结的是 LLM 权重和训练后技能/接口库；测试时允许绑定当前输入与运行既有代码，但不能利用标签修订库。若主论文坚持 native-only，本设计仍可输出有作用域的执行计划，但其可靠性保证只覆盖计划，不能覆盖模型执行。

**审查判断：这是一个值得定下实现的具体方法，能与“未编译条款覆盖”方法形成独立问题轴；当前可通过方法设计和有限查新审查，不能预支实验有效性或会议录用判断。** 它的可发表增量必须落在“从不充分来源证据识别接口 + 可复用连接器学习”上。单独引入线性类型、JSON 类型或正确 group-by，不足以成立。

## 2. 三个可以手算的区分性例子

### 2.1 同一实体见证，不能先各自变成布尔值

事实：`A(甲)`、`B(乙)`；规则：`A(x) ∧ B(x) → Eligible(x)`。

错误组合：`exists(A)=true`、`exists(B)=true`，再执行正确的布尔 AND 得到 true。三个原语独立都正确，但把变量 x 提前消掉了。

在**明确闭域的关系查询例子**中，正确连接先做 `join(A[x], B[x], on=x)`，结果为空，再执行 exists，得到 false。若将第二个事实改成 `B(甲)`，结果才为 true。这个仅改一个实体身份的对照可以区分“独立存在”与“同一见证”。在 ProofWriter 开放世界中，空 join 只表示这条规则不能推出 Eligible，不能因此把题目标签判为 False；若正反两边均无法推出，标签应为 Unknown。最终标签遵守该基准原生语义。

迁移对象：ProofWriter 中的共享变量；SARA 中同一纳税人/配偶/年度的条件；ContractNLI 中同一披露方、接收方、信息及例外的绑定。ContractNLI 的这种映射目前只是实现适用性推断，不能据此宣称已经有其完整形式 oracle。

### 2.2 按物品封顶和全组封顶，技能集合相同但作用边界不同

两件物品金额 300、300，额度 400。

- 每件物品分别封顶：`sum(map(min(v, 400), items)) = 600`。
- 所有物品合计封顶：`min(sum(items), 400) = 400`。

原语均是经过验证的 `min` 与 `sum`。`float→float` 类型和技能选择集合无法区分；简单顺序能表达部分差别，却不能说明 cap 究竟绑定哪个主体、哪个分组以及是否已经覆盖完整成员。

若训练例只有一件 300，两个连接都得 300，结论标签不足以识别接口。保持总金额不变，将其拆成两件 150，仍不区分；需要选择能让候选结果分歧的 300+300 或更合适的边界值。**所以不能把任意数据增强叫作识别：区分反例须由候选连接的预测分歧选择。**

### 2.3 共享一次性额度不能复制到各分支

同一家庭两项费用 80、80；规则规定家庭在本年度总共只能抵扣 100。正确的抵扣总额是 100，剩余应计金额 60。把每项费用都独立送入正确的 `deduct(v,100)` 会扣掉 160，得到 0。

正确连接把同一个 `Allowance[rule, family, year; balance=100]` 依次传递：第一项使用 80 后余额 20；第二项最多使用 20；或者先按家庭聚合为 160，再扣 100。若费用来自两个各有 100 额度的家庭，则合法扣除为 160。只改变 owner 分配而保持金额不变，就能区分共享余额与独立余额。

**Cap 与 Allowance 必须分开：** cap 是指定作用域上的变换，常有幂等性，不是消耗一次就不存在的资源；Allowance 才是有余额和唯一所有者键的状态。不可为了使用线性类型，把所有规则或事实都当成一次性资源。事实可重复引用；是否允许同一费用重复计入必须由源规则的用量约束决定。

## 3. 最小统一表示，不为五个数据集各写一套算法

### 3.1 值与接口

采用有限、可实现的 schema，而不是完整依赖类型语言：

```text
Relation[columns, variable_equalities, source_span_ids]
Amount[unit, entity_keys, group_key, lineage, stage]
stage ∈ {element, open_group, closed_group}
Allowance[rule_id, owner_key, period_key, balance, state_version,
          allocation_policy, priority, order_observable]
Effect = {read, introduce_witness, bind_same_witness,
          close_group, transform_at_scope, consume_amount}
```

- `columns/variable_equalities` 保留谁必须是同一实体；存在量词投影须在该变量所参与的必要连接完成之后。
- `group_key` 表示 person、household、item、estate、bag、year 等原文绑定的角色变量，字段名称本身不承载领域规则。
- `lineage` 是底层贡献 ID 与必要的变换记录。它帮助发现 join 导致的意外重复计入；不能一概禁止重复，因为规则可能明确允许同一事实支持多个结论。
- `closed_group` 只表示对当前结构化输入中、该规则指定集合的枚举已经完成，不等于现实世界没有其他事实；这是局部结构性质，不能包装成自然语言完整性保证。
- `Allowance` 的唯一键来自 `(rule_id, owner_key, period_key, category_if_required)`；共享同一键的分支必须传递同一个余额状态，不能各自初始化全额。
- 余额守恒并不决定合法分配。如果费用后续税率或优先级不同，把 100 分成 80/20 或 20/80 可能产生不同答案；须保留源规则的 allocation policy、priority、状态版本和次序是否可观察。未知分配策略保留为候选，不能按图短就选一种。§2.3 仅证明总扣额为 100，不证明任意逐项分配都符合所有可能规则。
- 数值上限、阈值、年度与主体名称均为当前输入槽，不能固化为训练域常量。

### 3.2 连接器语言

仅允许已有原语加以下结构连接器：`bind/rename`、`join_on`、`project_exists`、`group_by`、`map`、`fold/reduce`、`thread_allowance`。不允许为通过单个反例新写任意 Python。组件的代码和局部规格保持不变；候选间改变的是变量映射、作用集合与状态边的连接。

最小检查规则包括：

1. 原文规定共享的变量必须 join，不能通过两次独立 exists 替代。
2. 只有在目标聚合组闭合后，才能执行该组级 cap/threshold。
3. 归约须保留规则要求的分组键；投影该键是显式操作。
4. 同一个 allowance key 的累计 consumption 不超过初值；除非规则明确新建另一项额度，不能克隆资源状态。
5. join 产生的同一 contribution 重复计入必须有源规则的 multiplicity 许可。

这些都是类型、数据流和资源分析的既有思想；新方法不声称发明它们。

## 4. 具体学习算法

### 4.1 每个训练来源的输入和权限

输入为原始规则文本、事实、任务标签，以及该训练来源在官方生成器/可验证子集中可调用的参考判定器。对不存在可靠参考判定器的 ContractNLI，只有原始监督，不自动生成“已证实正确”的规则或事实变体。

LLM 一次提出带源文本定位的原语集合、变量角色与待确定接口槽。确定性模块只在有限连接器 grammar 中枚举候选。规则文本解析与连接合成应分别记录，避免把 parser 错误归到连接器。

### 4.2 版本空间与区分反例

**本方法优先学习接口，随后学习连接，不能退化为只挑选整段程序。** 初始接口先只携带粗粒度原语值；候选元数据来自来源文本可定位的角色关系，限定为实体相等关系、分组/所有者/年度键、贡献归属、用量与分配策略，禁止 task ID、答案或隐藏标签成为接口字段。

实体及 lineage ID 在来源内做 alpha-renaming，学习器只见规范化的相等/归属关系；跨来源库只存角色变量和约束，不存可反查 source 的唯一字符串、具体金额组合、标签分布或数值指纹。对实体一致重命名，接口决策必须等变、最终答案必须保持相应语义不变。lineage ID 只用于计算贡献是否相同，不可作为统计路由或检索特征。

对同一规则来源，优先寻找一对可验证的事实视图 `(z,z')`：原语投影到粗接口后的标量输出相同，但正确答案不同。例如保持两项费用都是80，只将“同一家庭”改为“两家庭”，共享额度结果不同。记粗接口投影为 `pi_K`，若 `pi_K(z)=pi_K(z')` 且 `y(z)!=y(z')`，则任何只以 `pi_K` 为输入的确定性连接器都无法同时正确处理二者。这是**接口丢失信息的直接证据**，区别于“某个完整候选程序算错了”。

令每个这种见证对应 `D_w`：来源允许的候选元数据中，哪些字段/关系能区分这一对视图。选择低复杂度的接口字段集 K，使每个已观察的信息丢失见证至少被一个字段区分，再重新检查连接候选。可用有限 weighted hitting-set 或直接枚举实现；字段集合小，不要求新优化算法。若多个最小字段集都可解释已有证据，保留其等价类并选择后续区分见证，不任意宣称已识别。跨来源合并的是参数化的角色/关系约束，不是实体名。这个“先证实粗接口不足，再补必要信息”的环节，是相对单纯程序消歧最应保留和验证的机制。

碰撞见证只证明某种信息必须存在，并不唯一决定正确字段或连接，更不证明自然语言抽取器已经恢复了它。若粗接口已足够但连接方式错误，继续下面的连接版本空间消歧；不人为要求所有失败都产生接口碰撞。

令 `H_i` 为来源 i 尚未排除的连接模式；每个候选共享同一组局部正确原语，只在接口/连接上不同。先通过静态约束和原始训练样例筛选。若剩余候选在原始样例上都正确，不能直接宣布它们等价。

在可验证来源内部构造有限的事实变换候选 `Z_i`，例如：同一实体/不同实体替换；保持金额的拆分/合并；保持金额和成员数的 owner 重新分配；增加同 owner 的第二项 eligible 费用。它们不增加独立来源数。

选择能最大区分连接候选且编辑最少的事实视图：

```text
z* = argmax_z [ number of candidate pairs with h(z) != h'(z)
               - lambda * source_edit_cost(z) ]
```

再由训练参考判定器得到 `y*`，保留满足 `h(z*)=y*` 的连接。最多 4 个额外视图，或候选只剩一个经限定语义检查证实的等价类即停止；4个视图同答只能称经验上未区分，不能称程序等价。若 `H_i` 为空，返回 `NO_VALID_CONNECTOR`，只允许一次预算内 schema 修复或固定回退；不选“最接近标签”的图，不改已验证原语挽救可行性。若预算用完仍不确定，保留多候选/降低复用资格，不能根据 LLM 自信分数虚构唯一真值。测试时不调用此参考判定器、不生成带隐藏 gold 的训练反馈。

与普通 CEGIS 的关系：沿用“候选—反例—收缩”的框架；本设计的研究对象是跨任务共享的**接口效应 schema**，以及面向主体/集合/用量混淆的区分见证，而不是提出新的通用 CEGIS。

可识别性必须成为实现契约：若允许的来源内变换对两个 schema 总产生相同结果，记它们为当前证据下的同一可观测类，不能把一个来源的偶然一致推广成已识别的唯一接口。最小反例选择只在这些类之间工作；每次选择必须记录分开了哪两个接口假设，以及回传哪条变量/作用范围/用量约束。若候选预测正确但 gold 反馈与所有候选不符，应归为 grammar/parser miss，不能无限新增连接器或任意重写组件。

### 4.3 跨来源归纳和冻结

将来源特定实体、规则 ID、阈值参数化，把通过证据验证的 `(scope slots, effect constraints, connector graph)` 存入库。只合并在角色重命名下接口约束一致的模式；同一 `min` 原语可服务于 per-item 和 per-group 两种模式，不能为了省技能条目而合并这两种语义。

共享反例也参数化，例如“同一变量不能来自不同实体”和“共享额度不能复制”。它们约束接口候选，而不是向 LLM 追加越来越长的失误故事。训练结束冻结：原语代码、接口模式、连接器 grammar、排序规则、预算及所有 source ID。

### 4.4 推理

1. 读当前自然语言规则与事实，抽取角色、关系与 scope slots；这些是模型产生的公开结构化输入，不是 gold IR。
2. 检索少量兼容模式并实例化；确定性检查上述变量、聚合、用量约束。
3. 只有合规候选已在限定语义中证明等价，或在当前完整允许 completion 集合上给出同一答案，才按预先固定的最小结构/调用成本选连接。若仍存在语义不同且影响答案的合法候选，送回 A 保留为未决接口/作用域，或走一次预先规定的解析修复/通用回退；不能用低成本、频率或自信分数把歧义变成确定语义。
4. 执行固定原语和连接，返回答案和源规则对应的检查记录。测试期间不写回技能库。

**保证的准确边界：** 在规则槽与事实绑定正确、组件局部规格正确且输入封闭枚举成立的条件下，可证明本接口系统阻止指定的跨实体连接、过早聚合和额度超额消费。不证明任意自然语言解析正确，也不证明该 grammar 覆盖所有规则任务。主准确率必须包含解析失败和回退，不能只报告类型通过的子集。

**与方法 A 的边界：** A 负责当前原文中哪些条款/作用域仍未解释以及其可能 completion；B 负责共享原语之间的连接接口与组合。B 在训练来源上通过反例，不构成当前测试原文的语义证据，不能据此替 A 删除 residual hole。A 若仍保留两种 scope completion，B 应对两种都构造兼容连接或报告歧义；不能挑较常见模式并将其冒充已编译事实。独立评测 B 时可固定完整可信的局部规则/事实，隔离连接问题；这项分析是条件能力检查，不能替代自然语言端到端主评测。

## 6. 必须承认的经典技术来源

- [Synquid / PLDI 2016 作者论文](https://cseweb.ucsd.edu/~npolikarpova/publications/pldi16.pdf)：用多态 refinement type 分解规格并驱动组合合成。因此“类型约束缩小程序搜索空间”完全不是本工作的首次贡献。这里需要研究的是规则文本与少量来源证据如何给出正确的作用范围/用量接口，不能假定用户已经写好完整类型规格。
- [Resource-Guided Program Synthesis, 2019](https://arxiv.org/abs/1904.07415)：refinement type 与资源潜能约束驱动合成，目标通常为程序时间/资源界。本方案的 allowance 是任务语义中的权益/额度，不是算力预算；这一区别不够单独成创新，只是说明所解决问题不同。
- [Resource-conscious AI planning, 2002](https://cyber.bibl.u-szeged.hu/index.php/actcybern/article/view/3599)：线性逻辑计划已经跟踪资源使用；[Nomos, CSF 2021](https://ieeexplore.ieee.org/document/9505237/) 用线性类型禁止资产非法复制。不可宣称首次避免额度/资产复制。
- [Example-Guided Synthesis of Relational Queries, PLDI 2021](https://www.cis.upenn.edu/~alur/PLDI21.pdf)：从关系输入输出例合成查询并利用数据结构引导搜索已经存在。不能声称首次 join/group-by 合成；要证实本方法从有限规则来源提炼的接口在新规则和新组合上带来迁移，而不只是在已知关系 schema 上恢复查询。
- [Morpheus, PLDI 2017 作者原文](https://www.cs.utexas.edu/~swarat/pubs/pldi17-morpheus.pdf)：固定高阶/一阶组件、不完整组件规格、类型引导 sketch、SMT 剪枝、例子和部分求值已经能合成表格变换。故“保持原语只学连接”本身不新。本文应测试的增量是：来源内实体/分组/额度的区分见证如何**识别接口约束**，并将其参数化后迁移到新规则，而非仅对单个 I/O 示例恢复一个程序。
- [Resourceful Program Synthesis from Graded Linear Types](https://kar.kent.ac.uk/84636/)：已用定量 graded types 约束资源，借助输入输出 context 管理在合成中传播资源使用约束。正式出处为 LOPSTR 2020 会议论文集、2021 年出版，非 ESOP；不可声称首次 usage-aware synthesis。这里类型/规格不由用户预先完整提供，学习正确的任务用量接口才是本方案研究对象。
- [Detecting summarizability in OLAP, DKE 2014](https://www.sciencedirect.com/science/article/pii/S0169023X13001274)：分组互斥、覆盖完整、度量/维度/聚合函数相容早已有形式化方法。不能将闭合聚合检查本身称为创新；当前难点是从文本规则和少量来源监督识别应该采用哪个 scope 与度量接口。
- [Socrates / Choose, Don't Label, 2604.08792](https://arxiv.org/html/2604.08792v1)：将候选程序按 Hoare 行为分群并合成有区分度的多选问题已经明确做主动消歧，文中就有按 user、user-date 或原记录分组的例子。故“找最有信息的输入/问法区分程序”不能独立算创新。本方案用受支持的训练参考判定器回答来源内最小干预，并将答案提升为可复用 scope/usage 接口约束；必须通过跨来源迁移和等预算普通程序消歧对照证明这个提升有价值，不能只改问答形式。
- Socrates §4 Algorithm 1 还在不足时调用 `RefinePredicates`，不能宣称首次主动谓词细化。区别须是组件接口上哪些语义字段/关系应被保留及跨来源复用，而非一般地把“程序消歧”重命名为“接口细化”。
- [Emergence Invariance, 2608.01548](https://arxiv.org/html/2608.01548v1)：§3 已论证固定接口碰撞与不可消除的风险下界；§5 人为构造 observation/memory twins，并通过恢复关键记忆或扩大可执行表示验证。已读方法/实验设计，未见自动最小语义字段合成或训练来源中的 scope/usage 接口学习。因而本方案不将“同接口不同答案必有错”当新定理，只把这个既有事实转化为接口学习的可验证定位信号。
- [Constraint-Consistent Skill Composition, IEEE 2026](https://ieeexplore.ieee.org/document/11484408/) 的公开摘要已有技能接口、pre/post、序列及状态约束。当前只核到摘要，作为范围近邻列出，不能假装已完成全文方法对照；本文也不能声称首次约束一致的技能组合。

经典工作本轮核实到作者/出版方原文页面与可取得论文，部分仅做针对机制的阅读，未全面重现所有定理。无需先开发完整新类型理论；可给一个覆盖限定 grammar 的小型 preservation/usage soundness 命题，但不能把这种技术引理计为独立创新。

## 7. 五基准实现覆盖与公平评测

| 基准 | 本方法的确切能力对象 | 不可越界 |
|---|---|---|
| OpenExempt | 资产、家庭/遗产等作用层级、分类后汇总、共享或独立额度 | 具体哪些 suite 支持可靠可重算视图需依实际 oracle 检查；不假定所有法规可随意改写 |
| RuleArena Airline | 同一行李的超尺寸/超重匹配、每件 `max` 与整组 `sum`、基准费用绑定 | 官方程序有明确 `max(oversize, overweight)` 后合计；这支持 grouping/join，但未核实存在可直接当 allowance 的原始机制，不得硬造 |
| SARA v2 Binary | 主体、配偶、年度及条件的共同变量，金额/阈值聚合的适用主体 | 本阶段核心固定 binary；不要为此另扩 numeric 训练指标或改变独立来源配额 |
| ProofWriter OWA depth5 | Horn 规则变量同一性、关系 join、量词投影，保留 true/false/unknown | 没有额度机制即可只启用关系接口，不能强行用资源消费解释普通逻辑事实 |
| ContractNLI | 披露方/接收方、对象及例外的主体关系，原始 NLI 迁移 | 无可靠完整参考形式化；保留原始测试，禁止自动产生带 oracle 宣称的变体；可单独人工审计少量角色绑定作为分析 |

不改原配额：训练 128 来源（OE32，其余各24）、dev 每库8、test 每库32；OE 双视图使主测试 160 来源对应192答案。训练的派生事实对照仍归属于其原始 source。所有源数据族、案例组与派生视图同分区。

**最小正式对照：** 共用相同冻结 LLM、公开输入、原语库、预算与可用工具，比较（1）空库/通用解析执行；（2）平坦文本技能；（3）SkillCompiler 风格 I/O+pre/post 及局部 binding repair；（4）完整本方法。若另一方法 A 也进入主方案，使用 A/B 的 2×2 因子比较，避免两个都提高准确率却无法归因。

还必须包含**手写的通用参数化连接编译器**：输入已经正确的 scope、共享变量与额度字段，执行相同 join/group/fold/thread。完美接口给定时，这个编译器本来就应正确，不把它当要击败的低级基线；它是接口正确性的参考上界。端到端公平比较则给它与本方法相同的 NL 槽抽取器和公开字段，区分收益来自接口识别还是执行工具。不得把“min/sum 算得更准”当成本方法独有贡献。

**最小必要消融：** 去掉作用域/用量约束但保留相同连接器搜索；保留约束但随机选同数量训练视图。两者分别验证“接口本身”与“区分证据学习”，不靠组件名称占一项消融。与 full-program from-scratch parser+solver 对照比较精度及成本，避免把通用工具增强当成全部增益。

为正面对照 Morpheus/Socrates 路线，还应将一个等预算普通连接程序消歧器作为有针对性的机制对照：候选、oracle调用数、来源相同，但它只保留当次通过的图，不进行“接口碰撞见证→字段/关系约束→跨来源参数化”。关键观测是新来源/新组合上的错误类型与同准确率成本，而不是训练例拟合率。此项可替换泛泛的平坦技能对照中的机制分析部分，避免额外扩大正式运行矩阵。

另一个不能回避的强对照是**保留全部允许语义元数据、使用同一连接合成器**，不做最小接口学习。它与本方法使用相同来源、抽取器和事实证据；比较正确率、调用/上下文成本、搜索候选数与同准确率开销。完美全元数据可用且成本低时，本方法不应被宣传为语义更强；最小接口学习的价值应体现为少来源条件下的稳定迁移或有限预算下的成本。若只是补回显然缺失的 owner 字段而全字段接口同样简单有效，则缩减方法贡献，不用人为压低该基线预算制造优势。

主指标为每基准 accuracy/exact-match、五基准宏平均、总调用/输出 token/耗时。机制指标是经独立标注/参考程序判定的 wrong witness、wrong aggregation scope、overconsumption 发生率；不能用“本类型检查通过率”充当正确率。可报告原语复用率与只改连接的修复比例，但这些是过程证据。

测试新组合需要预登记：相同技能包、不同共享变量/作用群组；新 scope 组合；同规则词汇但 owner 关系改变。选样按预先能验证的覆盖条件，不按某模型失败与否选。诊断以 source 为统计单位；派生视图不能当新增独立样本。ContractNLI 作为未形式化原始迁移覆盖组，在主宏平均中保留。

## 8. 预算、实现边界和决定条件

最小实现先只做上面 7 种连接器、有限非递归数值/关系图；ProofWriter 深度范围内可使用既有前向规则引擎迭代，不能开放任意程序合成。每来源最多32个初始连接候选、最多4个确定性 oracle 事实视图；一次 LLM schema 提议，最多一次接口修复。候选上限不通过临时提高预算绕过。

实现前无需付费模型的检查：三个手算例的错误连接能被区分、正确连接不被拒绝；相同规则改数值/改名无需新增模式；共享额度和独立额度有不同合法状态连接。这是规格检查，不是宣称实验效果。

小试固定五库各4来源（包含于128训练来源），仅用于暴露规格与实现错误。若三类接口错误中至少两类根本无法在真实来源中形成可验证实例，应缩小方法主张，而不是造更多任务凑成功；若所有收益可由普通 I/O 合约或同预算局部 binding repair 复现，不能再将本方法单列强创新。反之，若同原语、同来源预算下可稳定识别并修正普通合约未区分的连接，进入已锁定完整128来源训练与冻结测试，不继续无限发散。

目前仍待服务器核实：现有技能是否已含可调用原语或只有文本；各基准事实/规则解析器的可靠字段；OpenExempt 当前 suite 能否实现 source-preserving 对照；SARA 分组去泄漏后的实际可用训练来源；现有律师模型 reasoning 配置与调用耗时。它们影响实现成本，不推翻上述明确方法对象。

## 9. 可用于新方案的贡献句

我们提出一种作用域与用量效应驱动的技能组合方法：从规则来源及少量区分反例中学习实体绑定、聚合边界和共享额度约束，在保持局部正确原语不变的条件下合成可迁移的技能连接，减少由错误见证、过早归约和额度重复使用导致的组合错误。

这句目前是**研究目标和机制描述**；实验完成后才能把“减少”改写成带证据的结果主张。它不声称首次类型系统、首次技能合约、首次反例学习或从未有人研究技能组合。
