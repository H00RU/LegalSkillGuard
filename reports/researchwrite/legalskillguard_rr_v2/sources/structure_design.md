# 方法结构审查：对未编译条款负责的按需规则编译

审查日期：2026-11-05。范围：新一轮方法设计；不延续已撤回的结构修复 A/B，不运行模型或训练。下文将【事实】、【推断】、【设计】分开。文献以原文方法节和官方文档为依据；没有把摘要检索或没有读过的代码算作核查。

## 结论

**建议保留并落实为一个方法：在部分规则尚未形式化时，对它们允许产生的语义影响进行显式量化，只有答案对这些影响均不变才结束编译；否则由答案分歧反向确定下一批需要编译的原文条款。**

该方法针对一个具体失败：系统已经找到支持答案的形式证明，却漏译了能改变结论的例外、定义或优先级条款。它改变的是“什么算编译完成、什么对象参与验证、下一步编译什么”，不是再增加一次自我反思。它可以在部分条款仍未知时回答，但必须交代这些条款为何不能改变当前答案。

【审查判断】**方案级立项通过，固定为此机制，不因尚无实验效果再换题。**它具有明确问题、可核对的最近邻差异、可执行算法和实现价值；这不等于提前认证会议创新强度，更不等于“无人做过”。最接近的方法是 Logitext、SymBa、AWS Automated Reasoning，以及传统 CEGAR/lazy grounding。可发表的增量应落在“未译原文责任 + 允许完成集合的语义 + 分离完备批次编译”的整体，而不是分别把双世界、部分形式化、反例细化、来源链接算成四个创新。

本版已合并执行审查员的 `work/novelty-round2/execution_design.md`：用全局分离条件替换只看单对反例的贪心展开。该执行机制属于同一个方法，不另计为第二创新。

## 1. 需要解决的问题与边界

【事实】AWS 官方文档已经区分翻译与数学验证，并明确 VALID 只覆盖已翻译的 premises/claims；系统提供未翻译片段、原文覆盖分数、两种可能情景及翻译歧义情景。因此，“证明可能只对翻译后文本成立”是真实已有问题，“返回正反情景”不是新贡献。[AWS 官方概念文档](https://docs.aws.amazon.com/bedrock/latest/userguide/automated-reasoning-checks-concepts.html)

【设计】任务输入为原始规则文档 T、公开事实 F、查询 q。输出除答案外，必须区分：

- `stable`：在当前明确允许的所有规则完成方式下答案一致。
- `translation_unresolved`：未译规则的不同完成方式会改变答案。
- `fact_unknown`：规则已经足够确定，但事实缺失导致任务本身为 Unknown。
- `conflict`：已确定的规则/事实冲突，或仍允许会引发冲突的规则解释。
- `budget_exhausted`：到达预算，尚不能形成前述稳定性结论。

**对象层 Unknown 与翻译层 Unknown 必须分开。** 缺少“是否获批”的事实不能靠反复重译规则消除；同样，漏译“除非获批”的规则不能假装是正常的开放世界 Unknown。

实际接口将 `answer`（标签、数值范围或任务定义的 Unknown）与 `certificate_status`（completion_stable、translation_unresolved、unsupported_no_certificate、conflict、budget_exhausted）分字段保存。任务答案 Unknown 可以对所有允许规则完成均稳定，但这只意味着“规则翻译的不确定性不会改变该 Unknown”，不意味着事实层获得确定真/假。

本方法允许 solver 执行并生成结构化结果，LLM 再组织答案。此前的 native-only 是早期设计选择，并非用户硬要求。若仍要求最终回答由原生 LLM 独立产生，solver 证书只能评价辅助信息，不能自动转移为对 LLM 输出的保证；因此不建议继续保留该限制。

## 2. 固定接口与表示

【设计】采用四个对象，不要求先建立一个“完整且正确”的程序。

1. **SourceLedger**：确定性地覆盖原文字符区间；每个非空白片段均属于至少一个条款单元，保留编号、层级、交叉引用和原文哈希。没有识别出的残余文本也必须成为条款单元。它证明没有在记账层面丢弃原文，**不证明条款意义已正确解析**。
2. **CompiledRules**：当前已接纳的带来源 IR。v1 支持布尔、有限枚举、有限域量词、线性数值、显式例外/优先级；不把“通常”强行转成无条件经典蕴涵。优先级缺失时保留多解释或冲突。
3. **ResidualContracts**：每个未编译条款 j 对应允许的语义完成集合 E_j。合同包括作用对象/可写变量、必要适用条件、允许的效果范围、例外/优先级接口和依赖闭包。内部条件可继续未知。未知作用域为 TOP；未知交叉引用为 TOP；不能根据一次 LLM 判断直接宣告“与查询无关”。
4. **AnswerStability**：对所有允许完成方式进行检查，输出答案集合、两份答案不同的完成见证，或稳定证书。

这里的 TOP 是**约定 IR、域与语义下的全部可能关系**，不是全部自然语言的意义。v1 用有限域、无循环效果组合或有界 Horn 闭包降低求解负担。真正超出适配器语义边界的片段必须设为 `unsupported_no_certificate`，除非给出可信的域内过近似映射；不能把域外语义塞进域内 TOP 后领取 stable 证书。数值变量有明确界或线性约束，不无限枚举。

### 哪些证据允许收窄合同

必须记录来源等级，而不是将“语法可执行”当作语义验证。

- **结构可信**：由数据自带且允许使用的类型/分区信息，或预先审定的受限语言语法，支持必要 guard、作用域及写入边界；可用于正式收窄。
- **训练审计的编译模板**：在训练来源及独立开发集上验证覆盖义务、例外附着与变量权限。测试时只有满足模板显式前置条件和完整匹配检查才适用；超出匹配部分进入 residual，不能忽略。
- **仅 LLM 提议**：可用来选择下一步编译顺序，但未经核实的作用域仍保留 TOP。多个 LLM 一致不等于证明覆盖了正确解释。

若第二项学习方法生成连接器或组合技能，它们只产生待核绑定、编译计划或合同收窄候选；训练中通过不能使当前原文的 residual 自动变成 compiled。仍须满足当前来源的匹配、覆盖、权限及语义接纳契约。

这里存在真实限制：任意自由自然语言的语义包含关系不能靠 SMT 自动证明。规则最终被接纳为单一解释时，仍然需要如其他 autoformalizer 一样承担语义忠实性假设。论文必须同时报告：(a) 相对于显式合同的符号稳定性；(b) 合同是否包含参考语义的实证审计。不能把 (a) 写成任意自然语言全语义保证。若所有条款长期停留 TOP，该机制会保守退化；这不是隐藏的成功样本。

## 3. 可实现算法

令 K_t 为已编译规则，E_t 为全部 residual 合同。定义：

\[
\mathcal C_t=\{P: P\text{ 满足 }K_t\text{ 且每个未译条款的完成属于 }E_{t,j}\}.
\]

对完整程序 P，任务适配器给出 `Ans(P,F,q)`；它可以是标签、数值或任务定义的 Unknown。不能因为 P 不一致便用爆炸原理返回任意答案：不一致显式成为 `conflict` 状态。

\[
Y_t=\{\operatorname{Ans}(P,F,q): P\in\mathcal C_t\}.
\]

空的完成集合意味着合同/已编译规则彼此矛盾，不能宣布“对所有完成均成立”。只有非空且 Y_t 为单元素时才允许 `stable`。若这个唯一状态是 conflict，则报告 conflict，而不是正确答案。

**实现步骤：**

1. 对所有原文建账，初始化全部 residual 为 TOP。用廉价结构规则/冻结模板提取可信粗合同；首轮 LLM 至多一次，批量提出查询相关骨架和合同证据，不让它自行删除 residual。
2. 构造两份共享 F、K_t 的程序补全，residual 的选择可以不同；要求输出不同。SAT 给出答案分歧见证；UNSAT 在完成空间非空前提下给出稳定性证书。布尔/标签用有限枚举；数值用 min/max 或两份输出不等检查。
3. 选择一个**分离完备批次** S：只要两个允许补全在 S 中所有条款的完整语义观察相同，它们的答案必须相同。设条款观察为 o_j(P)，检查双副本公式 `C(P) ∧ C(P') ∧ Ans(P)≠Ans(P') ∧ ∧(j∈S)[o_j(P)=o_j(P')]`。UNSAT 证明 S 足以分离当前所有答案不同的补全；SAT 给出差异集合 D，任何充分批次必须至少选 D 中一项。累积 D，用隐式加权 hitting-set 求最小费用候选并重复检查。SAT/hitting-set 是复用的标准工具，不自称新算法。
4. 费用 C(S) 计算一次调用开销、原文和上下文闭包的真实 token；共享定义只收费一次。若已知差异集合的最小费用下界超过预算，则报告“约定一次批量、最坏情形充分方案的预算不足”；不能推广为所有自适应方案均不可能。若某答案分歧的 D 为空，说明条款编译不足以观测该分歧；先检查事实 Unknown，否则返回不可观测/表示不足，不反复追问。
5. LLM 在一次请求中编译选中批次及必要上下文，输出类型化 IR、原文片段对应关系、例外归属、读写变量和遗漏清单。校验器做类型/覆盖/引用闭包/合同一致性检查。`o_j` 要求该条款在约定有限语义足迹上完整确定；若 LLM 实际只返回部分解释，不能假装批次观察已经完成，未知部分继续保留 residual。
6. 若新信息与旧合同矛盾，不能通过静默删去旧解释维持“单调”。撤销该合同及依赖证书，回到上一个有效状态，重新生成可见的修订记录。只有在有效包含收窄 \(\mathcal C_{t+1}\subseteq\mathcal C_t\) 时，才调用单调性质。
7. 重算答案集合。v1 每题最多两次解析批次，规划单元最多 12 个 residual 组、32 次分离求解、总符号规划 5 秒。组数上限不能通过删除可能相关条款来满足；超出则合并保守组、全量解析或返回预算不足。超时不能伪装为 UNSAT，也不标最优。预算耗尽按任务接口返回 unresolved 或调用固定 LLM fallback；fallback 仍计入总准确率和成本，且不带稳定证书。

**现成工具与真正增量：**双拷贝 SMT、反例最小化、缓存、有限枚举均为现成工具。增量在于这些工具处理的对象是**原文未译条款的允许语义**，以及源文档责任如何决定“可以停止”的条件。若实现仅把已有程序中的一个布尔条件设为 unknown，再用 SMT 求值，贡献会退化成普通抽象求值，不能支撑本方案。

### 在128个训练来源上究竟学习什么

不训练事实答案，不把当前法律条款存成通用真理。外部库保存可复用的编译操作：例如“显式除外条款必须同时建立一般分支的排除 guard 与例外分支”、变量权限及跨引用检查、粗合同生成模板。训练错误反馈针对遗漏、过窄合同、错误例外附着；冻结后不再通过测试标签更新模板。

本方法本身是推理与编译算法，不必伪装成新的参数训练算法。128 个来源用于开发/学习编译库，5×32 冻结测试评估迁移；不能再将其中的标准模板提取单列为第二个创新。数据适配器若使用参考程序，只能在训练与诊断审计中使用，测试推理不能读取参考程序或隐藏标签。

## 4. 可手算例子：什么时候必须继续，什么时候确实能停

输入文档包含：

- R1：员工费用通常报销 `min(cost,100)`。
- R2：国际出差不报销，除非获得审批。
- R3：礼品扣除额按照另一个复杂条件计算；这个条款的已核作用域只写 `gift_deduction`，不修改报销规则或其输入。

固定事实为 employee=true、cost=80。R1 已编译，R2 只确定“其报销例外的必要条件为 international=true”，尚未解析内部审批条件；R3 内部未编译。

| 情形 | 合同允许的答案 | 正确行为 |
|---|---|---|
| international=false；R2 必要 guard 和 R3 写入边界已经核实 | {80} | 可以在 R2 内部条件和 R3 内部逻辑均未知时停止 |
| international=true；审批例外尚未解析 | {0,80} | 不能因 R1 有一个 80 的证明就结束；分歧核包含 R2 |
| 定向编译 R2 后，公开事实 approved=false | {0} | 返回 0；R3 仍可不编译 |
| 定向编译 R2 后，公开事实 approved=true | {80} | 返回 80；保留例外分支证据 |
| R2 已译，但 approved 在开放世界中未知 | 任务语义为 Unknown，数值可行集为 {0,80} | 报告 fact_unknown；不要反复补译 |
| R2 的 international guard 只是 LLM 猜测，尚未核实 | TOP，可能改变答案 | 第一行也不得提前停止，需先核实外层作用域 |

此例中的 R1 是带显式 override 接口的默认计算，不是同时断言 `payment=80` 和 `payment=0` 的经典理论。R2 的优先关系来自原文“通常/不报销/除非”解释并纳入合同；若该解释未确认，优先关系同样属于 residual。

**非空可停场景不只“所有条款已译”：**已确认外层 guard 为假、已确认写入字段与查询依赖闭包不相交、或多个未确定内部计算在当前输入上输出相同，都允许停止。这要求至少获得可信的粗合同，不能以词面主题相似度代替。

### 联合批次为何是必要机制，而不是普通单步不确定性排序

令两个未译条款的语义选择为 p、r，目标 `p XOR r`，允许补全 00、01、10、11。仅解释 p 或仅解释 r 均不能决定答案；一对见证可能只暴露其中一个。若一次调用固定费用 10、每条费用 1，逐条两轮成本为 22；联合解释两条为 12。分离算法先获得差异集 {p}，选 p 后仍发现 {r}，最终 S={p,r} 的双副本检查 UNSAT，因此在询问任何一个条款之前就可生成一个充分批次。

这不是首次发现联合依赖，ECED、批量测试与形式解释早已有相关工具；本设计将全局分离条件绑定到未译规则的语义观察和共享原文上下文费用。对 OR，读到 p=true 后自适应策略可提前停，而最坏情形一次批次仍可能需要两条；因此不能宣称本方案具有所有策略下的最小期望成本。

| [AWS Automated Reasoning](https://docs.aws.amazon.com/bedrock/latest/userguide/automated-reasoning-checks-concepts.html)，已读官方 concepts 全部相关段落 | fidelity/来源链接、未译提醒、VALID/SATISFIABLE/翻译歧义，正反情景已有 | 对未编译**源规则**施加 completion 或 source-closure 条件，使其实际参与可返回答案的判断；不能只把未译片段打印为警告。官方文档不够支持“内部绝未实现类似技术”的排他断言 |

### 普通 CEGAR、抽象解释、lazy SMT、partial grounding 是否已经覆盖核心

【事实】[CEGAR 原文](https://www.cs.cmu.edu/~emc/papers/Conference%20Papers/Counterexample-guided%20Abstraction%20Refinement.pdf)已经用上近似证明性质，用反例细化抽象；[带外部源的 lazy grounding](https://www.ijcai.org/proceedings/2017/0141.pdf)已经处理非单调依赖和逐步暴露程序信息。已读前者方法概述与后者 §2–3 定义；没有完整复核其全部证明。

【判断】本设计的逻辑骨架正是抽象解释/CEGAR 思想，不能把 soundness 单调命题当新理论。lazy grounding 通常已知源程序语义；本设计连未译自然语言的规则作用都不确定，不能直接调用精确 concrete checker 来判反例虚假。必须因此建立显式的原文责任、作用域上包络和接纳合同：这是需要解决的额外困难，不是只换应用名。

如果实现最终依赖人工提供所有正确规则 guard、effect 和 priority，而只让 LLM 填不影响结论的细节，那么它已经获得最关键语义，应用增量会很弱。**是否能从实际五基准可靠获得“比全译便宜、比 TOP 精确”的粗合同，是本方法唯一最关键的工程与科学检查点。**

## 6. 强对照、验证与有限停止条件

最重要的不是堆新指标，而是隔离同预算下“保留未译责任”的价值。

1. 全量形式化 + 同一 IR/solver；这是准确率与语义忠实性的主要对照。
2. SymBa 风格按支持目标补译 + 同一编译器；验证支持证明提前结束的风险。
3. **Logitext/普通 CEGAR 强适配基线**：同样 source ledger 和粗合同，使用通用变量影响/固定顺序细化及双世界检查。与完整方法比较分歧核策略的实际增量；不能故意不给基线必要覆盖信息。
4. 同一实现去掉 residual（未译当作不存在），以及 TOP 保留但固定顺序补译。两项消融分别隔离责任语义和预算分配。

执行机制另比较单对反例最小差异核逐轮解析、固定大小/按 token 贪心批次、分离完备联合批次。保持同一解析器、原文和合同，区分“减少物理往返”的价值与“只是一次给了更多 token”。有限精确子集可枚举全部条款集合核验充分性和费用最优性；不要求另做大规模训练。

主要指标：全体样本任务准确率、回答覆盖率、被声明 stable 但错误的比例、每题成本/耗时、已编译原文比例。辅助审计：参考语义是否落在合同内、未译相关例外比例、Unknown 原因。拒答不能从分母消失；fallback 成本与错误必须计入总体。

诊断集从已有来源生成受控遗漏/例外附着/跨引用扰动，不把同源扰动当作新的独立数据集或独立训练样本。带参考形式程序的基准用于严查 envelope containment；自由 NL 基准用盲审样本，不能声称形式上知道全部正确语义。

**后续验证契约（当前用户要求不跑实验，此处仅定稿协议）：**从训练/开发来源预先选择 10–15 个跨模式案例，必须同时包含相关未译例外、无关残余、事实 Unknown、不可可靠确定作用域、规则冲突，以及 XOR/OR 批次边界。首先核验数据结构与可枚举的分离性质；实际模型运行须由后续执行阶段的明确授权与锁定预算决定。

若“粗合同比全译便宜”未成立，或 TOP 使绝大部分案例只能全译，允许将方法明确定位为覆盖验证而非效率方法；不得再宣传提前停止优势。若与上述强适配基线行为几乎相同，则将分歧核选择降为实现细节；整体是否仍有贡献取决于原文责任语义与遗漏诊断证据，不能靠再命名补足。

## 7. 可主张与不可主张

可主张的理论性质仅是条件性的：假设参考语义属于非空完成集合，若该集合中所有完成给出同一非冲突答案，该答案对参考语义成立；若合同可靠收窄，稳定答案保持。证明直接来自集合包含，不应包装成主要理论突破。

当前可写入方案的创新表述：

> 针对部分形式化中的未译例外导致虚假确定结论的问题，提出以原文条款为责任单元的部分规则编译方法：将未译片段保留为受约束的语义完成集合，通过答案分歧定位需要继续编译的条款，并仅在当前答案对允许完成均不变时终止。

禁止写：首次神经符号推理、首次按需翻译、首次部分形式化、首次双世界验证、首次处理例外、完全消除自然语言语义错误、无需翻译就保证原文正确、所有模型一致即语义已证明、已确定没有相关工作实现过。

## 8. Foundation review（用于起草执行协议，非效果/新颖性认证）

主观 0–5 分：问题 4.5；张力 4；证据 4；逻辑 3.5；可行性 3；创新界定 3.5；风险透明度 4.5；表达 4。

**本方法通过研究方案级立项，可以据此起草并锁定执行协议。** 五基准适配合同必须逐一写清哪些 scope/guard 来自可信结构、哪些来自训练审计模板、哪些只能保留 TOP，这是实现规范，不是要求先跑出好效果才允许立项。实际收益与合同质量留待授权后的有限实验验证。第二个方法应另从技能组合/学习对象寻求独立增量，不能将本算法的标准量化验证与分歧选择硬拆成两个创新。
