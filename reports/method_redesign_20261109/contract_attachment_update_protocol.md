# Source-attachment update diagnostic

Authority and acceptance remain in the two current documents. This protocol is
an immutable experiment record, not another execution-instruction document.

The concrete bottleneck is updating a reusable source parser after a correct
native TRAIN fit conceals wrong attachment of normative heads and conditions.
The initial state is the actual independently learned ordinary program from the
previous diagnostic, not manually authored rules. Both arms receive its complete
code, the same four original TRAIN contracts/eight approved native annotations,
and the same two source corrections on original TRAIN15/20. The new learning
object is a set of source-anchored attachment productions with captured head,
conduct, conditions and references. A deterministic learner chooses a minimum
consistent subset by (production count, serialized bytes, IDs). It has no
semantic oracle beyond the supplied TRAIN constraints. The ordinary control
independently learns unrestricted repair code and may adopt the same grammar.

Both use the identical semantic-preserving source rewriter, bounded runtime,
common SG-DT decomposition hints and checks. The host supplies no linguistic
patterns. Corrected legal consequences remain explicit residuals rather than
permissions, prohibitions or default native absence. Source-anchor validity is
an execution check, not a semantic-fidelity certificate. The preserved original
graphs and full rewrite trace must accompany any claimed repair.

This comparison isolates UPDATE from the same initial acquired program. It is
not independent end-to-end acquisition and cannot support that claim. Count
the original acquisition in both end-to-end accounts if later making a cost
claim; count all present update generation and selection/replay cost. The prior
different acquisition diagnoses remain in the research-line cost. No new native
labels, synthetic legal cases, extra hypothesis pairs, sources or seeds.

Original TRAIN109/110/112/113 are fixed by ordinal before generation/inspection
for source-only reuse. They were not part of this mechanism's repair. Freeze
both learned outputs and scoring before execution. Review the claimed source
heads/support chains in full, preserve misses and ambiguity, and do not score
new native questions. No further patching from this reuse result in this pilot.
Four approved DEV pairs remain sealed; do not spend a DEV comparison merely to
rescue a failed or fully absorbed source-update candidate.

This is one finite bank-and-repair comparison, not a parameter sweep or a new
mechanical resource cap. If the strong independently learned repair absorbs
the useful effect, stop expanding this update candidate and report the concrete
research-design gap. A local complementary effect should be retained even if
aggregate numbers tie. No zero-fallback, whole-parser-proof, score-gain or
significance criterion is added. No main training, TEST or paper is authorized.

Closest precedents to distinguish: RuleChef (failure-driven rule/Python patch
and held-out admission), SG-DT (core normative predicate versus conditions,
no invented effect from exception references), syntax-guided/inductive program
repair (finite constrained update selection), and Wang et al. 2019 (abstract
programs and structured alignments under denotation supervision). A finite
selector or legal name alone is not novelty; only an observed legal acquisition
or update advantage under these strong conditions could justify continuation.
