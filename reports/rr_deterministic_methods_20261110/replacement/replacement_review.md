## 判断

**可以实现、值得作为强验证工具；目前不足以作为已经查新过关的第二项独立创新。** 本轮不是只给一个名称：已经写出精确的受限算法、重建证明、43 对有限检查和一个最小反例需 333,334 个记录的压缩求解。未通过的原因也很具体：核心“无界记录求和→符号重数→整数算术”的机制被 LIA* 及 SQLSolver 直接覆盖。可继续论证的新增量仅是法律算术单元的专用消元、最小反例生成效率及可复用语义监督；这些新增量尚未超过同信息的强组合实现。

## 1. 窄问题有真实法律来源

普通案例的最终输出可能完全掩盖缺少某个聚合上限。考虑每件项目先截断 C，再加总，最后受年度总上限 G 约束：

`P(x_1,...,x_n) = min(G, sum_i min(C,x_i))`。

漏掉年度上限的错误程序为 `Q=sum_i min(C,x_i)`。当 `n≤floor(G/C)` 时，任何金额输入都不能区分两者；最小反例记录数是 `floor(G/C)+1`。不能用两笔更大金额压缩这个反例，因为每笔已经被 C 截断。这个下界依赖真实的内层上限；没有内层上限或合法金额限制时，不能声称需要很多小额记录。

实际的 [26 USC 25C(b)](https://uscode.house.gov/us/usc/119-124/t26/s25C/) 同时含每扇外门 250、外门类别合计 500、一般年度总额 1,200，以及另列的设备类别上限。[IRS 的官方计算例](https://www.irs.gov/credits-deductions/frequently-asked-questions-about-energy-efficient-home-improvements-and-residential-clean-energy-property-credits-energy-efficient-home-improvement-credit-examples)逐步应用项目上限、类别上限和总上限。这里引用的是有时间范围的研究法源：应固定 2023—2025 安装年度及对应法律版本，不能把其优惠说成适用于所有当前年度。

这条真实法源证明嵌套上限有意义，不证明法律通常需要几十万记录才暴露错误。大数例只是算法尺度检查。比如外门类别上限遗漏，在三扇合格门时就能暴露。已有 [VeriEQL](https://www.cs.sfu.ca/~yuepeng/pubs/oopsla24.pdf) 的讨论部分也已经用 COUNT 阈值展示小范围反例搜索的局限，因此“小案例不足”本身不能作为新发现。

## 2. 完整受限算法

输入不是一份有未知语义的自然语言就自动得到真值。输入包括两个待辨别的候选程序 P、Q，已由法源固定的分组定义及合法数值域。每个独立组有一个整数标量 x；P、Q 的局部计算是有限分段仿射函数，外层为求和之后的线性运算及 min/max。第一版不支持任意跨组相关约束、多维不可分解输入域或任意嵌套重分组。

1. 联合细分 P、Q 的断点，得到整数区间单元 `I_j=[l_j,u_j]`。在每个单元内，两者分别为 `a_j x+b_j`、`c_j x+d_j`。不是假设二者语义一致。
2. 每个单元只引入两个整数变量：记录数 `n_j≥0` 和这些记录的金额和 `S_j`。
3. 加约束 `n_j*l_j≤S_j≤n_j*u_j`。这精确描述在区间内取 n_j 个整数的所有可能总和；n_j=0 强制 S_j=0。
4. 聚合值变成 `U_P=sum_j(a_j*S_j+b_j*n_j)` 和 `U_Q=sum_j(c_j*S_j+d_j*n_j)`。
5. 对外层 min/max 的分支加入线性约束，在两个方向分别求 `P-Q≥1` 或 `Q-P≥1`，目标最小化 `sum_j n_j`。数值输出是整数；有理数输出先统一精确分母。
6. 从 (n_j,S_j) 重建实际记录。取 n_j 个 l_j，再把 `S_j-n_j*l_j` 逐个填充到区间宽度；每单元最多三个“值×重数”片段就能表示重建结果。调用普通 oracle 前可以展开，不能假设 oracle 免费支持压缩输入。

**精确性证明。** 任意真实多重集按单元分组，立即满足上述约束并保持两个输出。反向，任意满足约束的整数解，设剩余 `R=S-n*l`，用 `R=k(u-l)+r` 构造 k 个 u、至多一个 l+r、其余 l，因 `0≤R≤n(u-l)` 总能构造 n 个区间内整数。因此压缩与真实记录在此受限域完全对应。最小计数目标也保持。

不是把任意多维凸集简单替换为平均点：多维整数多面体一般不具有这种整数分解性。固定分母的 floor/ceil 可通过余数单元扩展，但本轮代码没有实现该扩展，不能计为完成。

## 4. 强近邻及确切边界

| 工作 | 已有核心机制 | 本构造不能声称的新意 |
|---|---|---|
| [Piskac & Kuncak, Linear Arithmetic with Stars, 2008](https://www.cs.yale.edu/homes/piskac/papers/2008PiskacKuncakLinearArithmeticwithStars.pdf)，式(1)、§3、§4 | 未知有限数量的整数向量求和；星闭包；归约到整数线性算术；扩展到嵌套星 | 符号重数、无界多重集求和、可判定性和一般复杂度都不是新增 |
| [SQLSolver, Proving Query Equivalence Using Linear Integer Arithmetic](https://www.cs.yale.edu/homes/piskac/papers/2024SIGMOD.pdf)，摘要、§1和§4 | 将 SQL 无界求和转 LIA*；明确扩展到嵌套、带参数及非线性求和 | 不能因为某完备性定理只列一部分聚合就宣称它不支持一般 SUM；它是必比强工具 |
| [VeriEQL, OOPSLA 2024](https://www.cs.sfu.ca/~yuepeng/pubs/oopsla24.pdf) | 带完整性约束的复杂 SQL 有界等价/反例；明确讨论大数量反例局限 | 只赢固定记录数展开不够。可比较，但不能当最强对照 |
| [SPES](https://arxiv.org/abs/2004.00481) | 基于符号表示的 SQL 等价证明，包括聚合 | 不能把“普通 SQL 只能展开”作为前提 |
| [BABBLE, POPL 2023](https://ztatlock.net/pubs/2023-popl-babble/) | 在等式理论下进行 e-graph 抽象与程序库学习 | 把压缩/等价程序送入库也不自动产生新 M2 |

本构造只可能在一个更窄算法主张上成立：**从法源固定的标量分段算术直接生成每单元两个变量的准确消元，并同时生成最小现实场景，不走通用星闭包和通用查询等价转换。** 其公式大小由单元数决定，记录数只在整数变量取值中出现。这一特化有可能省计算，但目前没有证明相对现有专门化 LIA* 编码仍有优势；如果普通手工加权 SQL/Presburger 基线用同样的单元归约，就必须算作相同方法。

## 5. 与 M1 的关系及输入监督

M1 的目标是用干预恢复法源的 scope/order；本构造的目标是为已经产生的候选发现超出固定记录数的语义差异，并给出最小场景。若最终只是把它用作 M1 的一个选探针子程序，它应算 M1 的实现组件，不能拆成第二创新。

训练可以让独立参考实现回答重建场景的最终金额，再据此排除候选；所有强基线享有相同 oracle 接口和调用预算。测试新法源若禁止 oracle，候选间差异只证明存在歧义，并不能自动说明哪一个正确。教师核实源语义或独立法源标签必须明确登记为额外监督，不能拿候选自身执行当真值。

显式金额、税率、门槛都直接向所有方法提供原文。没有理由为制造任务难度把可读出的常量遮住；本问题来自组合/聚合语义，来自多记录产生的掩盖，而不是常量提取困难。

## 6. 若保留，唯一合理的有限验收

在新主训练前只做一次确定性比较，不跑模型：

1. 固定源支持的三个聚合结构族和完整语法；原生法条与参数尺度变换分开报告。
2. 同程序对、同合法域下比较专用单元编码、直接 LIA*、SQLSolver 可支持翻译、加权 Presburger 手工强基线、VeriEQL/逐记录展开。
3. 检查相同的 SAT/UNSAT 与实际最小反例；只对有正确性核验的输出计成功。
4. 比较转换后的整数变量/约束数量、求解时间与内存；不能仅报告发现了大数反例。
5. 如果手工强基线和专用编码完全相同，或强工具在相同预算下同样完成，则把本构造归入验证后端，不继续换名称、追加模型训练或宣称第二创新。

当前还没有达到步骤2，更没有新方法优于强对照的证据。**本轮交付了一项完整可构造的替代及其可运行内核，但没有把它当成第二项已成立的创新交付。**
