日期：2026-11-10。

**实现成立；相同信息下的额外学习能力没有得到证明，查询效率反而落后强对照。** 本轮完成了真实直接恢复器、同探测约束枚举、主动最大分歧和小类上的最优自适应决策树。不是只检查手写候选是否能被区分，也没有先枚举完整程序再称“直接恢复”。

## 复现和工件

在当前目录运行：

```text
python run_validation.py
python write_report.py
```

只依赖 Python 标准库，使用精确有理数与固定整数金额格点。无需网络、API、GPU、模型训练或新标注。运行会重写本目录的结果与学习查询账本。

- `direct_recovery.py`：直接恢复器。输入只有公开模式和 query-only oracle，不导入候选模型列表，也不读取隐藏 scope/order/outer。
- `run_validation.py`：合成 DSL、共用合法查询池、两种枚举强对照、最优树动态规划、独立评分和逐次账本。
- `summary.json`：全部汇总、精确分项计算账本、源码 SHA256。
- `*_results.json`：逐隐藏实例的结构、正确性、查询数与耗时。
- `*_ledger.json`：每种方法每次学习查询的输入、输出、用途和隔离说明；重复查询也计数。
- `domain_boundary_regressions.json`：输入域限制的安全拒绝检查，不把 unsupported 计作恢复成功。
- `RESULTS.md`：由最终 JSON 整理的数值表。

这里的 oracle 是明确构造的 DSL 函数。没有将其当成独立法律标注；没有读旧项目测试集；没有对新法源调用 gold 后宣称零样本迁移。§63/§3306 的受限源锚定核验由上级目录 `source_fixture_audit.py` 独立保存，不在这里重复实现或冒充原生 gold。

## 算法、模型类和信息权限

固定记录集合的每条记录有 d 个可公开改变的分组键、总额 T、排除额 E，满足 `0≤E≤T`。允许的范围是任意键子集的 GROUP BY，或逐记录。组内有一个已知数值 C 的限额；排除可在限额前或后；全局可有一个数值已知为 B、但存在性未知的总限额。输出只有最终标量。

所有方法都知道同样的 DSL、键、C、B、可行域和合法查询池；谁都不知道隐藏的键子集、次序、总限额是否存在。未知 C/B 的搜索、法律角色抽取和自然语言编译未在本轮实现。不能把本轮成绩写成“从任意法条学会全部数值规则”。

直接算法不枚举键子集或全程序：

1. 一个单记录输入先确定排除与封顶的次序，避免先猜 scope。令 `q=min(C,B)/2,E=C-q,T=C+E`，先排除的输出为 C 或 B；后排除的输出为 q，两个响应集合分离。
2. 比较相同键、不同记录 ID 的两条记录，识别逐记录限额；否则利用每次只改变一个键的输入直接恢复键成员。若键相关、无法独立改变，则恢复当前域中的等价分区，不编造唯一键表达式。
3. 若先排除且 `B>C`，取 `C<2a<B`、E=0，分享限额得 C、分开得 2a；未知的排除次序被 E=0 消去，未知外层限额均不激活。
4. 若后排除，即使 `B<C`，仍可令两条记录各为 `(C,C-q)`、`q=min(C,B)/4`。分享组输出 0、不同组输出 2q，且 `2q≤B/2`，使未知外层限额确实不激活。这是实现时补齐的遮蔽处理，原设计不能仅凭一般“隔离”措辞假定它成立。
5. 用已确认的不同组跨过 B，识别外层限额。若记录数和 C 决定总额永远到不了 B，则保留其存在性未知。

先排除且存在 `B≤C` 的外层限额时，所有分区都等价于 `min(B,Σ(T-E))`；B=C 时还包含全局内层限额而无外层限额的等价结构。程序返回行为代表和不确定说明，不声称恢复了隐藏 AST。

每个 scope 探测的隔离性还由宿主独立审计：对先前响应仍允许的每个候选，检查去掉外层限额是否改变该探测。B=C 的例外明确采用等价合并，不混称已隔离。该审计不参与学习器决策，也单独计入计算账本。

## 同信息强对照

**同探测关系约束**使用完全相同的实际探测序列、响应、DSL，枚举满足全部约束的候选；不使用额外 gold。它不是完整 SketchAX 的复现，而是检验“这些关系监督本身是否已经足够”的强、可精确求解对照。全部候选的评分结果都计入，不能只挑一个碰巧对的候选。

**主动最大分歧**在同一合法池上，对当前行为类计算最大 Gini 分裂，选择一次能排除最多候选对的输入。先把同一池上等价的语法程序合并，避免等价重复项影响查询选择。候选输出表由公开 DSL 本地计算，不调用隐藏 oracle；它的成本完整记录。

**最优树**对不超过 12 个行为类的任务，用 subset-mask 动态规划计算固定查询池上的精确最小最坏查询深度。期望查询用于递归的局部平局选择，报告该树的实际期望值；不把它称为所有 minimax 树中全局最优期望。大键数不计算指数级最优树，仍保留主动最大分歧。

原始任务的池包含全部 1296 个原有限输入以及公开代数探测，共 1871 个输入；扩展任务使用所有声明金额签名的单/双记录组合及公共组激活输入。不存在从隐藏模型选择查询池的步骤。所谓“最优”仅对这个池，不是对所有实数金额或所有可能数据库的全局下界。

## 实际覆盖和结果读法

10 个预先定义的任务共 216 个语法模型实例，覆盖：原 12 模型；2/3/4 键；外层限额低于、等于或远高于组内限额；键共线；禁止排除；所有金额都达不到任何限额。它们不是 216 份独立法律。每个任务另有未交给学习器的 512 个多记录压力输入；低额任务用其 81 个完整离散输入。

**直接恢复、同探测约束、最大分歧均为 216/216 行为恢复正确。** 最优树在适用的小类任务上同样全对。正确要求：既匹配共同查询池，又匹配额外压力输入；对约束枚举还要求全部幸存候选都正确。允许行为等价，不要求唯一语法树。

原始 12 模型中，直接恢复平均 3.33 次、最坏 4 次；同探测约束完全相同；最大分歧平均 1.50 次、最坏 2 次；最优树平均 1.42 次、最坏 2 次。这里各方法平均值统一按 12 个语法实例加权；`exact_minimax.expected_queries_uniform_class` 则按 10 个行为类加权，不能混用。

4 键任务的直接恢复平均 6.71 次、最坏 7 次；最大分歧平均 3.79 次、最坏 6 次。键相关任务直接恢复平均 6.80 次，最大分歧 1.70 次。没有出现直接法在查询数上胜过强对照的证据。

直接法零次完整候选程序评估，且确有较低本地计算量。但同探测枚举在原始任务只需 264 次候选评估总量，4 键 68 个实例只需 10904 次；小规模下这是很便宜的代价。因此不能仅据“枚举指数增长”的渐近措辞宣布实际必要性。

## 边界修复与计量

独立审查发现：原版只处理了“所有金额都在阈值下”的域，若总额上限为 8、C=7、B=12，首个次序探测金额 10.5 会非法。现已在发送前检查；返回 `unsupported_domain`，零非法查询，不假装完成。另设总额上限 12，检查后续 scope/outer 探测的边界。详细结果单列，不并入 216 个成功实例。

恢复器本身使用 Fraction；本轮主对照的金额格点为 1/8 单位，编码器对不适配的数值直接报错，未假定无成本无限精度。独立审查使用另一份 Fraction oracle 做了更广参数检查，结果由该审查文件单列。

账本分为：学习获取的隐藏函数查询；候选输出预计算；参考函数压力评分；同探测候选筛选；隔离性审计；学习程序/幸存程序的后验核验。`summary.json.exact_all_dsl_evaluations` 全部记录，学习调用总数和逐次 ledger 已用断言对账。树的状态数、评估的查询分区数以及最大分歧扫描的表格单元数另列，不藏到“0 oracle”里。

各方法学习耗时均在学习器返回后立即截断，不包含后验压力评分。公共输出表和最优树预计算的时间单列；其跨实例共享是公开且可复用的，不能把共享成本算成每次查询成本，也不能完全不报。毫秒级本地耗时只是实现描述，不作显著性结论。

## 可复用性与方法贡献判断

独立键分支输出 `group_by_keys` 或 `record_id`，从而保留可用于新记录的表达式。键相关分支仅恢复当前可行域分区；外层限额因固定记录数不足而未激活时，其未确定存在性也不能随便迁移到更多记录。尚未训练自然语言→这些表达式的编译器，没有跨法源性能结果。

[Xpose](https://arxiv.org/html/2504.10898v1) 已利用输入响应、结构分解、文本和组合搜索恢复复杂查询；[partition-rank learning](https://d-nb.info/136754226X/34) 已高效学习同类共享容量分区；[SketchAX](https://rishabhmit.bitbucket.io/papers/popl20.pdf) 已利用关系扰动约束合成。本实现新增的具体工程内容是：在声明的 cap/exclusion 语言中给出可执行的未知范围/顺序隔离流程，并保留遮蔽等价，而非仅枚举测试案例。

但实验也表明，同样关系监督交给普通约束枚举即可得到同样正确结构，最优/主动查询更节省 oracle。**因此目前只能保留为一个可工作的专用恢复算法和基准组件，不能把它列为已经证实扎实的独立论文创新。** 不能因为还没有测试跨法源编译就断言它必然无价值；也不能以未来编译器可能涨分抵消当前未显示的增量。

## 有限后续算法想法的判断，不新增实验

根提出的定向改动可在此 DSL 中成立：一个 base 记录金额 C，再加 d 条各只改变第 j 个键、金额 `2^j ε` 的记录。如果小额和低于组内剩余辨别范围和外层 headroom，则输出为 `C+Σ_{j∈K}2^j ε`，一次标量响应可编码键子集；逐记录与全部键还需额外重复键记录区分。

当前查询池没有这种非均匀多记录编码，不能说主动对照已用过它。加入后必须同时允许强对照使用。固定分币精度且 C=7、B=12 时，一批最多装入 8 位金额码；12 键需要分批，不能免费假设任意小有理数。它属于已知 coin-weighing/group-testing 思路的领域构造；rank-query 近邻本身也涉及 coin weighing。可作为一次明确的算法修改检验，但这里不据此另立“新理论”或掩盖本轮结果。
