# [历史快照] LegalSkillGuard 技能、模型与历史运行审计

审计日期：2026-09-08。

> **禁止作为现役执行规范。**本报告保存逐候选后一块配对准入时期的故障证据和旧run统计。正文中的“现行”、`provisional/DEFER`、每批2个、三块累计验收及三臂结论只表示2026-09-08快照，已被2026-09-09的LegalSkillEvolve直接积累协议替代。现役设计为128案8×16、合作型K=4、每块最多3簇且通用/领域证据同时存在时至少各1簇、五类硬门后直接入工作库、逐块prequential整体库观察、每两块库级维护及冻结后官方30案外测。执行真源见`README.md`与`docs/architecture/current_research_protocol.md`；以下历史案例仍可用于回归，但不得恢复其生命周期或结果。

## 当时结论（已被新协议替代）

现行项目已经在代码层收敛为一条可解释的论文主线：冻结Qwen3-8B进行多轮咨询，Luna只从训练期同状态优劣轨迹中归纳结构化技能文档，后一未见训练块从首轮起把文档提供给Qwen并前瞻决定保留或回滚，最终以事实获取效率、完整性和安全共同评价。不存在运行时技能触发器，也不存在模型作答后的规则改写。

CPU层面已经闭合：755项测试、35项静态论文协议检查和代码风格检查全部通过。2026-09-08又完成绑定当前模型revision、提示和数据哈希的客户组件、本地语义评审与Luna严格schema探针资格。现行活动库仍为空，且尚无schema-16正式轨迹、正式技能、学习曲线或官方外测结果。因此当前可以声称“框架、证据边界和训练前运行资格已就绪”，不能声称“方法已经提升”。下一次GPU运行的首要任务是从空库启动同一现行run的正式第一批，而不是恢复旧run或再造20/64条旁路探针。

## 当时技能生命周期（已退役）

1. 128个自建案件按8块×16案顺序运行；每案只出现一次，每案一个预声明人格，K=4形成同状态结构化策略分叉。
2. 程序先从健康且可归因的优劣轨迹形成F（新事实）、G（外部证据缺口）或safe-stop证据簇。一个同法域严格分叉即可支持领域候选；通用候选需至少跨两个来源法域。
3. 每批最多新选两个行为机制不同的证据簇。Luna对每个簇输出一个边界清楚的完整方法文档或`NOOP`。这不是“每批只能有一个技能”，也不是按法域配额强造技能；第1—7批理论上最多形成14次新候选机会。新提名预算与延期容量分离：每批仍保留2个新提名位，三块验证期限内最多并存6个provisional。
4. 候选须通过结构、安全、去重、精确教师响应身份、来源因果见证和活动库联合提示容量检查后进入`provisional`。这些门只证明候选来源合法且可部署，不证明有效。
5. 紧接的未见块把“活动库+候选”作为固定会话文档从首轮起提供给治疗轨迹；共享对照只看活动库。Qwen自主决定怎样运用，程序不做触发、不替换问题。
6. 配对结果必须平均收益为正，并出现新事实增加、合法证据缺口增加，或不损失信息的提问减少；同时检查有害尾、unsupported、belief-as-fact、重复、过早结束和fallback。client/memo/policy的模型替代恢复事件只在看结果前隔离完整配对，不作为候选负面证据；真正的治疗臂契约缺陷才立即拒绝。方向安全但覆盖不足可累计最多3个未见块；否则`ACCEPT/DEFER/REJECT`。
7. 第8块只处理第7块候选，随后冻结库并运行官方外测。每批固定8个哨兵案只画“当前库对空库”的开发曲线，不参与教师或候选准入。

这里保留“一簇一文档”是为了让来源假设和后续效应可识别；一个文档内部可以有1—5个连贯步骤，不会被机械拆成碎片。若新run存在合格簇但教师链无故不调用或丢失候选，这是实现故障；若Luna在证据确实不足时返回`NOOP`，则不是靠放松门槛强造技能。

## 历史run真实说明了什么

run15—29均为已隔离的schema-15调试运行，且大量案件在不同run中重复，不能合并成论文样本或学习曲线。但它们仍是定位系统故障的有效回归集。

| 历史量 | 只读统计 |
|---|---:|
| 轨迹 | 2142 |
| 律师提问 | 5205 |
| 每条会话内去重后的客户事实披露数之和 | 2165 |
| Luna提案 | 40 |
| 形成候选 / `NOOP` / 无效输出 | 31 / 6 / 3 |
| 前瞻审计 | 22 |
| `ACCEPT` / `DEFER` / `REJECT` | 1 / 8 / 13 |

这组数直接否定了“旧实验里技能教师完全没参与”这一猜测。Luna能够从旧证据形成候选，旧系统的核心瓶颈是候选身份与来源绑定、候选分配/验收、裁判与memo健康，以及最重要的旧技能执行语义，而不是教师模型单纯太弱。

历史各块的粗略“事实/提问”并不单调：run15前五个完整块约为0.443、0.355、0.308、0.412、0.393，run19相应约为0.453、0.351、0.340、0.422、0.473。各块案件、人格、候选臂和实现状态不同，这些数不能解释为模型随批次退化或提升。现行固定哨兵的“当前库对空库”配对曲线正是为解决这个可比性问题。

### run24的正例为何不能冒充现行技能效果

旧run24接收过schema-1技能`lsg.general.ask_high_critical_fact_priority`：8个配对中2案被旧引擎触发，平均奖励差`+0.061488`，两案各多取得1个事实且未记录有害尾。实际对话揭示了真实因果：

- `lsg_cn_0078`中，对照律师问“缴费凭证上明确记载的收费项目是什么”，客户不知道；治疗轨迹里Qwen原本仍提出同一问题，旧执行器却在作答后将其改写为询问“实际排污行为的具体情况”，从而取得F4。
- `lsg_cn_0098`中，对照问“是否已经签署正式合同解除协议”，客户不知道；治疗轨迹里Qwen也提出同一问题，旧执行器将其改写成询问“导致合同解除的具体原因”，从而取得F1。

所以这只能支持一个待重验的语义假设——优先询问高价值、客户可答的未决事实可能有用；它没有证明Qwen读到技能文档后会自主改变行为。现行schema-16已删除这种动作改写，只接受固定提示文档作为唯一干预。上述两个案件仍自然位于当前第二训练块；若第一块独立产生相似的schema-2方法，它会在正常前瞻流程中重新接受检验，而不会导入旧技能或旧结果。

同一旧run中，`final_to_ask_high_critical_fact`虽平均奖励`+0.032924`、每个暴露配对平均多0.875个事实，却平均多2.125次提问、有害配对率25%，unsupported增加0.091667、belief-as-fact增加0.25，因而被拒。这说明只追求“多问出事实”会产生不安全和低效技能，保留效率与安全门是必要的；不应为了每批硬落一个技能而放行该类候选。

## 历史故障如何进入当时回归

- 旧动作改写与零触发：改为固定会话技能文档，每轮逐字重渲染并校验文档ID和哈希。
- 客户把正确问题答坏、或把错误问题答成成功：客户模型只做闭集事实路由和有限披露信号；程序决定披露状态并逐字渲染绑定事实，协议失败不得伪装成“不知道”。
- 开场泄露边界：两个冻结模型只负责筛查候选项，39个提示项全部由研究者逐项裁定；逐案质量报告不再错误要求重复资格。
- 同名候选绑定错教师响应：现行候选同时绑定有效响应、来源见证、响应哈希、模型、证据簇和完整技能定义。
- 单个候选合格、合并后提示超长：活动库、延期项和本轮新候选在消耗下一块GPU前联合准入；未门禁消融也使用同一预算下不看结果的来源顺序first-fit，绝不截断文档。
- 旧缓存跨模型revision命中：缓存身份现含精确revision与adapter schema v2；旧资格缓存已隔离。
- 配置指标与代码报告漂移：五类指标清单现由启动时精确校验，报告只读取已校验配置。
- run28“迁址加油站名称”末字被当成“客户称”：已由词法/句法边界回归覆盖，不能再用末字包含关系报警。
- 稀疏候选唯一配对发生恢复事件即被永久拒绝：候选契约健康与矩阵覆盖现已拆开；无负面证据但覆盖不足只会有界`DEFER`，健康报告若截断或损坏则停机恢复，绝不伪装成候选`REJECT`。
- 延期候选被新候选长期抢走适用案件：候选按不看结果的生命周期年龄优先，同年龄轮转，剩余案件继续分给新人。
- 两个延期项令下一批Luna预算归零：每批2个新提名与最多6个并发provisional分别冻结，carryover不能静默削减新提名。

这些历史材料不会进入新教师上下文、现行技能库、学习曲线或论文统计；它们的唯一用途是证明对应故障有回归防线。

## 当时三个模型与七种功能调用

现行正式实验运行链是三个唯一模型，不是七个不同大模型：

| 模型 | 功能调用 | 论文中的地位 |
|---|---|---|
| 冻结Qwen3-8B | 律师策略、opening共享规划、抗拒/对抗人格披露信号分类、最终memo | 被研究的弱律师及共享脚手架；技能臂与对照臂使用同一revision和随机流 |
| 冻结gpt-oss-20b | 客户闭集事实路由、离线结构化语义评审 | 两套提示、schema、输入权限和缓存隔离；同一权重复用，不能宣称统计独立 |
| gpt-5.6-luna服务别名 | 只从合格训练证据簇生成技能候选 | 不评分、不验收、不看下一块或官方外测、不直接激活技能；记录调用日期、CLI及请求/响应哈希 |

确定性Python负责状态、客户最终披露决定与绑定事实回答、F/G计数、奖励换算、优势、来源绑定、门禁、哈希和统计。语料由当前gpt-5.6-sol high会话在最高法来源约束下逐案重建与研究者复核，但它不属于正式实验运行链。

这个分工可以写成清楚的论文故事：Qwen是唯一被技能干预的目标策略；Luna是离线经验归纳器；gpt-oss提供环境路由与兼容语义评审；确定性披露ID构成主终点，降低单裁判归因风险。Qwen自己的共享规划、披露分类和memo在所有实验臂完全相同，影响绝对难度但不是预期处理差异。gpt-oss双角色必须披露为同权重相关偏差，不应包装成两个独立裁判。

当前三臂能识别：完整系统相对空库的总体作用，以及前瞻收益/安全门相对“仅来源合格候选”的增量作用。它们不能单独证明Luna优于另一位教师，也不能把`control_no_library`称为纯`no-teacher`消融，因为该臂同时移除了所有技能内容。后续论文若需要单独归因教师质量，必须新增预算匹配的教师消融；这不是当前主链的实现缺口。

## 指标与外测边界

主终点是确定性的“每次提问取得的唯一新事实数”。同时报告唯一事实总数、Fact Coverage和Resolution，防止少问早停伪装成高效率；再报告Elicitation、Fidelity、安全、fallback、候选转化率和活动库规模。内部语义指标采用DLawBench兼容定义，但本地单一gpt-oss裁判不能冒充官方多供应商排行榜。

用户确认当前冻结官方中文30案在另一工作窗口重新整备后从未用于运行调试、模型/提示/门槛选择、教师或候选准入。当前payload的SHA256为`11e16b7d0bf68f8ddab706cda2c5ecdcd4cb4e8937bb8ba1f9f5148626571528`；现存run行为资产扫描也没有官方case ID。它只可在最终库冻结后外测。DLawBench是公开数据，因此论文可声称严格held-out执行边界，但不能冒充研究者从未见过的私有盲测。

DLawBench本身是多轮法律咨询基准，并用四类客户人格测量事实询问与解决能力；其官方仓库当前公开规模大于本地固定CN30，因此论文应准确写“冻结的官方公开中文30子集”，不要写成“DLawBench总共30案”。SAGE的顺序技能积累为“前块学习、后块继续使用”和效率曲线提供相关方法依据，但不等同于本项目的法律安全前瞻门；FlowSteer可作为结构化策略学习的工程启发，ScienceClaw的运行时技能文档只能作为工程参照，不能代替本项目的因果验证依据。

## 当时臃肿性判断与GPU前结论

已经删除或隔离的表面包括旧运行时skill engine、20/64/18额外候选探针、旧资格与结构化缓存、旧协议run、无revision及错误模型revision的planner缓存、未使用adapter、未使用文本技能渲染器、退役schema和空目录。当前只保留按Qwen精确revision分目录且按完整请求哈希命中的planner缓存。保留的K=4、8×16、相邻块前瞻验证、固定哨兵、事务恢复、hash/health gate及该精确缓存都有明确因果、统计或运行职责，不属于为了“Guard”堆出的装饰。

`executor.py`和`stateful_policy.py`仍较大，这是维护性债务，但在GPU验证前拆分会扩大回归面；它不改变现行实验概念，因此不作为下一次运行的阻塞项。历史档案约2.4GB，因本次需要用作故障回归证据而保留在隔离目录；正式入口和run恢复均无法读取它们。

当前两个冻结本地服务、客户路由资格、本地裁判资格和正式preflight均已通过。下一次持续监控会话只需从空库启动run `main_experiment_128_gpu_ready_20260908`的正式第一批。第一块要看健康轨迹、严格因果簇以及Luna是否对合格簇给出有理由的`CREATE/NOOP`；第二块要直接检查schema-2文档从首轮真实暴露、Qwen是否自主改变行为及门禁是否产出可解释的`ACCEPT/DEFER/REJECT`。若这两步未发生，就按对应不可变产物定位实现问题；若发生但效果小，再讨论方法优化，而不是回到旧探针或旧动作改写。
