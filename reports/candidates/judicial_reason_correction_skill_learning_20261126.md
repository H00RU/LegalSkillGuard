# 基于复审理由纠正的法律技能学习

**2026-11-26，M3 当前完整方案。** 已核验三个法域的代表性案件组，正式样本清单、方法实现与效果验证待完成。 [研究交接](../../docs/NEW_CHAT_HANDOFF.md)

## 研究问题

一审可能以错误的法律理由得出后来被维持的结论。只按请求结果给技能反馈，会把错误理由和正确理由都记成成功；复用错误理由时，另一份案情可能因此被判错。二审对一审理由的明确纠正提供了结果标签遗漏的监督。《最高人民法院关于适用〈中华人民共和国民事诉讼法〉的解释》允许二审纠正原裁判的理由瑕疵并维持结果。[司法解释原文](https://fgw.sh.gov.cn/cmsres/72/72c595db88b6404e8cd85af803da0733/974f8c31401beb1b78c560a4b92d04c7.pdf)

## 方法

1. **从同结果的两审对中学理由边界。** 教师按单个请求对齐两审理由。只有二审明确实质纠正了某一理由时，才提取被否决或限缩的要件、触发该限制的事实、可独立成立的其他依据，以及各自的原文证据。卡片同时记录争点、法域、法源版本和裁判时间。未审理、材料不足和单纯表述修正分别记录；仍有效的依据全部保留。
2. **用真实改判校验后果。** 在独立的同类案件中，核对这个要件是否会改变某项请求、哪些请求仍有独立依据，并据此确认或收窄卡片适用范围。按诉请匹配正式主文和理由。金额、利息起算日等实质变化另行核对，防止仅凭粗粒度标签相同就判定结果不变。
3. **在新案中有条件地应用。** 执行模型保持冻结，技能保存在外部库。模型按争点调用卡片，根据当前可见事实和适用法源检查触发条件，仅排除确实不成立的依据，然后使用其余有效依据完成逐请求判断。证据不足时保留不确定性。当前案件的目标裁判及理由用于评分和人工核验，推理时不可见。

例如，某案二审接受买方的消费者身份，但发现卖方明知要件没有证据，仍维持驳回十倍赔偿。教师记录的是该类请求下消费者身份与卖方明知须分别判断，以及一审否认消费者身份的理由在何种事实下不成立。遇到另一宗购买纠纷，技能引导模型分别判断两项要件，并独立处理退还价款等请求。这一更新能在原案答案没有变化时发生。其潜在收益出现在旧错误理由恰好会左右另一个案件结论时。[AppealCase 公开数据，第 2525、3045、2755 行](https://huggingface.co/datasets/ythuang02/AppealCase)

## 样本划分与混合训练

1. **核验请求和理由。** 按正式主文对齐两级文书中的请求、金额、利息起算等救济结果，按理由原文标记明确纠正、仍有效的独立依据和适用条件。清单保存来源、法院、案号及别名、两级文书 ID 和日期、案件组 ID、请求 ID、标签与证据指针。争议类型、理由变化、结果变化、未审理、发回及不确定各用独立字段记录。
2. **按争议分组再划分。** 各来源内部按同一一审案、合并或平行上诉、同一基础争议或行政决定、模板近重复和公开版本别名去重。案件组内所有文书和请求只进入一个集合。已逐案复核的 18 个代表案件组登记为开发已见，用于适配和标注校准。只在 TRAIN 或 DEV 使用这些组。公开原库的分片名称仅用于溯源。
3. **锁定各库 TRAIN / DEV / TEST。** 以独立案件组为单位，优先按复审裁判时间由早至晚划分，初始目标约 **70% / 15% / 15%**。锁定前结合每库实际独立组数、争议族和原生标签覆盖确定最终配额、时间界限及分配规则。记录每库各集合的案件组和请求数，列出同结果理由纠正、真实改判和普通维持的覆盖。DEV 用于确定配置和查验评分。封存 TEST 标签和输入清单，评分端与训练端隔离。配对、来源数或标签覆盖不足时先补足真实案件并复核，再锁定配额。
4. **三库 TRAIN 混合建库。** 同结果理由纠正为主要学习信号，真实改判用于检验适用范围，普通维持用于查验是否误改原本正确的判断。跨批次按来源和争议族覆盖安排样本，并记录实际暴露。教师只从 TRAIN 的两级材料生成或修订外部技能，执行模型保持冻结。技能调用限制在匹配的法域、法源版本和目标裁判时点；对照组使用同样的训练资料、检索范围和时点规则。每批保存技能库版本、来源、采纳记录、配置和实际调用账本。

| 相关工作 | 已覆盖的机制和 M3 的新增部分 |
|---|---|
| [SkillCommit](https://arxiv.org/html/2608.15165v2)、[SelfEvoSkill](https://arxiv.org/html/2606.14239v2) | 已有局部技能补丁、验证和有无技能的轨迹比较。本候选的更新信号是实际二审对某个法律要件的明确否定；即使原生结果没有变化，也能生成带事实条件和法源的修订。 |
| [SkillCoach](https://arxiv.org/html/2607.01874v1)、[LegalReasoner](https://aclanthology.org/2025.acl-long.361/) | 已有过程细则、步骤验证和基于过程的训练监督。本候选把成对裁判中被否决的具体理由和独立有效的依据写入外部技能，供冻结模型在新案条件满足时调用。 |

## 验证设计

- **同信息、同预算的比较。** 各组共享冻结执行器、教师、训练双审文本、适用法条、候选检索范围及推理预算。比较普通文字技能更新、检索先例后逐请求复核和 M3。另固定卡片结构和流程，用普通结论总结替换理由纠正监督做消融。
- **用同一混训冻结库分库评测。** AppealCase 报原生逐请求宏 F1；BrCAD-5 报发布协议下的整案二分类，并单列原始三类处分结果；EUR-Lex 报基于官方主文的处分与逐请求救济结果。三库另分别报告经核验的请求级指标、真实改判请求表现、应维持请求的误改率、被否决理由复用率和有效技能调用。以独立案件组作配对比较和不确定性估计。若主张混训本身带来收益，增加同目标库单库训练的匹配比较。
- **统一输入可见性。** 测试输入限目标裁判前已知的一审材料、当事人诉求与当时适用的法源；目标复审理由、主文及事后事实认定仅用于评分。去掉泄漏字段后的 AppealCase 输入协议单列报告。论文表 6 的 Qwen3-8B 宏 F1 为 59.73，作为原协议公开参考。 [AppealCase 任务及结果](https://arxiv.org/html/2505.16514v1)

复用现有执行器、教师调用、外部技能库与连续账本。可先用 AppealCase 打通真实配对、技能生成、部署和评分；随后接通另两库，核验三库清单和对照，按锁定的协议完成混合建库和分库评估。交付代码版本、清单与摘要、可见输入协议、逐批技能库、逐请求结果和实际成本。 [研究交接](../../docs/NEW_CHAT_HANDOFF.md)
