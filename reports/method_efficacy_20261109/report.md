# A/B 方法有效性复核与必要修订（2026-11-09）

**阶段结论：不建议为当前 A/B 独有贡献主张进入正式 TEST。** 生成、执行、建库和保存已能够工作；本轮进一步修好了真实模型程序进入编译库的更新路径，并验证了后续解析改善。但在当前表示中，B 的已用分支没有提供正确普通连接器缺失的信息；A 的实际分离机会也没有比静态查询依赖对照减少生成请求。当前应保留可用基础设施，停止把这些证据包装成 A/B 方法收益，等待用户复核。本结论不以“五库都涨分”、显著性或零回退为条件。

本报告是方法诊断与修订交付，不是论文、正式 TEST 或新选题。原128 TRAIN、8批、六组 DEV、原始失败和冻结库全部保留；没有重新跑一轮建库或六臂对照。

## 3. B：当前 entity_equality 分支被普通连接器吸收

新增[标准连接执行入口](../../legal_skill_guard/rr/horn_connectors.py)，与 B 共用匹配、关系类型、`Relation.join`、查询编译及调度器。连接键直接来自模型 IR 已明确给出的共享变量，没有擦键、少执行规则或弱化类型。普通原子统一是另一完整语义对照。

[同程序干预](B_same_program_interventions.json)覆盖全部21 TRAIN、7 DEV接受的真实模型逻辑程序，检查完整推导闭包、查询值和1402个唯一规则实例的关系输出。TRAIN严格恢复各来源之前的库前缀，DEV才使用最终冻结库；未来来源没有回灌。结果全部一致。DEV 中 B1、B8、仅首模式、仅次模式也给出相同完整语义。

结构原因比单一准确率更直接：当前分支的连接键是左右关系列的交集 K。被选中的学习图同样执行两槽 `join_on`，角色列代换后仍然是 K。输入相同时，每个规则实例输出相同，迭代闭包也相同。这个论证限于当前实际 entity_equality Horn 分支；不是对所有可能 B 表示的否定。

原候选生成器擦除等式能够制造粗接口碰撞，再让模式恢复键；这些人为擦除输入没有当作普通对照。第二模式单独启用可以执行，原来未被选中是等价候选的排序结果，不是新增推理能力被隐藏。

三次轮换热运行、28程序各自中位时间的和：标准连接0.3205秒、实际B库0.3465秒、普通统一0.02735秒。计时关闭诊断收集，未增加模型或数据试次。这组小规模CPU结果不支持当前B加速主张，也不外推大型数据库性能。

原 DEV 有5个逻辑来源实际调用 B 图，96次图执行、54次查询相关；跨库实际调用仍为0。此前32个可编译的非PW初始程序（23航空、8 SARA、1 OpenExempt）没有连接器节点；当前实际输入因而没有 B 的调用机会。目录曝光、共同训练和 Python 执行均不算跨库迁移。

## 6. 借鉴来源与贡献边界

此前已经落地的轻量程序翻译与确定性执行借鉴 [PAL官方实现](https://github.com/reasoning-machines/pal)、[LINC官方实现](https://github.com/benlipkin/linc)、[Logic-LM官方实现](https://github.com/teacherpeterpan/Logic-LLM)；其程序表示、提示/生成接口和错误修复依据详见[原参考实现设计](../rr_method_runtime_20261107/reference_frontend_design_20261108.md)。不将成熟程序执行范式、语法检查和提示示例当作本研究创新。

本轮静态查询依赖强对照属于标准需求驱动思路，可参照[Soufflé官方 Magic-Set 文档](https://souffle-lang.github.io/magicset)；这里实现的是AST依赖切片，不是完整Magic-Set复现。普通连接遵循显式共享变量的关系语义。近期[Policy-as-Logic for Robust Reasoning over Rules](https://arxiv.org/html/2608.11905v1)也采用政策形式化、运行时事实提取与求解分工；它支持基础架构的合理性，不能替我们证明 A/B 的额外收益。

本项目本轮保留的具体工程产出是：带来源与作用范围的残余完成性检查、可对照的静态选批、真实响应溯源的编译程序晋升、受限单例检索、可恢复冻结库和完整成本记录。当前证据没有把这些工程产出提升为 A/B 核心方法贡献。
