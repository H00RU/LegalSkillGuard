## 学习对象与实际更新

旧服务schema在事实读取阶段要求is_query_service，模型需要看题目；上一轮实际把题目工作日填成了服务日期。本轮两位独立教师接收相同原文、两臂当前库、真实失败、部分源反馈和作者法条，各一次调用、各提出两个联合版本。更新对象是**服务观察schema＋事实读取程序＋查询转换程序**，执行模型权重不变。

事实读取现在仅接收当前facts，题目和native query只在后续转换中用于已有事件的身份对齐。新组件实际移除了is_query_service。方法候选0将协调主语展开为事件；候选1保留service_relations、workers列表及句内period，再由转换器展开。后者被预定获取检查和代码长度次序选中。普通教师同样可修改表示、程序和转换，已选候选0使用平坦服务记录；不限制控制表达能力。

实际学得程序保留Alice→大学的服务角色而不填入任何服务日期；把农业劳动协调名单展开为三个正确工人；保持下一句反向工作及其独立期间。固定后案的实物支付不被误当作没有服务，付款年份不变为服务起止日。所有实体、日期和事实由当前原文取得，不传案例ID、标签或参考事实到运行时。

主读、补读和候选重组均保存facts_only语义；补读的程序残余只提供结构，不把查询事件字面值带回事实专用读取。持续学习的教师输出接口也已支持该输入范围及可选观察程序，避免后续完整替换组件时无意丢掉学得读取能力。没有启动新的完整训练。
