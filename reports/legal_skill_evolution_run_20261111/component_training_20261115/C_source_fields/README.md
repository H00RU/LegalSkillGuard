后两源的目标条款10、51都已经被原学得planner实际查询；这里人为固定它们作失败定位，不能声称证明了自动覆盖。最后一版不再要求模型重复生成宿主已有的条款ID和谓词引文，保留全部原文、证据域和语义字段，未改原生评分或允许错误法律结论。

可见schema修复前后原文、系统提示、host/decoder schema逐项相同；唯一变化是公共提示函数把host schema放入模型输入。锚点缺陷通过两份实际请求复现：原本governing/evidence的所有枚举都被别名改成单一focus；修复后逐个验证完整原文ID仍可引用。这个软件修复不等于模型已正确使用跨条款关系。

最后两次实际输出分别4.59秒/141输出token、5.41秒/111输出token，均stop，解决了该小接口的生成负担，但**语义仍未通过**：

- e671第10条明确写agents和professional advisers；最终输出的recipient_members为空。不能以“格式正确”把这两个接收者补回去。
- 442c第51条“Notwithstanding anything in this paragraph 6”限定依法保留记录副本，所覆盖的第6节包括48—50的终止返还/销毁；最终读成confidentiality_duration_only。第53条才是对保留副本持续保密的条款。不能把两者合并，也不把正确predicate和modal当作完整正确。

## 研究决定

不继续扫描这个手写大框架。它没有消除信息损失，不能接入C后冒称学得机制成功。继续既定C源程序/组合学习：由教师利用原TRAIN真实失败修订可复用源程序和有出处的局部作用域组合，保留已有效的处置/留存转换；普通教师用相同原文、监督和程序能力独立修订。不得全局删除“限定留存”来修好一个普通使用场景，不得要求每个列表项自己重复上文生效谓词。

这不是8B法律记忆测试。同模型原有直接回答在上一对为6/8，而C4/8；资料进入表示和组合时丢失的问题仍需方法解决。源字段接口、公共修复、fallback和少数正确字段均不算两项贡献成立。
