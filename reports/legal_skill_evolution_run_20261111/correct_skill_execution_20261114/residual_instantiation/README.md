## 当前暂定机制

问题是正确法律程序已经取得并送达，弱执行模型仍将案件中的关系方向、持续状态或未读取事实绑定错误。例如“自2017-02-03起已婚”被绑定为婚姻始末同日，或仅记开始而无法判断当前状态。

学习对象是**技能条件下的案件观察契约**：案件中哪些源文状态/事件形式应被观察、它们如何映射到固定法律程序的输入，以及哪些观察不足以决定输入。教师生成观察schema、事实读取指令和纯事实绑定程序；法律核保持，错误/未读不直接变False或空集。当前源契约学习和真实使用已完成，重复学习/独立反馈收益尚未证明。

本轮新增执行路径：

1. 对真实未解决返回追踪动态数据与控制依赖，定位此次阻断的输入通道。当前实现是实际依赖切片，不声称全局最小查询或语义完备证明。
2. 沿已学绑定程序反查该输入对应的案件观察字段，自动编译原子事实读取。当前支持单个相容视图、单个数组事实通道；其他情况明确未解决。
3. 只有明确完成当前有限文本读取的`none_stated`才能映射为空集，`unread`保持未知；正事实与文本缺席均保持原文见证要求。
4. 重跑同一绑定程序、相容性检查和法律核，不改法律规则、不选择有利答案、不以fallback补齐。

在实际8175输入上，ProgramGuided的学得持续婚姻转换已完成，执行残余指向`legal_separation_decrees`，绑定程序反向切片得到`views[0].decree_facts`。Direct的原输入在更早的婚姻持续性检查停止，残余指向婚姻的end/open字段。两者不是按原生答案人工挑选同一补读通道。

实现：[动态残余](../../../../legal_skill_guard/skill_evolution/kernel_residual.py)、[字段读取编译](../../../../legal_skill_guard/skill_evolution/observation_slice.py)、[运行路径](../../../../legal_skill_guard/skill_evolution/kernel_residual_reader.py)。新模块与既有合同来源`residual_reader.py`职责不同；后者已按原提交字节保留，旧消费者不迁移。闭合运行的原源码快照另存，不用修改后的驱动重新启动原run。

**强控制揭示的限制**：最后一个联合控制直接给出了足以决定答案的事实内容。单独把其明确`none_stated`投影为当前有限集合、保持所有正事实原样，现有适配器/P得到Entailment。此[事实载荷诊断](joint_scoped_diagnostic.json)不补任何引文，明确标记`strict_response_accepted=false`、`counts_as_core_success=false`；它不是合法接受结果，也不修改原失败。它说明不能把本例的额外作用直接归给定点读取：联合的source-status表示至少在事实内容层面吸收了作用，尚缺真实可接受控制及跨来源增量证据。

发现一个具体接口不一致：原生成schema允许空witness数组，而host要求非空。已在当前字段编译器把records/none_stated设为minItems=1，unread仍可为空；用真实失败响应回归，缺席空见证现会在生成schema校验阶段拒绝。没有放宽host、没有补造见证、没有为此再请求模型。冻结原始schema与驱动保持。

三个相关测试文件共**21项通过**，包含实际程序返回保持、可选null不被误判为必读、两臂实际阻断差异、从真实绑定推导字段、未读与明确缺席区分、已处理不补读、真实缺见证回归及原来源读取器回归。检查不等于方法收益。
