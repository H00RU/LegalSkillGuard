# 旧版 EC/EV 修订与当前 CoRev 的关系

旧版确有承接价值，且不只是把EC和EV分别调用教师。2026-11-05交接前的utility-v6已经实现任务保护、法域依赖分组、整体/局部组合选择和历史失败回放。这些内容属于已有工作，当前方案不能将“同时改多条技能、整包验收、保留失败”重新认领为新贡献。

## 已核对的旧设计和实现

| 旧版内容 | 实际实现 | 当前可以利用什么 |
|---|---|---|
| EC/EV任务保护 | EC修改保留EV投影，EV修改保留EC投影；一条记录可有两个不同任务的指令块 | 局部修订的默认边界；保护无关职责，减少整库重写 |
| 依赖一致的编辑分组 | 同案允许共同出现的法域、记录迁移和改变的ALL指导形成连通分量 | 保守结构邻域/强基线；不是学得的语义修订依赖 |
| 整体与一个局部组合比较 | 对合格分量取并集，再与整个教师提议比较；没有枚举所有子集 | 候选组合、来源级回放、提交和恢复的成熟基础 |
| 规则缺陷与执行失误分开 | 执行失误保留原规则前缀，修改执行示例；规则缺陷才允许改规则 | 先判读取、表示和执行错误，再决定是否重写法律规则 |
| 真实历史失败保留 | 无关成功或noop不会擦掉旧失败见证，回放仍绑定原候选身份 | 当前修复上下文、原始输出和连续版本账本 |

旧TRAIN八批发布记录再次核对：EC和EV各8次教学，实际接纳EC 5次、EV 4次，共9次。它有真实实现和学习记录，不只是旧提案。[本次零调用核对](legacy_EC_EV_reuse_evidence.json)保存源文件hash和计数。

## 与当前第二项贡献的实质区别

旧版回答的是：**怎样改一个任务或一个法域部分，同时保护其他已经工作的部分？** 其依赖分组主要来自公共法域共同出现及结构兼容性。

当前CoRev还要求：**哪些步骤在法律判断职责上发生了联动变化，哪些修订单独不够；这种经验能否帮助下一来源生成和排序修订？** 证明需要固定来源的完整旧/新4格或8格、合法可执行的兼容接口、真正必要的修订集合，以及后续来源对该经验的实际使用。旧版没有完成这项跨来源修订关系学习。

尤其，旧版EC与EV独立答题，EV没有消费EC预测。因此“同一批EC、EV都被修改”不能被改名为上游—下游CoRev证据。旧版的任务投影保护、静态连通分量或整体提交，也不能替代新方法所需的版本干预证据。

旧版完整收益只证明其旧实验中的技能修订有效，不证明当前两个专门机制成立。当前固定研究及后续小试仍未证明CoRev，不据此次比较改变Goal状态或验收标准。

## 当前执行决定

1. 复用任务保护、错误诊断、局部组合与精确回放的有效实现思想和证据；它们作为共同基础或已有强对照，不作为新贡献。
2. 先按真实法律职责组织可调用对象；保持“单改足够就单改”，再从实际交叉执行中判断共同修订。没有工具数据流时不伪造USE；结构共现只作为保守线索。
3. 不为了调用旧函数增加EC/EV格式兼容层。当前已存在的版本包、候选表和请求复用路径继续使用，只移植语义一致、能减少复杂度的部分。
4. 旧库不直接装入本轮。旧128个TRAIN与当前32个OE TRAIN的EC事实文本经NFKC/空白规范化后无精确交集；该核对不是近重复证明。旧库带有不同案例的获取暴露，不能默认为当前固定TRAIN产物。旧EC/EV特定F1、历史均值容差和4096-token限制，也不覆盖当前原生评分、逐来源保留和预算。

## 本轮已完成的关联修复

“规则是否有缺陷”和“执行表示是否失败”的区分已落实到新的真实记录：对同一个原TRAIN家庭雇佣题，改为直接保留原文方向的关系记录后，FreeEvolution学得程序正确执行；Full的原始规则逻辑也正确，但使用了已声明端口的裸变量。仅对无歧义的声明端口做确定性绑定，保留条件、常量和局部变量，复用同一份响应即可恢复。原始失败和首次拒绝记录未覆盖。

两臂在这**同一个已见TRAIN母来源**上均得到正确的确定性程序执行；新增物理请求0E/2T，修复回放新增请求0。不是两个新来源，不是新的executor生成，也不是Lift/CoRev效果。[实际恢复证据](literal_acquisition_recovery.json)。当前累计9115E/152T，在途0，83项相关离线回归通过。

另外，共同调用路径已支持将有源依据的法源前提传入被调用技能，并将这些调用位置纳入真实前提使用清单；提升后的参数先读取、再调用，不会被当作“程序未引用的元数据”删除。这解决法律定义/许可等模块连接的具体接口限制，工程回归不计作创新实证。
