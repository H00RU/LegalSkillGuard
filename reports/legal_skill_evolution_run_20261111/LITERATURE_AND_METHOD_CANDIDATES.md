# 从近邻方法到两项可检验的设计

2026-11-13，北京时间。当前阶段是文献与真实任务证据共同约束的设计校正。本次新增 executor/teacher 调用 **0/0**；累计 **9326/177**，在途 **0**。沿用同一 Goal，未完成。本文是设计检查点，不是两项贡献已经成立的结论，也不是新实验队列。

## 1. 本次改变了什么判断

用户指出先读相关论文、明确与同行的比较，再验证，判断正确。此前偏重接口与局部试错，虽然产生了可运行资产，却没有及时把算法放到最接近的方法旁边比较。现在复用已有查新，补读方法、附录、消融和可取得的官方实现，而非继续把同一批合同修好就称为创新。

合理顺序是：**近邻方法与真实问题 → 明确算法及强对照 → 有限原型 → 根据结果修正判断**。文献不必全部读完才做原型，但不能用读摘要或工程诊断代替查新；原型也要检验具体差异，不能只有格式、执行通过。

当前保留的主问题：冻结模型如何从原始法源学习可持续复用的获取技能，并在新法源改变角色、定义或例外绑定时正确更新它。第一候选延续已有源编译方向；第二候选将“修订”具体化为可学习的语义适用条件和重写。两者均为研究假设，下文明确哪些环节尚未实现。

## 4. 第一候选：从源语义反例学习编译技能

**要学的东西。** 持久化的源到法律关系转导程序G，以及它生成的关系契约R和消费者P。G不仅保存每份合同结果，还学习“什么文本结构表示哪种法律功能、角色怎样绑定、限定条件作用于谁”。公司名是变量值；不能以合同ID分支代替学习。

**近邻假设在这里哪里失效。** 仅按最终答案选规则，无法排除答案相同而法律依据不同的程序；仅压缩已有解，无法取得从未表示出来的授权或例外。逐篇修补可以修当前来源，却未必改善下一来源的获取。这里要把原文支持和源功能混淆变成可积累的转导约束。

**更新算法草案。**

1. 从相同原文、原生TRAIN监督和初始公共底座取得完整候选G/R/P及带出处的派生。教师允许提出新关系、产生式和消费者，host只做通用格式、类型、出处和执行检查，不补法律规则。
2. 对实际派生中的变量绑定和语义组合做类型化反统一，形成可跨来源使用的产生式；记录它影响的实际判断及源依据。不是只重组历史NQG固定表。
3. 保存仍符合已知证据的不同解释。native相同但源关系不同，不能直接按短代码宣布其中一个语义正确；用原文本和现有允许反馈核查差异，不能把模型自评当真值。
4. 由具体矛盾定位相关产生式/关系/消费者，再生成最小的新增、拆分或重绑定。源角色已证错时改G；关系和相关源条件确已充分时才归因P；漏例外或来源不充分时维持未决，不把缺失视为False。
5. 在原有证据和历史行为约束内选择更紧凑的可运行版本，版本化保存G与失败约束；下一来源先实际使用G，再根据真实新反馈更新。成本包含全部获取、检查和拒收。

理论起点是反例引导合成、类型化反统一与程序库学习，均不是新发明。这里的待检验差别是**源语义约束参与跨来源获取器的归纳与修改**。有限候选集一致不代表法律解释完整；不声称得到了全文语义的形式证明。

**手算例。** 第一次看到“信息包括本公司及其employees的资料”，产生式若生成“许可向employees披露”，源功能检查应指出没有许可动作。正确更新是改变角色与动作的绑定程序，使这段派生保持信息主体，而非写入“这份合同nda-5为否”。再遇到“可以向其employees披露”时，需要产生授权关系；两个来源的employees词相同，源功能不同。角色拆分本身是公共底座，贡献取决于学习算法能否更可靠地取得和复用该区别。

**决定性强对照。** 从同样起点独立获取完整自由Python方法，拥有相同原文、监督、语义反馈、全部历史、可比费用，允许选择相同分解、文法和关系；再用RuleChef式候选修补/选择与分解ICL加源核查作为已有算法对照。不能向自由臂提供方法新学出的G/R/P后称为独立获取，也不能只让方法获得更强judge信息。公共解析、执行、类型和未知值修复公平共享。

**已有实现与缺口。** 已有纯程序执行、源识别程序、关系/消费者、版本库、账本和真实10项主路径源支持可复用；它们不是上述归纳器的效果证据。跨来源产生式更新、未决解释维护及其端到端强对照尚未实现。预期检验可靠性或同等正确性下的完整获取成本，不预设必须涨多少分。

## 5. 第二候选：从真实修订学习语义适用边界

**要学的东西。** 条件化更新程序U＝匹配模式、源语义守卫、重写、受影响依赖。它学习一次修订何时能够用于另一来源，以及何时应保留旧实现或分成不同分支。它可以作用于独立自由获取器，不以第一候选特有文法为前提。

**具体区别不能只说“学习补丁”。** Refazer/Getafix已有上下文重写，EviSkill已有修改证据与回放，SkillAdam已有完整问题历史。这里提出的是把法律源关系的正、负适用证据用于学习修订的边界，并使更新只影响被该源条件改变的行为。语法相似不意味着不同合同采用相同规范。这个区别是否超出普通条件化程序修复，仍需强对照决定，当前不宣称查新已证明唯一。

**更新算法草案。**

1. 只从真实教师前后修订和真实执行轨迹取样，不把两份独立程序差分、人工关闭操作或合成错误当作真实修订学习。
2. 将改动与实际改变的源关系、消费者和判断做依赖切片；反统一多条修改，形成参数化重写。切片只解释程序影响，不证明法律真值。
3. 用已有TRAIN原文判断修改的正、负适用情境。由这些证据细化源语义守卫；未知保持未知。不能把“历史答案没变”自动当作法律条件不适用，也不能用合同名或任务标签当守卫。
4. 比较全局改写与条件化分支。在保留真实源约束和历史行为的前提下选择更简洁的更新；没有共同适用条件则保留不同分支，不能按全局多数覆盖合法差异。
5. 在后续来源上实际匹配守卫、实例化修改并执行，保存源依据、版本和成本。不确定时走既有获取/修订流程并单列；只有真实后续适用才算更新技能复用。

**手算例。** 一个程序把所有“employees”都绑定成本方许可对象。一次真实修订学到：某条定义中的employees属于关联方，不能直接作为本方披露授权。但这不能全局删除employees许可，否则会破坏另一份明确许可向本方员工披露的合同。候选应学到改动适用的主体/动作绑定条件，并在另一份材料上正确触发或不触发；不是保留一个354特判。

**独立检验。** 在同一个已取得的自由compiler上比较：普通联合AST编辑＋完整错误—修复检索＋相同全部原文、轨迹与回归；另给Refazer/Getafix式上下文补丁同样的源语义特征。对照允许创建guard、新节点、分支和联合修改。共享初始compiler用于隔离更新；端到端总成本另算。若普通条件补丁已吸收作用，如实否定额外贡献。
