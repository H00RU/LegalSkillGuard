# 明确给定法律前提：机制决定与最近邻核查

2026-11-13。只读当前执行文档、已有研究备忘录、原TRAIN public及最新scoped-premise产物。没有项目executor／teacher调用，没有实验、DEV／TEST或仓库修改。按paper-ideation作定向检查，不从头月度扫描。

## 结论与推荐

**把“法条引用对应一个谓词、GIVEN优先、再作普通演绎”列为公共底座，不能独立占第二贡献。** 最强简单控制应该直接具备它。若要沿这个实际瓶颈继续，值得做的具体候选是：**由失败证明驱动的语义接口细化**，学习新的观察类型及其生产者、消费者和有源依据的消解程序，修复“观察已经含有有效法律资格，但现有接口把它降成无用字符串／缺失事实”的问题。它的学习对象是接口抽象及解释程序，不是又添加一个case-specific GIVEN分支。

这项候选尚未获支持。当前最清楚的两份§152记录，不能直接被当作它的独立效用实验：第一题的时间条件已经为假，正确日期计算足以决定答案，丰富关系GIVEN不会再带来native增量；第二题的方法臂缺少§152(b)(1)可调用规则，需先补齐真实源规则，不能把缺根修好冒充接口学习作用。应先做一个小型离线原型，连同严格stipulation-first控制一起检验，再决定是否值得模型预算。

## 2. 学习对象：有源消解的观察类型，而不是词面别名

当前关系port期待`son/child/...`，却实际收到`pursuant to section152(c)(2)`。后者没有给出具体亲属类型，但已经给出法律所需的资格。把它转成unknown是在接口中丢信息；把字符串随意归成son则补造事实。适当的新类型可区分：

```
RawRelation(word, owner, person, period, evidence)
SourceQualified(clause, named_roles, period, polarity, evidence)
```

消解函数由教师从给定源取得，例如SourceQualified(152(c)(2), …)只证明该条规定的关系资格，不能直接证明完整的152(c)(1)qualifying-child。GIVEN(c1)到dependent的转换需要152(a)的真实源连接；进一步到152(b)(1)还需要正确的角色投影和该条规则。禁止凭子条款前缀直接抬升为母条款成立。

“没有GIVEN记录”表示没有这种给定前提，不等于其法律命题为False。对于阴性GIVEN也保留箭头方向：没有exemption entitlement不自动推出没有deduction allowance。原生问题只给查询角色／期间，不能生成正阴性前提。

这些类型的**手工固定实现属于底座**。候选贡献要学习的是何时接口不充分、该增加哪种区分、怎样更新抽取程序及所有实际消费者，并在新实例中复用。

## 3. 一个可运行、可被推翻的更新算法

状态`A_t`包含：观察构造子、字段编码程序、源谓词／角色签名、源见证消解器、消费者依赖及版本。教师仍是学习者，host不另造通用归纳器，也不手工写法律桥。

1. **收集真实接口失败。** 记录消费者需要的谓词、实际已取得的引用／角色／期间见证、被保留或丢弃的观察及执行结果。没有证据的缺失输入不能充当正例。
2. **区分缺规则与缺表达。** 若库中没有源根／源蕴含连接，记录为规则获取问题，另计其获取成本。若已有源可解释观察而当前编码／消费者不能表达，才形成接口细化任务。时间算错是计算边界问题，不混计为此机制。
3. **教师提出一个联动补丁。** 从当前源与原TRAIN记录，产生新的构造子或语义区分、参数化抽取方式、带角色和期间约束的消解程序、所需消费者改动。允许成熟CEGAR／程序修补思想；不要求教师之外的独立归纳器。
4. **检查补丁。** 新前提必须来自facts的实际见证；新法律连接必须来自提供的source；不将scope或缺失升级成事实。只在对应已观察源关系上检查，不追加全法源全分支门槛。原正确TRAIN行为及此前有效观察保持可重放。若只是增加`if string == 'pursuant…'`而没有真实新接口表达及消费者使用，不算本候选的学习证据。
5. **固定版本后复用。** 对后续原TRAIN来源执行新抽取程序和消解器，记录新构造子的真实命中、哪些消费者因此获得前提、最终native是否改变。所有获取／修补／读取成本计入。

和普通局部修补的可检验差别是**联合改变表示和解释它的程序**，使一种此前不可表达的真实法律资格变成可复用前提；不是改问法、补几个正则或者仅在同例恢复答案。若普通反思在相同信息下产生相同类型／效果，候选被吸收，应如实降级。

理论起点可以用抽象域细化及带出处的逻辑消解。可证明的只是：在接受的见证和源规则下，角色／期间统一后的消解不会新增无源法律断言。这个相对保证属于正确性依据，不宜包装成新的逻辑求解理论。完整源抽取是否正确仍需实际证据。

## 4. 必须保留的强简单控制

1. **严格stipulation-first。** 原文中的明确法律给定先形式化为带角色／期间／极性的谓词，未给定保持unknown，再用源规则正常统一／演绎。给它相同完整source、同模型、同原TRAIN监督及全部公共源／scope修复。它可以用相同引用索引和表示，独立获取自己的规则。
2. **同信息自由反思修订。** 使用相同旧库／原文／反馈／原始失败观察，允许任意修生产者和消费者；不能人为限定它只能改prompt或单函数。
3. **LTRAG式错误—修补检索。** 同样信息以实际历史修补例方式提供。它隔离“检索到一个相似GIVEN例子”与学习接口新表达力的差别。
4. **无接口细化消融。** 保留事实支持、unknown、源引用、scope等公共正确性，只删除学得的新类型／联动解释更新。不用question-as-fact等坏路径制造消融差距。

共享同一已学源／已形式化前提的比较只隔离执行作用。真正端到端比较要双方独立获取，并计全部形式化／修补成本。普通Prolog能表达这些转换不否定获取贡献；但它若在真实独立获取中已做到相同效果，就不能再称有额外能力。

## 5. 原TRAIN实际适配与局限

只核对当前TRAIN public。SARA24中，约11例包含明确法律GIVEN／引用或具名法律状态。重要例子包括：151(d)exemption到deduction，152(c)(2)关系资格，152(c)(1)到dependent，63(f)给定分量到c3总额，151(b)给定扣除到63(d)类别排除，以及negative151 entitlement。这证明问题实际存在，不代表11例都需要本机制，也不代表11个独立法源。

目前63／151／152最有辨识力的记录已被当前工程流程暴露，不能拿同例恢复称新独立验证。剩余当前原型未修补的典型项包括§1税额题的`married under7703`、§68(f)年份／surviving-spouse叙述及3306(c)(1)的American employer。前两项很可能由正确的固定stipulation／年份处理吸收；后者是直接明示法律状态。不要因它们含引用就预言native提升。

**两项独立作用的关键检查：** 当前152(c)(1)日期例，正确计算同住天数即可否定qualifying-child，关系GIVEN是否被消费不一定改变native答案。该例可支持计算边界机制，却不能同时证明第二项接口贡献。当前152(b)(1)例则涉及缺少根规则，须先公平区分这项获取费用和接口效果。这不是要求所有样本独立激活或零回退，是防止把已知不同原因计到同一贡献。

## 6. 建议的最小下一步

先做**零新增模型调用的接口原型及强控制能力对照**：保留现有raw记录，从实际C2引用观察建立可表达的SourceQualified见证，使用已取得的源定义测试角色／期间／极性消解；同时实现普通strict stipulation-first推理。若该固定控制已在相同已取得信息上完全完成转换，则“引用GIVEN编译”本身降为公共组件，不据它新增真实调用。这个零调用比较只能说明执行／表示作用，不能宣称独立获取成功。

若确实出现固定接口无法表达而教师能从旧TRAIN学出新接口，并在不补新法义的情况下改变真实消费者，再预先固定原TRAIN中不同法源的有限比较。教师不得见其后续案例正文／答案，双方独立获取；原先已暴露的151／152只作开发诊断，原分数保持。下一真实比较需同时包含strong stipulation-first及自由反思，不只有删模块或空库。

若当前有限原TRAIN池没有能区分它和固定控制的来源，应将这项作为第一机制的公共语义底座，集中寻找另一个独立瓶颈。不能用增加ctor数量、几个恢复样例、source桥存在或一个术语替换声称第二创新已形成。**本检查支持一个具体可反证原型，不支持现在宣称两项贡献已经找到或成立。**
