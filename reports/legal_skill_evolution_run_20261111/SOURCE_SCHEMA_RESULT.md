# 源语义接口：真实比较与下一项机制研究

候选在两个预先固定的原TRAIN合同上答对4/4，对照0/4；全部九合同的目标主路径为10/18对6/18。这是源关系结构化值得继续研究的信号。候选同时破坏三个历史合同，未通过准入；目前0项正式技能更新，不能认定第一项贡献或两个创新已成立。下一步研究条款关系的可复用编译技能，保留主体、动作、条件与例外的绑定，而非继续让全局字段读器完成整个法律判断。

本报告保持同一Goal与五库、划分、模型和评分；没有新完整训练、DEV/TEST矩阵或论文。实现难度可以通过原型解决，方法筛选先看额外能力及实质差异。Astra原设计、旧Lift/CoRev、旧A/B/M1/M2及其有效/否定证据全部保留。

## 实际学出了什么

两次教师独立获取使用相同7个原TRAIN合同、原生监督、真实旧读和4个部分冲突证书。候选学出两个字段：操作性披露许可覆盖的接收者类别、通常披露限制与例外关系；同时生成Python原生判断程序。对照自由选择同样对象、完整原文程序或文本技能，实际独立选择一条联合文本技能，直接在完整当前合同上回答两假设。对照不是NoSkill回退。

当前部分冲突证书只证明：已知值兼容、同问题标签不同的两个实际记录，不能由不观察缺失状态的同一只读程序同时正确回答；修读器或取得新谓词是必要路径之一。证书不是真字段金标，不证明真语义不足，不可用其共同补全回填未知。

已有技术包括CEGAR、[SYNGAR](https://arxiv.org/abs/1710.07740)及[BINDER](https://arxiv.org/abs/2210.02875)的神经程序接口。候选的研究假设是用部分冲突指导可错源编码器的更新；“有字段、程序和检查”不算新贡献。两教师均获得证书，当前比较检验结构限制的作用，不是证书本身的独立消融。

## 主路径正确性与具体失败

所有18个成功模型响应正常stop、thinking OFF、reasoning_content为空。候选18项均实际执行了生成程序。不存在当前8192截断；本次瓶颈是源语义获取与推理分工。

- **d50：源读取错误。** 同一明确披露条款允许directors、officers、employees，读器漏employees，添加未获许可依据的legal_advisor，还将employees解释为需新同意，导致两项均错。
- **354与62f：角色及操作性混淆。** 仍把信息描述、定义、非招揽或其他段落中的角色列入许可集合；354甚至返回大部分词汇表。引用了存在的源片段，不等于片段支持字段语义。
- **d936：遗漏明示接收者。** 原文明确包含employees、directors、contractors及条件；字段遗漏employee，员工假设错。
- **e671：跨动作限制迁移。** 合同的“不联系业主/员工/患者”及复制限制，被读成employees披露需同意；代理和专业顾问关系也被扩成多种无局部依据的角色。
- **8af、78ad、e7b：部分目标判断有真实许可依据，但完整返回记录仍混入角色或限制错误。** 例如78ad源条款支持employees/contractors，额外agent无同等依据；e7b许可employees/consultants，同时返回多项不恰当禁止关系。故目标标签答对不等于源记录整体通过语义检查。
- **442：内部共享许可被读出。** 引用条款允许因网络紧急情况内部共享，程序在本次两假设上给出正确结果。这支持该局部路径，不替代其余来源或整体机制验收。

候选程序把“已获许可”当已完成的源判断，其权限投影不能纠正源读器错误。单纯让字段更复杂或增加schema检查不能解决这一点。此次具体源关系词汇与程序确由教师获取，但未形成稳定可复用、通过原准入的技能。

## 工程修复、费用与保全

首次对照9次HTTP400是实现缺陷：安装的vLLM在生成前拒绝显式数组上的uniqueItems。实际标签允许空值的设计没有引发错误。客户端当时吞下WireError并继续批量提交，九次均计入账本；这个处理已修正为系统性WireError直接停止，普通模型类型/语义错误仍分别记录处理。

共享修复从解码schema中移除uniqueItems，保留**原提示中的完整schema及输出后的严格原schema校验**，重复证据ID仍拒绝。用全部18份原请求离线检查：前后xgrammar文法字符串完全一致，修复后通过实际vLLM同一兼容性检查；原生输出类型、范围、唯一性和未知语义均未放宽。126项回归通过。随后只对9次失败对照请求作一次修复后重试，保持原教师产物、策略、来源、采样和评分；未重调候选读取或教师。

## 下一项实质工作

围绕“局部源识别如何学成可复用法律推理技能”推进一个更有能力的学习对象：学习条款到法律关系的编译技能，而非要求执行器直接返回全局已获许可集合。编译产物保留主体、动作、接收者、条件、例外的作用绑定，关系组合由可执行技能承担，针对真实失误更新可复用编译规则。源识别与关系组合分别观察，直接检验增量来自哪里。最终算法与实现仍待形成，不把本段规划当成已经完成的创新。

[法律证明携带神经符号框架](https://www.mdpi.com/2504-2289/10/9/295)已有源链接规则、优先级与证明图；[法律逻辑编码研究](https://arxiv.org/abs/2502.17638)也已有引导式合同编码。新机制要落在编译技能的**学习、更新及跨源复用**上，而非以图或逻辑表示本身命名创新。以这些邻近工作的实际能力和已有Free/AllPorts/Generic强对照确定关键比较。实现风险不成为搁置有力机制的理由；也不将普通包装算作贡献。先建立这一项完整贡献，再围绕独立瓶颈建立第二项。
