# 第二项投入建议：从真实法律修订归纳源条件化的可执行编辑程序

日期：2026-11-13。研究设计备忘录，供同一 active Goal 选定两项贡献。当前推荐仍是待实现、待检验的假设。本轮只读项目记录、源程序和作者资料，没有项目 executor/teacher 请求，没有运行实验，没有修改或发布仓库，没有读新 DEV/TEST、官方 case formalization 或其标签。

## 1. 我最愿意投入什么

**把一次真实的法律技能修订学成可在另一来源上实例化的更新程序：共同归纳“法源关系见证、旧代码匹配、新代码生成”中的变量，再用真实适用与不适用证据学习它的边界。** 学得对象是更新算子 U，不是修订日志、错误摘要、补丁向量或当前题答案。

这项工作接续现有报告中尚未落实的 U 草案，但必须增加一个真实操作：**源与编辑的联合参数绑定**。它不仅问“这个来源是否适用某补丁”，还回答“补丁中新的主体、效果、条件和参数，应当绑定到当前来源的哪一个对象”。同一替换必须同时满足法源关系和代码编辑。对新来源，只匹配旧代码并移植原修订，会保留旧来源的角色或法值；只给 source 特征再让教师自由重写，尚未学到可直接调用的更新。

拟采用成熟的 PBE/反统一、条件学习和反例消歧，而不要求新造通用归纳器。教师可提出和修订候选更新程序，host 执行明确的约束、参数实例化及版本记录。研究贡献应由同信息强比较和真实删除消融建立，不以“底层算法完全全新”或“普通 Python 无法表达”为门槛。

主张若成功，应是：**法律修订不仅产生一个更好的当前程序，还能积累能辨别法律适用差异的更新操作，减少后来同类源语义错误和重复修订，在保持旧能力时改善后续任务表现。** 不主张首次反馈修订、首次局部补丁、首次反例、首次源引用或首次外部技能。

## 2. 为什么这不是旧 CoRev 换名

已经逐段读过现有 `legal_skill_guard/skill_evolution/patterns.py` 与 `revisions.py`。旧实现比“仅历史缓存”强，不能弱化它：它确实保存前后程序、alpha 匹配源码、移植显式读取、检查新法值不能凭空填入，按实际源字段过滤，并支持多位置编辑。

但该实现也有明确边界：

|旧的实际操作|本项拟增加的学习操作|
|---|---|
|`learn` 限定两个已存在的 producer/consumer 技能及完整版本表；legal 模式还要求本地 joint-needed|对真实修订中的一个或多个相关编辑学习算子，不以“两个技能共同必要”定义对象|
|`instantiate_edit` 要求整个旧函数与目标函数同构，名字与已有常量一致替换|学习可匹配子 AST/编辑上下文的模式；目标多一个合法分支不自动失配|
|`instantiate_skill_edit` 保持输入/输出集合；新法值不由见证填入，改动前提需显式 READ|把当前法源见证绑定为编辑程序的显式 typed 参数；声明迁移必须完整，不能靠旧来源常量移植|
|`verified_relation_fields` 是保存后用于匹配的字段条件，未由正负应用证据归纳边界|从实际修复与实际不应改动的来源学习关系守卫；出现冲突时缩小或拆分其适用范围|
|编辑中的参数主要从旧目标代码绑定，源字段负责筛选|源关系变量与代码编辑变量共用替换；例如某员工的雇主、某例外的目标效果必须绑定同一对象|

**上述第三、第五项是必须真正实现和使用的增量。** 若最后仍只是同一 `before/after` 的整函数移植加 source 字段，应判为旧实例。原 A/B、M1/M2、Lift/CoRev、Generic 引导后用为 0、普通切片完全相同、Seed/自由修订吸收收益等结论全部保留。

## 3. 真正最近的三个邻居及更新实现

### 3.1 Refazer/Getafix：核心算法亲属，应采用并正面对照

[Refazer 正式论文](https://www.microsoft.com/en-us/research/wp-content/uploads/2017/04/icse2017-refactoring.pdf)把真实前后代码作为 PBE 输入，学习匹配及修改 AST 的程序。此次进一步读取作者仓库 `gustavoasoares/refazer` 固定 SHA `560bfa4d899cf402b3643e762b0bea9e3bc37626` 的 [Transformation.grammar](https://github.com/gustavoasoares/refazer/blob/560bfa4d899cf402b3643e762b0bea9e3bc37626/Tutor/synthesis/Transformation.grammar)、[Semantics.cs](https://github.com/gustavoasoares/refazer/blob/560bfa4d899cf402b3643e762b0bea9e3bc37626/Tutor/synthesis/Semantics.cs)、[WitnessFunctions.cs](https://github.com/gustavoasoares/refazer/blob/560bfa4d899cf402b3643e762b0bea9e3bc37626/Tutor/synthesis/WitnessFunctions.cs) 和 [RankingScore.cs](https://github.com/gustavoasoares/refazer/blob/560bfa4d899cf402b3643e762b0bea9e3bc37626/Tutor/synthesis/RankingScore.cs)。语法已有 Context/Match、ReferenceNode、Update/Insert/Delete/Move 和补丁组合；witness 从前后树差分反推编辑及匹配上下文；ranking 是结构分数。不能把参数化、子树匹配、复制现有子树或多编辑当成新增能力。

[Getafix 原论文](https://arxiv.org/abs/1902.06111)及[作者技术说明](https://ai.meta.com/blog/getafix-how-facebook-tools-learn-to-fix-bugs-automatically/)已经提出带不变代码上下文的分层反统一与排序。此轮未定位可核验的原作者完整实现，不把同名 GitHub 仓库或第三方复刻称为 Getafix 官方代码。传统算法的源对象是程序树和告警。本项把法源见证与编辑树作为**共同受约束的输入**，让新代码 hole 可由当前源见证绑定，而非只从已有代码树取值，并据法律源的负适用证据学习边界。

这不是“给 Getafix 加 source 字段”即可自动成立的差异。若将 source graph、共享变量以及同样正负约束完整加入通用 PBE 后，所得程序与 U 相同，它就是本项采用的成熟算法，不能再创造一个等价对照后声称超越它。可检验的是该算法相对最强自由更新、普通历史检索，以及**同源信息但源选择和代码参数彼此解耦**的上下文补丁，是否带来真实作用。

### 3.2 EviSkill：编辑证据与跨轮保留已经很完整

[EviSkill §3 和 App.C](https://arxiv.org/html/2610.05030v1)已有证据卡、局部重放、accept/reflect/reject、全局拒收后的编辑再检查和跨轮保留。沿用固定 SHA `896dbcb75b94d09dc5330e1cc6dcadb864244e77`，此次重新读了 [working_branch.py](https://github.com/Zhouyaner/Eviskill/blob/896dbcb75b94d09dc5330e1cc6dcadb864244e77/wmsm/working_branch.py) 的编辑合并、工作库重建、缓存标识，并检查 [evidence_pipeline.py](https://github.com/Zhouyaner/Eviskill/blob/896dbcb75b94d09dc5330e1cc6dcadb864244e77/wmsm/evidence_pipeline.py) 中 `_apply_markdown_edit`、`_make_standalone_contrastive_edit`、跨轮比较与重放入口。实际编辑器按 target/content 执行 append、replace、delete 等；跨轮能纠正原编辑，并非只保存日志。

本项的差异不在更多 replay 或更好 ledger，而是**把多个修订事件编译为一个可直接实例化的编辑转导器**。它将新法源对象代入编辑参数，学习什么情况下该编辑不适用。EviSkill 的证据与回放可以共同作为双方底座。若 U 仍由每次教师自由改完整技能而不调用学得编辑程序，差异没有实现。

### 3.3 SCOPE：反事实定位与原始量/组合修订不再是空白

[SCOPE，2610.31062v1，2026-10-22，§3.2](https://arxiv.org/html/2610.31062v1)已把自然语言政策编译为神经谓词、确定性提取与组合代码；利用已记录谓词输出分析达到 gold 所需的变化，定位谓词或组合错误，并用相近的正确样本支持更新。它与现有法律程序路径足够近，不能再把“重放已知事实、定位某字段、定向修改组合代码”列成 U 的增量。本轮没有核验到对应作者代码，论文机制与代码证据分开记录。

本项要求额外学得**修改程序本身的跨来源变换**。SCOPE 式诊断回答本次程序哪里要改；U 回答从这次修订能得到哪一个后续可调用的变换及其法源参数。跨例直接实例化是核心区分，不能以修本次 GIVEN/日期问题代替。

## 4. 算法：输入 → 选择 → 更新 → 持久化 → 调用

### 学得对象

一个更新算子保存为：

`U = (source_query Q, code_pattern B, rewrite A, shared_typed_holes H, guard g, constraints C, examples E)`。

Q 是带出处的法源关系模式；B 是旧程序的局部 AST 模式和必要不变上下文；A 是新 AST 的生成式。H 记录源变量与代码 hole 的同一性。g 是从适用证据学得的关系条件。E 保存真实修订及明确不适用的来源；未知与未审查不是负例。它不是某一份合同的 R，也不是补丁后代码快照。

**输入。** 已有版本 P，当前原文 S，实际执行/读取轨迹，合法的原 TRAIN 原生标签及源语义反馈。源语义反馈可以由同一技能教师根据原文取得；审查依据、可靠性与开销须记录。不能从 native 答对反推所有中间关系都对。第一项获取器能提供关系见证，但双方必须获得同样的见证或同等获取机会，不能让 U 独享额外法律监督。

**步骤 1，建立真实修订事件。** 教师从 P 修订得到 P'。保存同一真实 seed 的前后库，以及原文支持的目标关系差异、有效旧行为和实际修改位置。两个独立生成的完整程序之间的差分，不算真实修订例。原始材料标签可合法学习；不额外施加“必须无标签”的条件。错误的关系、缺失关系和程序内部异常分别记录。

**步骤 2，抽取联合编辑例。** 从已执行的前后修改取得局部 AST diff，保留绑定所需上下文。教师或通用溯源将法源见证对象与编辑中的角色/参数位置明确对应。例如法源中的 `exception e targets effect r` 与编辑后新建 `r.exceptions += e` 的 r/e 共用 ID。对应不确定时保留多个候选，不以同名或相同字符串直接合并。这里不要求新造法律构造子，现有对象与函数同样可学习。

**步骤 3，联合反统一。** 在同类修订之间，对 `(Q, B, A)` 同时作类型保持的反统一。反统一 memo 的 key 含源角色及对象身份，不能只有词面。重复源对象和重复代码变量必须替成同一 hole；不同效果或不同所属主体不能因为都叫 employees 而合成一个变量。右侧 hole 只允许来自 B 的匹配、Q 的当前见证或确实与来源无关的程序常量。没有绑定的新法值不能生成。单个修订也可以先形成 PBE 候选，后续证据再缩小或扩展，不设置“至少几次修订才准实现”的新门槛。

**步骤 4，学习适用边界和选择操作。** 在当前候选程序空间内，从真实正/负应用约束选最简一致的关系守卫或决策列表。可采用精确 set-cover/MaxSAT，也可由教师生成候选再作同样的约束筛选。正例要求匹配并再现已支持的编辑；负例要求不触发该有害编辑或选择另一已支持分支。若两个源上下文的要求相反，优先按已存在语义关系拆分；不可分则保持两个候选及未决状态，不能用合同 ID、gold 标签或默认 False 拼成伪守卫。历史得分不变本身不是负适用证据，需实际源关系或明确行为约束。

**步骤 5，学习编辑构造子及其先验。** 将通过约束的 U 作为 φ（观察/读取程序）及 G（组合程序）编辑语法中的构造子，而不只是把它产生的某个完整程序排到求解队列前。一个操作可以同时改 φ 的问题/字段/观察粒度及 G 中消费这些观察的代码；对照拥有相同的原始 φ/G 编程语言、全部历史与教师能力。给每个编辑采用两段 MDL 编码：`L(edit | R) = min(原始 diff 编码长度, 模板 ID 编码 + 当前源参数/残差编码长度)`；模板不适用时只有原始编辑路径。这里是成熟程序库学习的编码先验，不是新增第三项贡献。重复真实修订可让正确共性以更短的条件编辑表示；具体法值来自当前源，不能因为数字短就保留旧法值。LAS/一致性检查的硬法律约束不变，在多个一致候选间，以该学得编辑代价参与选择，因此 U 确实改变候选构造与先验。两段编码、模板词典和 tie-break 必须在后续来源前冻结，不能按验证得分改权重。

**步骤 6，更新持久状态。** 持久化 U 的所有支持、反例、已淘汰候选、类型、源—代码对应及版本依赖。新增证据使旧候选不一致时，使其失效并重新选择，不能继续沿用旧 accepted 标记。源关系解释改义后，相关应用证据必须重新审查。多个编辑的组合可以保留，组合不是为了重新证明 CoRev 的两技能共同必要。

**步骤 7，后续实际调用。** 对后续来源，使用当前可获得的源关系 R 和目标程序 P*，联合求解 `Qσ ⊆ R`、`Bσ ⊆ AST(P*)`、`gσ=True`，以同一个 σ 实例化 A。源对象必须换成当前来源对象。只要 source 条件或绑定仍未知，就不强行移植，进入所有系统共有的普通获取/自由修订路径并计费。更新只安装到相应源作用域；若修改共享 compiler，则保留执行时可判断的源条件分支，不能把最近来源的法值写成全局事实。冻结后的 U 调用不读 gold、不需测试时教师。

所有获取、尝试、拒收及回退均计入总成本。U 调用成功要求记录：哪个历史编辑形成了模板，当前 Q/B/g 的实际绑定是什么，生成了哪段代码，哪个目标关系和原生任务路径随之变化。函数入口被调用但目标分支未执行，不能记为机制使用。

### 手算说明

假设真实修订发现：程序把“定义中列举关联方员工”的关系当成了“允许向本方员工披露”。正确修订改变该角色关系的用途，同时保留另一条明确披露许可。一个可复用 U 的输入模式应把“定义所描述主体 a”与“许可动作参与者 b”区分，并把 after 中的新绑定位置与当前源的 a/b 对应。

新合同仍出现 employees，但许可对象变成接收方的子公司人员。U 应使用当前源的公司及所属关系实例化对应参数；不能把原合同的公司或本方员工移植过去。若当前源真的有明确向本方员工披露的许可，否定该许可的编辑不应触发。这个例子解释算法职责，**不是新增训练例、真实运行或效果证据**。若只需“定义≠许可”一个固定语义谓词即可解决，第一项获取或普通自由修订可能已经吸收，不能强归 U。

## 5. 理论起点与能诚实证明的结论

理论起点是 Refazer 的版本空间 PBE、Getafix 的上下文反统一，以及有限空间的反例消歧。两段 MDL 是可执行的归纳偏置；它不证明更短的编辑更符合法律，也不提供必然泛化提升的保证。此次工作的理论价值应围绕**源与程序共享变量的绑定和适用边界**，不是对语言反馈写一个类梯度公式。

可以建立三项有限结论：

1. **绑定一致性与重命名等变性。** 若联合模式的右侧变量均在源模式或旧代码中有界，匹配采用同一类型保持替换，那么生成编辑没有未绑定的法律参数；对源实体与代码局部变量作一致 alpha 重命名，更新结果作相同重命名。证明由替换和 AST 构造的结构归纳给出。这不证明源关系本身正确。
2. **约束集上的保守性。** 在被冻结的候选空间、确定性执行和正确的监督约束下，选择出的 U 再现已支持修订，不违反已明确的负应用/历史语义约束；对于显式守卫为 False 的调用保持原分支。它只保证约束覆盖的行为；动态轨迹切片不是所有未见输入的等价证明。旧错误不应被“非回归”永久冻结。
3. **有限候选消歧终止。** 若本阶段候选集有限，每个真实反例至少淘汰当前一个不一致候选，且不在该证明阶段不断扩语法，则至多淘汰该有限集合后得到一致候选或报告不可满足。教师开放新概念/新编辑后是新阶段，不能继承一个全局终止保证，也不能据此推出泛化准确率。

上述不是“所有法律解释正确”的定理。若论文最终重点在经验更新收益，前两项足以把算法行为说清，无需堆砌泛化界或给教师可靠性作无根据保证。

## 8. 最强同信息控制与真正删除操作

### 同信息强控制

**自由教师持续修订**：相同公共种子、完整源文、全部历史 before/after、合法标签、源语义反馈、工具、回归与可比资源，允许相同 source 模式、guard、helper、分支、多处编辑与完整程序自由改写。普通源解析、类型、事实读取与公共正确性修复共同可用。不能只给对照错误摘要，或禁止它学参数化函数。

**成熟条件补丁控制**：用 Refazer/Getafix 式上下文模板学习，同样看到源关系及明确正/负证据。它可依 source 条件选模板，模板 hole 从代码匹配绑定，并用相同历史执行检查。它检验“新增信息或普通有条件补丁是否足够”。另做源—代码共享变量连接的机制干预，才能解释联合绑定有什么作用。若成熟控制也采用同一 source-bound holes 和同一约束算法，则与 U 合并，明确为采用该成熟算法，不能当预期被击败的另一臂。

EviSkill 的证据卡/编辑重放可作为较强相关方法接口，但不是必须同时复现所有榜单配置后才准实现 U。最终主要方法比较需要真实实现或明确等效适配，不能把 FreeReflect 标签改成 GEPA/EviSkill。

### 必需删除消融

1. **完整 ours − U：真正删除跨例编辑程序的学习和实例化。** 保留第一项获取、相同源见证、全部原始修订历史、自由教师、预算与回归；允许检索完整历史并普通修订。代码上不调用 `generalize_repair`/`instantiate_update`，不读已归纳 U，关闭其编辑编码先验，恢复共有原始编辑代价。不能只换一段 system recipe 另生成完整程序。它回答“把经验变成可执行更新操作是否独立提高后续主指标”。
2. **U 内部的联合绑定删除：** 保留同一个模板候选、同一个 source guard、同一当前源信息及后续检查，将源变量与代码 hole 的共享连接去掉，恢复代码上下文的普通实例化/自由参数补全。记录因此发生的错误目标、错误主体或未绑定参数，不能通过私下按 gold 恢复连接。它解释贡献来源，不替代第 1 项最终消融。
3. **U 内部的边界删除：** 保留同一模板和变量绑定，去掉从负适用证据学得的条件，使用最一般可匹配模板。它检验防止跨源错误推广的作用。不能删除 source 全文或监督制造信息差。

主指标仍为预先固定任务的 native 结果，所有 fallback 留在分母并独列。机制证据至少说明后续多少来源真正调用 U、改变了哪项源关系/目标路径、修复与破坏各多少；源正确性作为解释增益的证据。总 token、教师/执行调用和墙钟成本包含 U 的学习、拒收及检查。只降低成本、只降低 harmful edit 或只提高回放一致性不能替代用户要求的主结果提升与两项独立消融。

不能用一次教师 recipe 的 0/3 对 3/3 判断整个 U 方向；反过来，也不能在控制吸收效果时归因“对照太强”。先固定算法与比较，做实现故障定位；若整个固定阶段没有出现目标操作使用或无独立效果，再决定降为公共组件，不按验证题补模板追分。

## 9. 与获取贡献怎样独立

第一项的目标对象是 `G: 原文 → 概念/规则及其源解释`，研究开放语义如何取得；本项对象是 `U: (旧技能, 当前源见证, 修订历史) → 更新后的技能`，研究真实修订如何成为下次可执行操作。

两者共享原文、语义见证和执行底座，但不能共享独占监督。U 能接在共同 FreeReflect/普通源获取器上；获取贡献关闭时，U 仍可用公共源关系和已有修订继续工作。U 关闭时，获取贡献仍可取得规则，再由强自由教师完成更新。完整系统需保留 `G+U / −G / −U / strong baseline` 的真实比较。不能把 −U 的整体差距完全归因第一项，也不能以新来源规则获取本身证明 U 复用。

如果第一项的“全库增量合成”最后已经从历史归纳相同更新转导器，那么两项重合，应该并为一项，而不是拆两个名称。接口应把“新源规则的合成”和“历史编辑程序的调用”分开，让它们可实际删除。

与拟议 LAS 获取器组合时还需排除一个严格等价情形：**若 U 只给相同有限候选空间、相同目标的完整求解器 warm-start，且最终返回同一唯一最优解，它对该求解结果的精度作用就是 0。** 不能把更快找到同一解解释成第二项准确率贡献。因此 U 应实际作用于可执行 φ 与 G 的联动编辑构造，并通过学得的条件编辑语法改变一致解的先验/编码代价。获取器处理“现表示能否满足、需补什么概念/组合”；U 积累“历史上怎样修改 φ/G 能修复这一类源语义错配”的跨例构造子。即使两者理论上都可用 Python 表达全部程序，有限实际候选与归纳偏置也不同。若实际输出、候选及排序仍逐项相同，应报告 U 在该阶段无作用，不能强造限制让它有用。

删除 U 时同时关闭其编辑构造子的实例化与学得编码先验，恢复共有原始编辑编码；保留完整 M1、同样全部 φ/G 语言、自由教师和全部原始历史检索。不能额外禁止 M1 改读取器、建 helper 或联合修订。仅公共日历/GIVEN/事实合同修复仍不算 U 的训练收益。

## 10. 最小实现路线

1. **保持当前资产。** 保留现有 best FreeReflect、旧 compiler、全部反证及连续账本。本备忘录本身不启动任何旧 runner。先把真实修订事件与现有源观察索引成只读输入，按事件而非法条函数数计数。
2. **实现一个通用编辑表示。** 复用 Python AST、现有沙箱/类型/版本机制，新增 source query、共享 typed holes、局部 code match 与 Update/Insert/Delete/Move；先支持现有函数/记录与分支，开放新编辑由教师提出，不重造封闭法律 DSL。
3. **实现联合归纳、条件编辑语法与约束选择。** 联合反统一 + RHS 有界检查 + 正负适用一致性 + 最简一致守卫/分支 + 两段编辑编码；实际改变 φ/G 候选构造与一致解选择，不能仅作完整求解的 warm-start。保留所有候选和失败。教师可承担提出、概括与修订，host 不被要求独立学出法义。最初可用小规模枚举/精确优化，控制候选规模，避免为工程通用性大改底座。
4. **实现确定性实例化与单独日志。** 同一 σ 绑定源与代码，生成 source-scoped 更新，记录模板来源/实际绑定/修改位置/影响判断。普通自由更新入口不变。必须能用开关真实删除 U 学习与调用。
5. **固定有限 TRAIN 比较后再调用模型。** 同一学习流、来源顺序、实际监督、费用、freeze 点和后续任务先写协议；旧开发材料只承担学习/校准，后续机会从原 TRAIN 按预先规则确定。先证明能真实学习并调用 U，再开展两项机制与强方法的后续完整比较；不先运行完整 128 学习、DEV/TEST 或论文队列。

**最终建议：只投入这一项 U 的具体实现，不另起 utility、credit 或又一轮 prompt 方向。** 它的价值在于把法源差异与程序变化共同学成可执行操作；成熟 PBE 是可采用的核心。当前最重要的工程产物是一次真正的跨例 `instantiate_update`，最重要的科学比较是它相对同信息自由持续修订是否有独立主指标收益。
