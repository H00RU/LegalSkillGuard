2026-11-13。服务当前同一 Goal 的贡献设计，不扩候选列表，不恢复任何关闭队列。已读更新后的两份当前文档、comparison_audit，以及原 TRAIN public 与已暴露研究报告。采用 paper-ideation 的接缝审查、paper-experiments-appendix 的机制消融口径；本次无实验、无模型调用、无 repo 修改，不读 grading/DEV/TEST 或官方案例 formalization。

## 投资判断

**原任务支持把投入集中到“法律规则的组合获取”和“持续更新中的语义归因与历史保持”两个层面。** 这些需求在真实材料与现有失败中都出现，不必换数据、不必强制两个技能共同改写，也不要求教师之外另造归纳器。设计应解释为什么相同原文与反馈下，其学习操作优于普通教师整段编译/自由反思；不是证明普通 Python 无法表达。

现有有限比较没有证明这两个较完整方向已经被强控制解决，也没有证明拟议算法必然有效。它明确淘汰的是若干具体产物和无额外作用的学习操作。应先选定理论上有力且能单独开关的两项机制，再统一实现；不再用一次 recipe 生成的三题成绩持续改名换方向。

## 瓶颈二：原生反馈较稀疏，规则错误与答分变化并不一一对应

**真实任务需求。** 已有程序会出现 native 答对而主体/例外错，或修正真实语义字段却不改变 native 答案。只按一题终局反馈挑编辑，可能学到偶然捷径；只让检查器多提问题，也可能不产生任何新有效更新。

- [SOURCE_CHECK_LEARNING_RESULT §9.2](../../../reports/legal_skill_evolution_run_20261111/SOURCE_CHECK_LEARNING_RESULT.md)：8af真实消费者的诊断中，换保留主体、信息、清空保留条件、补例外连接，四个 native 答案不变；删许可或把 request 改为termination才改变答案。这是既有程序上的因果诊断，不是新增训练例或人为改变评分。
- [NEURAL_BINDING_RESULT](../../../reports/legal_skill_evolution_run_20261111/NEURAL_BINDING_RESULT.md)：4d4e联合控制有一个员工标签正确，但实际引文谈 affiliates 及其员工，不能单独支持 Receiving Party 自身员工。局部编译的正确性/覆盖则另有边界。
- [SCOPE_LEARNING_RESULT](../../../reports/legal_skill_evolution_run_20261111/SCOPE_LEARNING_RESULT.md)：17条字段记录来自一个母合同；4项与既有示例不一致，只有两条“没有保留对象范围”有源矛盾且实际被消费者使用。未消费动作和合法角色别名不能自动标成错误。

**学习机会。** 将现有真实执行轨迹与源依据用于识别“哪项观察/规则编辑值得学习”，并使教师更新能作用于后来来源。可用成熟信用分配、约束学习或反例引导；这里不要求新构造子或host归纳器。机制必须实际改变候选生成/选择/更新状态，不能只是把所有反馈再叙述一遍。

**已有强控制和限制。** 普通自由反思已能学残余修订器；Residual/NoResidual/Seed在固定两母来源同为4/8主路径答对，候选修改0字段，不能重贴这个实例。检查学习虽能排除某些错误，固定复用LearnedChecks与NoChecks源输出完全相同，也未证明学习优势。现有细粒度语义反馈集中于4个合同且多为部分支持集合，并不是128来源完整gold。新机制可利用这些真实反馈，但不能把未列出的合法解释视作负类、把官方形式化变额外监督，或给强对照扣掉同样的源反馈。

**可作为第二项更新贡献的任务基础**：从连续真实反馈学习何时保留、专门化、替换或组合已学规则，避免当前来源修补破坏旧来源，并把有效修订迁移至后续。具体机制由主设计决定，本报告不另起算法方向。完整历史回放、通用联合编辑、历史多编辑检索都是必须保留的强控制；“有回放/有版本/有教师反思”本身已有成熟实现，不能独占。

不要把历史非回归准入包装成新贡献，也不要重新追求“至少两个模块必须一起改”。若已有历史缓存/普通局部专门化已吸收候选更新，则按固定协议记录，不追加新门槛或无限换例。

## 已有最新比较能说明什么

`comparison_audit.json`验证BoundaryRefine与FreeReflect实际输入、种子、完整法源、反馈及配置一致，12条执行可精确重放；差别是system recipe及生成的完整程序。**FreeReflect也实现原始观察/计算细化，不是删除该机制的消融。** 单次教师产物、三条固定来源的0/3和3/3是可信的产物比较，不能据此估计稳定机制效应或否定整个细化方向。

PrimitiveGiven未继承原种子的三条151监督，且取得较新host合同；只能作额外诊断，不是全历史匹配端到端控制。三个新法条头在读案例前根据所供法源新取得，不能自动称作旧技能跨未见法源迁移。函数被调用与目标分支真正执行分开。

## 五库承载边界

- ContractNLI：24不同合同/96视图，最适合源组合获取和持续更新；四个固定假设会遮蔽部分细节，需将机制改善落回真实native判断。多视图不增加母来源。
- SARA：24案例/24视图、8种主法条，适合角色、引用、数值与条件复用；基本GIVEN链、日期计算、局部NAF与公开事件默认属共同底座。最新FreeReflect真实解决三条新法条案例，不应再把相同计算本身视为未被控制覆盖的创新机会。
- MAUD：24母合同/72题级上下文，适合定义及选择性限定识别。各视图上下文不同且含omitted；不支持声称完整案情的多步司法适用，也不能跨视图偷补隐去法条。contract141是好的设计反证材料，不是已认证新收益。
- OpenExempt：32案例/64视图、10种法条包，支持规则识别与逐资产额度应用；不能把EV改为跨资产总额聚合或借完整法条错用EC/EV权限。
- Airline：24例只用一份政策；正确政策缓存很强，适合已学技能的数值复用/成本与边界检查，不能证明跨政策获取或法律修订链。

## 建议交给两项设计的反证问题

获取方案应能具体解释：为何在8af定义—许可—第三方排除、MAUD141选择性条号继承这类原材料上，所学操作比完整原文自由教师更可靠；若只是直接抽角色或同段回填，已有控制足够。更新方案应能解释：在同一反馈下怎样选择可迁移编辑并保留旧规则，而非因教师能生成Python就称贡献；若修改只影响native看不到的字段，不把它计为主任务收益。

**下一步应形成并冻结这两项学习操作的理论依据、可执行状态/更新与真正独立消融，再进行一个连贯原型。** 不新增来源，不按已关闭的两三题反复修补，不以当前小样本结果全盘否定方向，也不为设计预先保证涨分。本报告完成的是任务/比较反证审查，未将任何新候选判为实证成立。
