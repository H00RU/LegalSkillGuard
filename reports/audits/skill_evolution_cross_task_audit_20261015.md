# 法律技能学习跨任务审查：失败断点、既往负结果与下一决策

日期：2026-10-15，Asia/Shanghai。本报告响应用户对“归档”“paper-skills”和现有项目的审查要求。
这是研究与实现审查，不是新的效果实验、已验证修复或论文成稿。
当前源码：`/media/sangfor/vdb/legal-skill-evolve`；hhy 下的 `legal-skill-current` 指向这里。

## 1. 结论先行

法律技能学习并未被证明不可行，但当前项目也没有建立稳定超过强空库的完整学习方法。
多轮咨询、案件匹配、合同推理各有自己的困难；换任务没有自动消除一个共同的缺口：
教师能描述正确原则，不等于冻结学生能把原则转成可靠、完整且可迁移的行为。
这个缺口不是“没有在线学习”：外部库确实随批次更新，只是更新不等于能力改善。

当前最直接的证据是：依据与技能已经交付，律师仍会漏用完整条件链；
新合同措辞变化后，已学字面查询又缺乏覆盖。部分收益主要来自更保守地少选、更多判断未提及，
而非获取更多正确依据。强空库也会出错，但“模型弱、有提升空间”不保证这些错误能靠文字库修复。

不能据此推出文字技能无效、法律任务不适合、必须上参数训练或可执行代码。
项目里这些方向已经有多项负结果，本文明确区分已观察的断点与尚未证明的因果解释。

## 2. 本次实际审查范围与证据等级

- 当前实现：原文与划分、原始成员评分、技能差分编辑、字面查询执行、整库交付、教师输入和响应适配、有限实验驱动及报告。
- 当前真实工件：四批教师/发布/律师轨迹、八来源主比较，以及刚完成的四来源六条件对照。
- 历史：10-05 客户来源边界与案后参考、10-09/10 案件匹配执行修订、10-12/13 合同依据/示例/逐命题及 ExpeL 适配记录。
- 外部：ACE、ExpeL、ReasoningBank、ScienceClaw 的论文或作者固定代码；不以仓库名字代替机制对照。

证据分层：本轮数据能直接检查实际原生请求/回答并独立复算；不少历史结果只能核对恢复的报告，
其原始运行目录已遗失，不能宣称本次又逐一复验了全部历史响应。没有读取官方 DEV/TEST 或保护的24来源结果。
只读审查没有主动发起律师/教师调用；原队列在期间自动完成探针并尝试接续对照，实际费用另计。
没有改动生产源码、冻结配置、技能或评分，没有恢复暂停的 Goal。

## 4. 为什么不同法律任务反复遇到困难

|阶段|有记录支持的问题|不能据此推出什么|
|---|---|---|
|多轮咨询|客户对主体、阶段、属性与来源的匹配不可靠；部分源材料混入尚待调查的事项；早期教师没有未披露参考事实全文，10-05已补齐|不是全部128案没有奖励事实，也不是法律咨询必然无法学习|
|案件匹配及句级依据|分类和依据是不同目标；依据误选多，教师的局部排除修订又会漏掉正确事实；具体正反边界写入运行技能后，8B仍可能违背它|不是“教师拿到标签就一定收敛”，也不是旧任务完全没有任何正收益|
|ContractNLI|原数据/Gold较清晰、无客户路由，但完整多片段依据与条件/极性绑定仍不可靠；查询配方难以迁移，文字指令未可靠修正最终选择|不能继续把当前问题归因于客户、路由或没有原始依据标签|

历史任务的类别数需按代码而非简称判断：旧案件匹配本身也有0/1/2，句级依据则是成员选择。

具体规则已经送达却不执行、未改单条规则也随整体库变化而回退，在旧匹配阶段已有记录。

## 5. 当前链路：学习信号存在，行为转化不可靠

实际顺序是：完整原NDA/17命题 → 旧库本批首答 → 教师见本批及累计原Gold、自己的公开历史 →
原子差分发布 → 同案拟合；下一批用新库。没有训练8B权重。
公共命题范围执行已发布字面查询，最终律师仍判断所有关系和原SPAN集合。
这不是TF-GRPO组内策略训练，也不是重新启用客户模拟。

### 5.1 教师没拿到答案，不再是当前解释

此前已逐项解码八份成功发布的教师请求，累计2/4/6/8来源原文、原Gold和父库相等。
B4各学习器有8份before、6份旧after；逐项组另有81个字面错误登记。
All-failed、已返回却遗漏的依据、错误关系及发布后的失败并没有被整个教师通道删掉。
来源ID有效、JSON合法、输入无损只是必要条件，不是教师语义归纳正确或学生执行有效的保证。

### 5.2 指导与证据送达后仍遗漏，不只是检索问题

TRAIN588/nda-8原Gold为22/23/24。逐项库更新后查询已返回22/23，最终只选24。
22是引导，23是强制披露触发，24是通知义务；不是缺少后两条对应原文。
nda-18原39/40/41也只选39，漏掉人员对象分支。B4两组各7个已返回Gold仍被遗漏，分类均正确。
B3逐项28个FN中27个发生在分类正确题。教师与律师本来就收到完整取证要求，不能再加一句“别漏”就称修好了。

### 5.3 在新来源上，已学词面配方覆盖不足

八后续来源130个Gold成员，逐项库查询上下文仅覆盖22个；标准35、静态85。
逐项末库123个正向短语中52个超过五词，符合已见措辞特异化的风险。
这不是因果证明“换短词就会好”；静态覆盖更高但最终F1仍低于强空库，也反证只追检索覆盖不够。

### 5.4 收益偏向保守选择，未建立完整依据能力

八来源强空库→逐项末库：TP88→67、FP30→12、FN42→63。
P 74.58%→84.81%，R 67.69%→51.54%，F1 70.97%→64.11%；联合84/136持平。
NotMentioned正确43→47，但Entailment62→58、Contradiction10→7，分类总115→112。
不能用精确率或未提及正确数的上涨代替联合提升。

本次进一步对原始八来源分解：

|原Gold依据结构|题数|强空库：分类正确/联合全对/F1|逐项库：分类正确/联合全对/F1|
|---|---:|---|---|
|未提及|53|43 / 43 / 不适用|47 / 47 / 不适用|
|单SPAN|54|46 / 39 / 83.33%|40 / 34 / 78.43%|
|多SPAN|29|26 / 2 / 61.43%|25 / 3 / 50.47%|

多SPAN任务即使分类对，完整依据也很少全对；这是实质执行断点，不是单纯三分类准确率问题。
这是事后观察性分解，不是独立子组显著性或证明了唯一内部机制。

### 5.5 成功示例通道偏容易题，但不要误说成教师只看成功

`actual_success_catalog.json`有138个实际成功组件记录，按来源/命题去重为85个。
在训练8案的136题中，曾在本方法before/after至少完整答对一次的覆盖如下：

|原Gold结构|全部训练题|实际成功库覆盖|
|---|---:|---:|
|未提及|54|45（83.33%）|
|单SPAN|38|30（78.95%）|

34个多SPAN问题没有成功示范。教师仍拿到了这些问题的原Gold与真实失败，偏差发生在“运行时检索成功示例”通道。

只加成功示例不能被默认当成弥补完整证据教学的办法；这也不否定利用失败进行学习。

## 7. 不能再称为全新修复的已试方向

- 只改成逐命题：旧完整新来源比较未胜强共同回答；小四案曾有正信号，但进入真实在线学习后未稳定保持。
- 只换引文/数字/SPAN归属输出：已有负结果；本日逐源输出16答使F1大幅下降。
- 再把正确答案/漏句交给教师：当前已完整交付，逐项原文关联也已实施。
- 单纯加Gold示例：10-12完整84答记录中，空库F1 60.74%、经验规则59.12%、经验规则+Gold片段57.47%、仅Gold片段48.29%。
- 单纯加成功轨迹：10-13完整ExpeL适配与本日探针均未给出稳定联合收益；不能假装尚未尝试。
- 仅把技能改成代码：历史完整全文可执行cycle经验3/16，强直接thinking4/16；程序执行不等于法律推理正确。
- 从一个playbook拆成多个文件：若最终仍把整库同时交同一个模型，只改变存储布局，不会自然改变执行能力。
- 更多B1、更多格式资格、再跑满八批：没有新的可证伪机制时，只增加开发成本。

上述历史数值来自恢复的报告而非本次可直接复算的旧raw。负结果限定于其实现和预算，不是对整个方法家族的普遍否定。
这些记录也说明，不能再把固定“先提取事实，再判断”、完整例子或代码化本身当作从未试过的根因级方案。

## 8. 和相关工作的真正差异，不是技能文件长得像不像

**ExpeL**保留成功经验检索与规则归纳；经验采集包含同任务真实失败/成功对照，不只是教师读最终错题后写原则。
当前自己的教师已看完整失败，但难题的成功示范覆盖不足；只复用计数核心并不复制原方法全部经验分布。
当前适配把语义嵌入换成past-only TF-IDF、以局部组件成功为示范、按批使用原Gold，必须披露，不能冒充canonical复现。
[原论文算法及经验消融](https://arxiv.org/html/2308.10144v3)、[固定作者实现](https://github.com/LeapLabTHU/ExpeL/blob/e41ec9a24823e7b560c561ab191441b56d9bcefc/agent/expel.py)。

**ReasoningBank**的作者代码对成功/失败分别提取记忆，再检索相关过去任务，而非只保存成功示例。
自然语言策略也能有效，不支持“必须代码技能”。但原环境是web/software动作轨迹、原模型与检索条件不同，
不能默认把相同提示搬到8B合同整段联合判断也有效。当前教师已有失败信息，不应再新增一个同功能失败反思层。
[作者失败/成功归纳](https://github.com/google-research/reasoning-bank/blob/ed80611788292ea739f1effd31f16c53823b8a0d/WebArena/induce_memory.py)、
[作者记忆检索](https://github.com/google-research/reasoning-bank/blob/ed80611788292ea739f1effd31f16c53823b8a0d/WebArena/memory_management.py)。

**ACE**把生成、反思、增量策展分开，避免全文反复压缩丢失策略。我们已有原子差分保存，
不能简单借“context collapse”解释全部回退。未改单条技能时整体答案仍可能变化，也不证明仅是文字被覆盖。
其自然语言增量经验在其他任务有收益，但不保证本任务无效编辑也能自然单调变好。
[论文机制](https://arxiv.org/html/2510.04618v3)、本地 `third_party/ace` 与 `learning/ace_native.py` 保留作者来源。

**ScienceClaw**不只是prompt技巧。作者仓库的法律方向本身已包含ContractNLI证据检索；
固定代码中，`ContractModel`拟合证据LR/LightGBM，`LabelModel`直接做E/C，默认排除NM。
整体演化还包括源任务重放、独立验证准入。我们仅复用了轻量词干/词法原语，
没有复现这些监督预测器或整个演化机制，当然不能把它的收益视为“换数据集后我们也应有”的保证。
直接加入预测器会改变收益归属，删除NM或借验证择库也违反当前声明，均未实施。
[固定法律工具代码](https://github.com/beita6969/ScienceClaw/blob/e925f732c7ca435f557e88075bc47a58f1e984f1/packages/scienceclaw/scilib/contracts.py)、
[作者当前框架说明](https://github.com/beita6969/ScienceClaw)。

**SkillWeaver**的procedural memory是实际可调用函数，更新有函数版本/执行记录。
可借鉴“学习产物对应什么真实能力”，不能由其网页API成功推出法律语义也能被简单词法程序解决。
[固定作者KnowledgeBase实现](https://github.com/OSU-NLP-Group/SkillWeaver/blob/f2a63d65d0f6ff46ac30e817cede8797f8f25b97/skillweaver/knowledge_base/knowledge_base.py)。

因此，值得研究的接缝是：外部经验在当前法律任务上，如何真正改变学生的条件绑定和完整证据操作，
而不是再归纳一份学生本来就无法可靠执行的原则。这个研究问题成立，不等于我们已经有了解法或创新结果。

1. 先处理真正阻断既定比较的Schema错误，并统一可见性/报告口径；这些是必要修正，不包装成研究创新。

3. 若可信适配能稳定超过强空库而我们的不能，优先学习其已证实机制并用移除消融定位差异，停止另造同功能中间层。
   若它们同样不能建立收益，就停止当前“文字规则＋字面查找”的同质搜索，明确讨论研究对象/可学习能力是否需要实质变更。
   不能用一个失败适配证明整个方法家族不可行，也不能继续仅增加训练量赌趋势。
4. 任何新结构提案必须同时写出：具体改变什么行为、和本报告第7节已失败方案有何真实区别、有限实验怎样否定它。
   如果说不清，暂不实现。不存在本次已经验证、可以保证大幅提升的根因修复。
5. 方法可用后再冻结正式预算、做多批后续迁移/保持、独立学习重复与未调优的官方测试。不同批难度的裸分不要求数学单调；
   配对净收益、完整依据召回、联合破坏率与末次库迁移必须同时看。不能以单库来源bootstrap代替学习重复。

也不是“再跑满一轮”就能解决；应围绕可重复观察到的完整证据与条件适用失败，形成确实有效的学习干预。
