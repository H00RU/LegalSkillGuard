## 2. M1退化的结论能从原始记录复核吗？

可以。对 `first_epoch_credit_analysis.json` 的157个局部块重新计数：

- 60个非空误差表，全部只有一个补全；56个为 `[[0,0]]`，4个为 `[[0,1]]`。
- 4个稳定块来自3个ProofWriter来源，均标记 `independently_fixed=true`，真实多补全稳定块为0。
- 抽查4块实际内容：保留/删除“Bob is nice.”、“Dave is red.”、“Anne is rough.”、“Anne is round.”对应事实。它们不是法律规则的新增或修订证据。
- 法律来源没有核心稳定信用更新；未知局部语义错误率保留null，没有填成0。

代码 `legal_skill_guard/lsl/local_credit.py` 的 `robust_loss()` 与 `weak_loss('mml')` 支持报告结论：对 `[0,0]` 两者均为0；对 `[0,1]`，稳健loss是 `softplus(s1-s0)`，恰等于二选一MML的 `logsumexp(s0,s1)-s0`。`mixed_candidates.py:build_tables()` 中ProofWriter又用独立参考结构固定规则上下文，因此这批表确实没有检验跨多个未定组合的机制。

`first_epoch_M1_MML_observed_equivalence.json` 报告损失差约2.98e-8、梯度差约5.96e-8，与上述代数关系一致。本次独立复核重算了全部表的类型和稳定来源，并检查对应代码；没有重新加载GPU权重跑梯度探针。

**允许结论：首轮真实数据未区分M1与MML的拟议机制。** 不允许扩大成“M1对所有数据都等价MML”，也不能因两份权重或部分DEV分数不同就认领跨组合方法有效。报告给出的权重相对L2差约0.02255，本身不解释其原因，更不是机制归因。

## 3. M2到底有多少实际训练证据？

| 数据集 | 四格总数 | 非零交互目标 | 有非零目标的来源 |

| NormBench | 1530 | 1104 | 101 |
| ProofWriter | 505 | 35 | 7 |
| Airline | 3 | 0 | 0 |
| SARA | 0 | 0 | 0 |
| ContractNLI | 0 | 0 | 0 |

代码 `native_composition.py:objective()` 确实用 `MSE(q, center(-errors))` 更新组合头；`select()` 使用学习的组合评分选择候选。合同无独立oracle时，`mixed_candidates.py` 保持mask，没有伪造四格gold。

一个容易误读的细节：Airline的3条记录仍有非零joint-head梯度，但目标交互均为0；这是将预测压向零目标的训练，不能计作已获得3条有方向交互知识。NormBench的Boolean激活见证是抽象结构语义，不能说成1104个真实法律案件。

**允许结论：M2的参数训练机制在NormBench及部分ProofWriter上接通，有可核实训练信号。** 仍不能据四格数量证明泛化收益、法律规则进化或与同容量强对照的优势。完整DEV尚未形成。
