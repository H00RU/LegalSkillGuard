# 独立范围复核：法律技能进化与当前 LoRA 路线

日期：2026-11-11。researchwrite revise / major direction review。复核对象是研究适配、证据边界与剩余工作量，不评估投稿录用概率。本轮不恢复暂停任务、不改服务器、不运行模型。

## 1. 明确结论

**应将“冻结执行模型＋教师辅助获取与修订＋外部技能库”重新设为主研究框架；当前 LoRA 分支完整保留，停止将它默认视为主论文的必经路线。** 理由是它更符合用户明确的研究对象和预期交付物，而不是当前实验已经证明冻结模型方法优于微调。

用户要求的是法律方向、技能进化、自组训练集和两个扎实创新点。最新方案明确写成“学习结果主要是模型参数……不强求继续称为技能库进化”；服务器也真实实现了 LoRA 和组合头。这是**设计层改变了研究对象**，不能将责任推给按已发送方案执行的服务器 Codex。用户本次澄清应优先于旧方案里扩大自主权限的表述。

回归外部技能库只是校正范围。教师、反思、增量技能库、技能检索均已有大量工作，不能将这个框架直接算作新的两项贡献；旧 A/B/M1/M2 也不能因改写为技能条目就自动恢复有效性。

这些事实足够指出**目标错位及当前核心机制尚未得到验证**，不足以判定“微调失败”“两项方法永远无效”或“外部技能方案已可靠”。无需先把余下大矩阵跑完，才能承认目标错位。

## 4. 为什么外部技能路线更适配，而不是自动更省钱

| 研究需求 | 当前 LoRA 为主 | 冻结执行模型＋外部技能为主 |
|---|---|---|
| 观察学到了什么 | 主要是参数、候选概率、图头变化 | 能直接检查技能内容、版本和使用记录 |
| 观察随批次进化 | 优化步及loss/DEV变化 | 固定执行模型下技能库版本与能力变化 |
| 教师角色 | 当前没有技能教师回路 | 可提出/修订候选技能，但不能自己认证其正确性 |
| 泛化对象 | 新输入上的参数模型 | 冻结技能在新案件/新法源的适用与复用 |
| 用户原项目资产 | 可复用数据、评分、底层运行器 | 还可复用版本库、检索、建库批次和冻结恢复 |
| 主要新工作 | 参数优化与结构监督工程 | 可复用技能学习与使用机制本身 |

这是一项适配判断，不是性能优劣比较。LoRA同样可能用于技能学习研究；问题在于当前项目将主要学习对象换成了用户并未打算研究的对象。

也不能承诺回归后一定更快。暂停报告中共同初始化约473秒、四个获取模型首epoch各约594–612秒；仅这些训练加起来约48分钟，不等于整个阶段耗时。此前长耗时还涉及请求、候选生成、执行、超时和评价。外部技能演化可能产生更多教师与执行调用，必须单独记录成本，不能以“没有反向传播”推断总成本必低。

## 5. 少量关键近邻：框架成立，但框架不是新贡献

- [Voyager](https://arxiv.org/abs/2305.16291) 已以黑盒LLM、可执行技能库、反馈迭代形成不依赖参数微调的能力积累。可解释的技能内容与外部库演化是有效研究形态，但不是新的架构发明。
- [ExpeL](https://arxiv.org/abs/2308.10144) 已从训练任务经验中提炼自然语言知识，并在推断时检索经验和洞见；“总结经验放进库”本身不足以构成方法贡献。
- [SkillWeaver](https://arxiv.org/abs/2504.07079) 已生成、练习和完善可复用API，且研究强智能体技能对较弱智能体的迁移；“强教师给弱执行器造技能”也不能单独认领新颖性。
- [ACE](https://arxiv.org/abs/2510.04618) 已用生成、反思和整理更新外部playbook，研究增量上下文演化。因此版本化、反思和不改参数都应作为底座，与具体法律机制区分。

本复核不再给一长串新idea。将框架恢复到技能进化后，必须围绕已经观察到的法律失效确定具体更新/使用机制，并逐项与上述方法以及旧项目强对照比较。**两项方法是否足够，当前仍未有证据可宣布通过。**

| 源指针、内容共享、角色视图、类型/格式检查、冻结恢复 | 作为共用工程组件保留 | 可能支持技能内容与接口，但不再单列创新 |
| 旧技能库版本、检索、批次记录与教师运行接口 | 审计后复用 | 可减少回到主线的工程工作，不等于旧方法有效 |

| M1/M2缓存与确定性分析 | 留作失效诊断/受限组件资产 | 非零数学量不等于可迁移技能；不能直接更名成两项技能创新 |
| 余下LoRA epoch、七系统未完成DEV、自动后续队列 | 保持暂停，不因沉没成本自动续跑 | 当前首要问题是范围，不是多跑两轮就能修复 |
| 新模型/种子/数据配比/更大训练矩阵 | 本次不扩展 | 这些不能替代技能方法定义与独立贡献证据 |
| TEST及论文主结论 | 保持封存/不写成功结论 | 没有完整方法实证，仍需守住评价边界 |

若后续需要LoRA作为对照，再按一个明确比较目的恢复相应部分；不预设必须完成整套已排队矩阵。恢复一项结果的必要性由它能回答的研究问题决定，而不是“已经做了多少”。

## 7. 回到主线还需要多少类工作

不是从零开始，但也不是把LoRA输出另存为JSON即可。剩余工作分成四项，顺序有依赖：

1. **研究契约归位**：明确冻结的是有效执行模型（含adapter），跨批次学习对象为外部技能；教师在训练中提出哪些改动，冻结测试时可调用什么。选定原始base还是现有LoRA必须明示；以当前意图，原始base更便于归因。
2. **技能对象与循环接通**：明确技能的可复用内容、来源与适用条件、更新后如何被执行器实际使用；区分具体法规事实与跨案件过程。沿用已审计组件，但不能将单条训练题答案缓存称作技能。
3. **两项机制的实质设计与近邻对照**：必须给出发生更新的规则、解决的不同法律问题、为何已有经验总结/静态检索/普通修补不足。当前没有资格跳过这一步并重许“两个创新已过关”。
4. **有限证据验证**：固定执行模型、候选来源及信息预算，检查技能确实被调用并影响过程；区分静态知识/示例检索、教师临时解题与真正跨来源技能复用。批次学习曲线应是在固定评价规则下比较库快照，不能用优化loss替代。

前两项主要是范围与系统接续，现有资产能减负；第三项仍是核心研究工作；第四项是必要实证。没有可靠依据估计几天即可完成，也不应重新承诺先执行若干天后一定补出两项创新。

## 8. 数据与法律方向不能只靠名称维持

自组训练集可以由公开、独立来源的数据按统一任务接口和去重规则组合，不必每道题都新标。当前五库清单有价值，但ProofWriter是合成逻辑、Airline是政策规则任务，不能把五库直接称为五个法律数据集。

以法律为主线时，应把真实法律任务的失效和贡献放在主证据位置，其他规则任务用于机制的外部检验；不能只在ProofWriter出现核心更新便认领法律技能贡献。SARA多个案例共享有限法条、Airline多个场景共享政策，仍需保留原有来源分组说明，不把32测试案例写成32未见法规。

五库都有普通更新并不说明学到了跨库技能。真正的跨来源复用需要技能来源、检索使用、冻结版本和效果差异对应起来；五库混合后分别测分，首先证明的是联合训练后的各库表现。

## 9. 最终范围判断

**建议回归冻结执行模型、教师辅助和外部技能库的研究主框架，并保留全部可复用数据、检查及历史实验证据。当前LoRA探索暂停归档，不以补完训练作为确认研究目标的前置条件。**

该建议已经足以定主线；它没有把尚未成立的两项创新重新包装成完成。下一份设计应在这个固定框架中解释两个确切法律问题及两个可区分机制，而不是再次把学习对象悄悄切换。

本复核完整性：8/10，表示范围、现状、证据界限和资产处置可供决策；不是方法成功率。缺口是完整DEV尚无结果、本复核未复算全部原始训练日志，且新技能机制尚未设计/验证。保持暂停，不作运行状态改变。
