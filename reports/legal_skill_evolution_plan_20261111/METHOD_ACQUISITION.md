# 方法一研究提案：耦合法源前提提升

日期：2026-11-11。状态：已收敛为一个具体、可实现的外部技能获取机制，供总方案审查；未运行模型，未证明真实增益，不宣称全球无重复。执行模型、教师模型参数均固定，持久化学习对象是技能及其读取/绑定程序。服务器继续暂停。

## 1. 具体问题与已有证据

法律技能从一个来源学到后，容易将**该来源的实体、阈值、例外对象或适用范围**写成通用步骤。类似任务再次出现时，仅判断“这条技能是否适用”有两个不足：放宽触发会把旧法源前提迁入新来源；收紧触发则只能保住原来源，不能获得可迁移能力。

既有失败记录有原文缺失节点、合同许可/否定解释错误、post-return范围外推和角色连接误用。它们不能全部归咎于执行模型能力，但说明外部技能需要能改变“从当前法源读什么、读出的多个值怎样共同进入推理”，而不是固定旧答案或只缩小guard。

本方法的新增操作是 **Lift(C)**：选出技能中一组相互耦合、被固化的法源前提C，将其整体替换成读取当前原文的局部观察端口和绑定程序，保留仍然适用的推理骨架。数值只是其中一种前提；绑定对象、条件极性、阈值覆盖的计算基数也可成为端口。

不是泛称“知识与程序分开”。持久化学习的是：**哪些位置需要重读、哪些前提必须一起重读、局部读取问题如何表述，以及读取结果怎样绑定到原来的全部使用位置。** 该操作能使技能在新来源继续工作，不能由只拒绝误用的筛选器替代。

## 2. 技能对象和最小可执行接口

一项技能 `S=(P,A,B,V)`：

- P：小型推理步骤图或受限helper程序。执行器按步骤读取案件事实/源片段，再由比较、选择、计算等确定性操作处理；不要求8B把整部法律转成完整IR。
- A：法源前提单元。每项有类型、原始来源/出现位置、当前值、所有使用位置。它们是待抽象的旧来源内容，不是独立gold。
- B：已经学到的当前源读取与绑定程序。例如 `ReadLimit(scope_question, source_locator) -> {amount, covered_components}`。
- V：技能版本、训练来源和真实使用记录。V支持复现，但版本控制本身不是创新。

最小操作为：

`READ_LOCAL(question, provided_source_spans, expected_record_schema)`

`BIND(record_field, all_declared_use_sites)`

`COMPARE / SELECT / CALCULATE / RETURN`

READ_LOCAL返回局部字段、逐字段原文支持和未确定状态。执行模型只需回答一个局部法律问题，如“此上限约束基本扣除，还是基本与附加之和？金额是多少？”，不生成全文程序。输出仍可能错误，需要在真实实验中测量，不以schema通过冒充法义正确。

同词面不同位置不自动合并为同一法律前提。已存在同一个程序变量的多处使用必须同步绑定；跨原文出现的同一性只有在可核的引用/原生结构支持下才使用，否则保留独立端口。测试时不传入gold字段，教师不替执行器现场解题。

## 3. 教师、执行模型与独立反馈

教师只做两类提议：从训练轨迹形成初始P/A；对失败提出有限的Lift候选、READ_LOCAL指令及源定位方式。教师不能把自己写的字段值、解释或正确性结论当gold。

执行模型被冻结，用原文和技能执行局部读取及任务；host执行helper和绑定。独立反馈来自数据实际拥有的任务答案、证据跨度、结构字段或已经审计的参考实现；按字段mask，不存在的中间标注不补造。

若某训练实例有完整、独立的相关前提字段，可以把这些字段代入P进行诊断：代入后仍错，说明当前P在该例上仍有过程问题；代入后对且真实读取字段错，才有直接证据支持读取/绑定问题。该结论只覆盖已知的相关字段。若只有最终标签，原因标为未确定，比较有限候选的真实表现，不能让教师宣布“肯定只是前提问题”。

这一区分防止用越来越复杂的端口掩盖原始推理步骤错误，也防止让一个“正确前提oracle”偷偷进入测试。

## 4. 确切更新算法

### 4.1 构造有界耦合块

对当前技能P构建use-def图；为A中的源单元建立耦合超图H，边来自：

1. 同一个已声明语义记录/操作的共同参数，例如 `Ceiling(amount, covered_components)`，`Exception(condition, target)`，`Deadline(trigger, duration, calendar)`；
2. 同一源单元被多个位置使用的绑定一致性；
3. 原生结构明确提供的参数引用/限定关系。

普通最终RETURN共同依赖不能把整张图合成一个块。只枚举同一局部记录边及深度至多2的相邻记录闭包；首版每次最多3个前提单元。超过该范围保留未解决，不称已覆盖任意长法条。

类型记录与use-def是候选生成归纳偏置，不是法律正确性的证明。教师提议的分组仍须由独立反馈检验。H、源定位提示和相同原生反馈均给强对照，不能本法额外取得gold。

### 4.2 提升操作

对块C：

1. 在P中抽出C所对应的源内容；保留其消费位置和相互引用。
2. 教师生成一个局部、联合读取请求Q_C和有限字段schema。它可以跨相邻句查例外目标，但只读提供的当前原文，不回答整道题。
3. 用 `B_C(source,query_context)` 取代旧值；同一块作为一个版本提交，不能先接受金额变化后遗留旧覆盖对象。
4. 原P其余程序保持。持久化的是Q_C、绑定图和提升位置；新来源读出的具体金额/实体留在本次运行记录中，不再次写成全局技能常量。

这也是可见的演化量：一条“按旧来源具体前提执行”的技能，变成一条“按当前来源解析这组前提再执行”的技能。

### 4.3 选择目标

对来源分组的TRAIN回放/训练内保留证据D，候选为 `S_C=Lift(S,C,Q_C)`。以全部原生任务输出计分，调用失败、未解和无效读取保留分母。选择目标为：

统一执行协议采用无权重词典序：先满足触发组改善与固定历史组保留，再最大化同源得分变化，再最少改动、最少新增读取token。此处不另设λ、不做目标函数调参，判据以PLAN.md第6节为准。

在可获得的独立局部字段上另检查字段正确率，不允许用最终答对抵消已知错误法源字段。候选需同时有旧支持来源的回放和不同来源的真实支持；仅增加同一题的解释长度不算泛化。来源分组由训练协议预先固定，不依据TEST调节。

更新时比较不修改、单前提Lift、耦合Lift和同预算自由过程修复。若只有自由过程修复能改善，记录为过程修复，不硬说是耦合提升成功。先在TRAIN提出，只用TRAIN回放及预先划定的训练内保留来源选择。DEV按固定节点只读评测，不用作逐次技能更新、候选选择或提前停止依据；若将来决定用DEV选方案，必须另行明确并报告其反馈用途，不能继续宣称DEV无反馈。TEST冻结到整个技能库冻结后。不能把同一条款改写两次算两个独立来源。

这属于有明确领域操作的程序/技能合成，借鉴CEGIS和程序抽象；不声称重新发明反例循环、泛型参数或最小化目标。

## 5. 确定性例子：两个单独改动都不够

以下是明示语义的构造例，不是现实法规或新增训练集。

来源A规定“基本项最多100，附加项在此之后另加”：

`f_A(B,A)=min(B,100)+A`。

教师从A形成的技能固化了 `amount=100, covered_components=basic`。来源B规定“基本项和附加项的合计最多60”：

`f_B(B,A)=min(B+A,60)`。

在四个固定输入 `(40,30),(70,5),(20,20),(30,50)` 上：

| 技能版本 | 来源A正确数 | 来源B正确数 |
|---|---:|---:|
| 原固定技能 | 4/4 | 1/4 |
| 只提升金额，覆盖对象仍固定basic | 4/4 | 1/4 |
| 只提升覆盖对象，金额仍固定100 | 4/4 | 1/4 |
| 同时提升金额与覆盖对象 | 4/4 | 4/4 |
| 通用联合修复，取得同样两个字段 | 4/4 | 4/4 |
| 预先将全部相关端口参数化 | 4/4 | 4/4 |

因此，单改常量没有自动解决法源迁移；耦合块提供了一个不需要单步得分先升高的更新单位。guard只能拒绝在B用旧技能，无法使同一过程自动读B后正确执行。

同时，通用联合合成和全部参数化也能解此例。**本例证明需要联合变化，不能证明本法优于所有通用修复器。** 新机制的实证目标是：在源读取有成本/误差时，更准确地找出应提升的语义块，以有限提议和读取预算得到可迁移技能，而不是垄断可表达的函数。

`check_premise_lifting.py`及`PREMISE_LIFTING_FINITE_CHECK.json`已运行；读取器是精确fixture，不是Qwen实测。没有模型/API调用。

## 6. 与近邻的具体差异

- **guard induction / Skill-V / family-scoped memory**：主要决定是否使用、何处使用或修订可检验边界。本方法改变技能内部的源获取和绑定，使原本不应沿用旧前提的新来源可以继续复用程序。Skill-V也允许过程修订，因此必须比较同预算自由修订，不能谎称它只能改guard。
- **Binder / 法律模板slots**：已经可将自然语言局部读取嵌入程序。这里只将其作为运行组件；学习对象是哪些源前提需要提升、哪些必须同块提升，以及持续积累的绑定程序。不是预先给所有任务写好相同slots。
- **Refazer / anti-unification / DreamCoder**：一般程序参数抽象和库学习早已有。本法不要求提供修复前后程序对，也不以代码压缩作为独立的泛化证据；使用不同法源上的失败与native局部反馈，搜索耦合前提到source-read的提升操作。最强对照可有同样程序语言及源定位提示。
- **CEGIS / SketchAX**：反例约束、关系测试和逐步修复不新。本法不生成未经核验的法规或新gold；具体贡献限于法源前提的联合提升操作、候选闭包和可迁移绑定对象。若只剩“失败→叫教师改→回放”，差异消失。
- **ACE / ExpeL / SkillWeaver / SkillRL / EvoSkill / KDASO**：经验总结、教师蒸馏、技能创建/修订、强模型技能迁移和法律技能优化均已有。本法须在相同预算下证明所学源绑定改写比自由文本技能修订更有用，而不能只说使用法律或使用教师。

逐篇primary依据与限制见ACQUISITION_PRIOR_ART.md。

## 7. 五库数据的可用通道

主方案使用 **OpenExempt、SARA、ContractNLI、RuleArena、MAUD** 五个独立来源数据集。混合128训练、各库分开32测试及实际来源组划分由统一数据协议锁定；本方法不把同一法源的不同题目称为不同法律来源，也不要求五库补人工完整程序。

- OpenExempt：复用已审计原始规则、输入与任务标签；只对实际可独立核验的字段提供局部反馈，旧技能正确答案不能自动成为法律中间gold。
- SARA：经原例核验的局部税法结构和案例输出可检查数值/角色前提；不能将已发现不完整的任意支付程序当通用oracle。
- ContractNLI：使用原生假设标签与证据；可测在新合同重新读取许可/义务前提。缺少完整合同程序时，字段语义无法独立核验的部分不报局部gold准确率。
- RuleArena：按已审计原生规则与参考输出检查局部阈值和计算对象；同policy不同场景不是新法规。
- MAUD：使用原合同文本与原生问答/分类标注检验当前合同的局部前提获取；不把一个问答标签扩写成完整合同IR或未经标注的条件关系。

NormBench、ProofWriter只作已有资产支持的可选机制诊断，不计入上述五库主实验。某库没有适合提升的源差异，就报告整体迁移/误用评价，不能为得到核心成功随意改法规、制造标签。各库最终能支持多少独立源差异须由实际split清单说明，不预先假定128条就是128个法规来源。

自然不同法源的原始标注可一起作为学习例，不把A案件换上B法规后沿用A标签。受控构造只用于算法单测，单列而不加入正式样本量。

## 8. 强对照与可归因证据

同冻结执行器、同教师、同任务/来源、同源定位提示、同读取API与调用预算：

1. 自由文本外部技能演化（EvoSkill/KDASO式有限修订）；
2. 可验证契约/适用性修订与按family隔离；
3. Binder式全部相关字段参数化，给同样联合读取接口；
4. 通用程序修复/CEGIS，允许联合编辑，给同样候选提示与原生反馈；
5. 本法，以及仅单前提提升的定点消融。

不是要求把每篇整套系统都复刻成新增全量臂；总方案固定最强代表与必要消融，其余同缓存诊断。关键不能只拿无技能和朴素检索作基线。

核心证据包括：提升了哪些端口/为什么成组；新来源中是否真的读取并绑定；旧源保留与新源实际使用收益；新增源读取成本与误差；自由联合修复能否达到相同结果；冻结后未见来源上的任务表现。记录“拒绝使用旧技能”不算新技能复用成功，教师直接给出该题答案也不算。

## 9. 本轮研究承诺

这是一项具体、可实施的**领域技能抽象方法**，不再以安全检查承担创新。它最可能的价值是把法源差异从可复用推理程序中学出来，形成按当前原文重新绑定的技能。

当前证据支持“问题、操作、监督和区别已具体”，不支持“两个创新已过关”或“必优于通用联合修复”。本轮不恢复服务器、不运行模型、不启动LoRA。下一步由总方案将它与第二机制明确拆开，并在用户恢复之后做有限真实验证；若同信息通用方法完全覆盖其价值，如实报告，不追加无尽方向搜索。

## 10. 最强新颖性判断

这项机制的可辩护增量是**把相互依赖的法源前提作为一个学习更新单位，将它们共同改写为当前源读取与全使用点绑定程序**，并用已有原生反馈选择哪些块值得这样抽象。它与Skill-V/检索范围控制的输出不同，也比“提示模型泛化技能”更具体。

但联合程序修复能够表达同一变换，Binder式全部字段参数化也能直接构造同一最终技能。因此，现在不能把“函数表达能力更强”或“首次参数化法律技能”作为贡献。最强研究主张应是：该领域操作和耦合搜索偏置使有限预算的技能演化更有效，而不是独占这种解法。若同信息联合修复/全部参数化在迁移质量与成本上完全覆盖本法，M1的独立方法贡献就不足；这是真正要检验的竞争假说。当前确定性例子已保留这些强对照的成功，未把它们删去来制造创新。
