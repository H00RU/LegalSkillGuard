# 独立方法与可行性复核

日期：2026-11-11。审阅范围：PLAN.md、foundation 五文件、两份方法说明、两份查新记录、DATA_PLAN.md、CONTROLLED_LAYER.md。protocol.json 尚在主代理编写，本记录不声称已审其最终内容。本轮不检索新方向、不调用模型、不改根方案。

## 结论

无 P0 方向性错误。PLAN 已明确冻结参数、教师参与外部技能学习、五库原生指标、真实实现交付和固定强对照；没有把有限程序例或查新当成效果保证。**可作为导师可读研究方案，执行前需修复下列 P1 一致性问题。** 修复不需要重开选题或扩大实验矩阵。

七臂结构足够检验当前两个假设：Free/LiftOnly/CoRevOnly/Full 构成四臂机制对比；Lift+GenericJoint 和 AllPorts+CoRev 分别挑战两项贡献；NoSkill 提供实际任务基线。强对照明确允许联合改动和暂存暂时低分的版本，这是必要且正确的。论文贡献仍是待验证的领域机制，不能从此复核推出已证明两项独立创新。

## P1：执行前必须统一

### P1-1 全端口强对照与三前提上限冲突

位置：PLAN §6 的 AllPorts+CoRev 行及“每块最多3个前提或技能”。

如果一个技能声明超过三个源前提，AllPorts 的“全部相关前提”与统一最多三个前提不能同时成立。把它裁成三个端口会弱化关键强对照；允许它读全部却不给成本或搜索口径说明，也会造成不公平。

建议精确改法：区分**候选搜索维度**和**候选内部的端口数**。M1 至多搜索三个源前提的 Lift 块；AllPorts 直接生成覆盖该技能全部已声明前提的一个候选，允许联合读取，不额外获得原文/gold，所有字段和读取成本完整计入。两者同享每批最多三个候选包与相同回放池；M2 的三项上限始终指已有技能修订数。明确 192 是逻辑配置—来源执行上限，不是每配置内部的物理模型调用上限。

### P1-2 来源内在线更新与批次更新冲突

位置：DATA_PLAN §6 与 PLAN §4/6。

DATA_PLAN 写每来源完成即反馈教师、下一来源使用更新技能；PLAN 写每批先用当前库回答 TRAIN，随后更新，且整批共享三个候选块。两种次序会改变训练经历、B1 含义和更新次数。

建议精确改法：锁定一个时间轴。若选择八批协议：每批16来源都先以同一批首快照回答，再收集该批反馈、执行最多三个候选包、提交下一批快照；回放中对同批来源的再次作答单独记为候选验证，不能覆盖最初在线成绩。数据文件相应去掉“下一来源即更新”的解释。若选择逐来源，则必须在 protocol 给出跨16来源共享同一个三块队列的规则，不能每来源重置三块。

### P1-3 第一阶段的有限工作量尚缺迭代数

位置：PLAN §7 阶段一。

20来源名单和比较类型固定，但只写“每批三块”不能限制重复走同20来源的轮次，也没有明确这20来源分成几批。若执行者不断为得到跨来源复用而重跑，仍可能形成长期无止境实验。

建议精确改法：protocol 明确20来源的一次确定序列、有限批次和各比较执行哪些版本；修复实现错误后仅重做受影响项，继续使用原始队列和账本，不重置候选包数、不新增完整学习轮。无需把每轮工程修复变成新的用户授权门。第一阶段完成后明确停止在128来源完整学习之前。

### P1-4 “真实机制有证据”的阶段门槛需要可观测口径

位置：PLAN §7 阶段一转阶段二。

文本同时允许“没有自然共同修订事件”的验证完成，又要求“真实机制有证据”才建议完整学习，未明确受控父来源上的真实模型执行算哪一类。这容易让服务器把确定性 fixture、人工植入旧错误或仅日志记录当作自然机制证据，也可能因自然低频而无期限搜索。

建议精确改法：分开三列报告：A. 工程和确定性构造；B. 用真实冻结模型在预注册原生/受控任务中产生并执行的技能改变，且下一来源确实使用；C. 自然失败中观察到的同类事件与相对强对照增量。B 可以支撑进入完整学习的实现验证，不能替代 C 的论文结论。若总方案决定必须有自然事件才进阶段二，应明写该固定20来源门槛，并允许验证以未满足结论正常结束，不再扩来源找事件。

### P1-5 CNLI 题目范围遗留冲突

位置：METHOD_EVOLUTION §6。

该方法表仍写同合同17假设，PLAN/DATA_PLAN 已固定 nda-5、nda-7、nda-16、nda-20 四问。须改为四问；否则方法执行者可能扩大调用量或改变聚合分母。原生视图总量280/88/352按四问计算正确。

## P2：建议在本次 protocol 中一并固定

### P2-1 技能粒度的约束落地

PLAN §3 已正确要求共享粒度并禁止拆字段凑方法二。建议增加机器可检查的约束：候选生成前冻结已有 SkillID/输入输出边界；M1 变换作用于一个技能内部的源读取/绑定；M2 核心事件涉及至少两个在该轮候选生成前已经存在的 SkillID，且边界没有为了本次块重划。技能创建/拆并规则应同等适用于所有臂。不要把跨臂恰好不同的后续技能内容强行要求成完全相同，这本来是学习结果。

### P2-2 两方法目标函数与 PLAN 已锁词典序需消歧

METHOD_ACQUISITION §4.3 仍是带 λ 的质量—读取—长度加权式；METHOD_EVOLUTION §4.4 留有加权式/词典序两种选项。PLAN 则已统一“当前组严格改善、历史来源不下降、然后词典序”。建议两方法显式标注：实际运行唯一采用 PLAN/protocol 的统一规则，不再调 λ。否则七臂可能自行选不同接受条件。

### P2-3 192次逻辑重执行的覆盖范围

这个乘法只有在每包最多八个**总回放母来源**（触发组和历史组并集，不是各八个）、至多八种版本配置、最多三个候选包的条件下成立。必须包括用于确认最小性的所有真子集及旧版本。候选迁移验证也应占该共享队列，不能由 §4.6 再暗开一组额外来源/包。真实模型重试、多个视图、多个 READ_LOCAL 物理调用另计，不能把192称总请求上限。

### P2-4 四个主要比较的统计族未明确

PLAN 正确采用母来源簇配对，不把视图作独立样本；单一学习顺序的区间也未冒称覆盖训练随机性。剩余问题是 Full 与四个对照在五库和宏平均上均有结果，主要推断族尚未锁定。

建议最简方式：四个 Full 差值的五库等权宏平均为主要比较，按数据集分层、母来源配对重采样；各库及OE两项区间为描述性。若报告确认性显著性，预定四比较的多重比较处理；若仅报告未调整95%区间，标明不据单个区间跨零与否作整组显著性保证。不能在看完结果后改选最漂亮的数据集为主要终点。

### P2-5 DEV 的阶段角色

PLAN §6 禁止 DEV 逐项调技能，§7 又允许 B8 DEV 决定两方法作用。两者可以相容：前者是训练时无反馈，后者是运行结束的阶段审查。但若依据 DEV 重新设计方法并再测同 DEV，应记录其已成为开发反馈，不能继续称该过程完全没有 DEV 选择。按当前固定B8测试方案，无需更改数据量。

## 不需要追加的工作

无需新增数据集、全量对照臂、底层训练算法或额外随机种子。也不需要现在证明强对照必败。当前唯一必要的修改是让候选额度、训练时间轴、第一阶段边界、监督范围和统计口径在 PLAN/protocol/详细方法中相同。修改后可锁定方案；创新假设由已登记的实测回答。
