# M1：跨组合一致的局部语义归因

2026-11-10。统一修订的一项方法；继续当前 Goal 和已有生成式获取实现，不重开研究方向。下面给出确定的研究实现承诺，不宣称已经获得真实训练增益或证明全球首创。

## 0. 研究依据与主张边界

**问题**：法律规则的获取结果与后续组合会互相补偿。一个模型漏读否定或例外，另一个组合步骤又放错范围，最终答案仍可能正确。混合训练中，一部分数据有结构标注，另一部分只有答案或证据；若把答对的整段程序当成伪 gold，弱监督会把已经从结构数据学到的正确源语义反向改坏。

现有共享文字载荷、多角色视图、源跨度和增量解码保留作为底座。新 M1 的主要贡献改为：**对生成的局部源语义替代，在多个仍可行的组合上下文中进行同位置替换；仅将跨上下文方向稳定的原生监督差异转成局部训练偏好。** 新节点仍由生成器产生，组合上下文只用来判断弱标签能否支持这次获取更新。

依据：服务器固定森林不能生出缺失节点；NormBench 原生 TRAIN 有共享、多角色结构，但其 depends_on_units 为空，故不把依赖闭包当贡献；弱监督语义解析的 spurious program 是已有问题，MML、Gentle MML、跨样本一致性及执行多数过滤都必须正面对照。完整查新见 NEW_PRIOR_ART.md。

允许主张：具体新训练对象、确切更新规则、有限反例中的不同梯度、可实施性。禁止主张：没有 gold 也能恢复任意完整法义、有限候选内的稳健性等于真实语义保证、未更新就是预测正确。

## 1. 与 M2 的边界

- M1 学习原文里**有什么**：规范头、条件/事实内容、局部词义与角色、是否存在某个源记录。生成空间允许新增记录、删除不受支持的记录、纠正内容/类型；不是固定候选森林重排。
- M2 固定这些局部内容后，学习条件属于哪个结论、条件树如何组合。维持当前四格有向交互损失，不将该损失并入 M1 再报两项贡献。
- M1 的 weak loss 可以查询 M2 的候选组合，但对这些组合 stop-gradient；不凭一次结果反向把组合误差算给源节点。M2 继续使用其既有、独立可信的结构/交互训练信号。

学习成果是可迁移参数。共享载荷只减少重复文字，不把不同位置的同词面自动合成同一法律谓词；来源、角色视图和版本仍独立保存。

## 2. 一次样本的数据流

输入 `s` 为训练来源文本，`E_s` 为该数据真实提供的证据/结构字段，`Q_s={(q,y)}` 为该来源已有训练查询及标签。五库混合共256训练单元，冻结后五库分别32测试单元，具体去重分组和分配以统一 manifest 为准；不能把一个案件的多种解析算成独立来源。

1. **生成获取**：沿现有源分段解码器读完整目标原文。每一段至少进行一次获取，产生带源指针的内容载荷与角色视图；可产生新节点。没有查询覆盖某段时也不能自动标成“无规则”。结构标注明确的 non-operative/span-negative 才作为负标签。
2. **形成局部替代**：从当前生成和定点再生成中，抽取同一来源片段的互斥获取选择，例如保留/遗漏一个新例外、条件原词/错误否定、规范类别的两个解释。比较单位是最小可对齐源记录或必须一起更新的记录块；候选差异不能夹带无关节点。新增节点创建新的可选槽，后续轮次可继续增生，不把首轮节点表永久冻结。
3. **建立共同上下文**：对每个获取块 j，保留2–8个类型合法、满足独立原生约束的组合补全 `C_j`。同一对替代 a/b 必须使用相同的上下文。除非独立证据固定了唯一补全或已穷举只有一项，否则至少覆盖当前最优和一个结构不同的有效补全；只剩单个采样补全不计稳健信用。数量不是gold正确率。
4. **交叉执行**：在每个共同上下文 c 中，执行 c[a]、c[b] 对原生训练查询的结果，取得局部偏好区间。无需创造新案件 gold。原生局部结构/证据约束单独检查，未知字段不参与打分。
5. **有支持才更新**：跨上下文一致改善的获取选择获得偏好梯度；相反方向、完全不敏感或缺少共同有效上下文的选择不获得弱标签伪监督。其源监督训练仍正常进行，最终仍输出模型自己的预测，不用“未辨”抵消错误计分。

测试时只读取源文本和测试问题；不读取测试标签、gold structure、gold evidence，不为每道测试题索取 oracle。

## 3. 共同上下文如何构造，避免比较偷换

记 `a∈A_j(s)` 为一个源局部获取选择；`c` 为删除该块具体内容后保留的组合模板。模板按源槽引用，不能按只有某个候选才存在的 gold ID 引用。

- 空记录与新增记录通过动态可选源槽表示；空值意味着不实例化该节点，而不是擅自变成一个真假常数。两种情况必须分别通过编译/类型检查。
- 两个替代必须拥有可比较的外部接口。接口不兼容、发生未声明捕获、无法可靠对齐的候选只参加原生监督，不强行做“局部”比较。
- 共同上下文先按类型和独立的已知原生字段筛选。对弱QA允许保留一个上下文，只要它与此获取块的**至少一个**替代联合后满足可检查约束；不能只留下偏好a时表现好的上下文，再宣称a稳健。
- `C_j` 的筛选使用 native schema/证据、已有候选和固定预算，不能读取隐藏全图决定哪条组合真实。证据集合不等于完整语义图，也不意味着删除证据后标签必翻转。
- `C_j` 有限采样时，所有结论写成“在已检查补全集内”，并保存被检查图及结果。漏掉反向上下文会产生错误信用；不声称有限集合给出全局可识别证明。

这一步是局部反事实**执行**，不是生成反事实法规或凭模型补造答案。

## 4. 精确目标与参数更新

对已提供的查询定义归一化误差：

`ℓ_s(c[a]) = (1/|Q_s|) Σ_(q,y)∈Q_s loss_d(Execute_d(c[a],q),y)`。

`loss_d` 固定使用原生分类0/1错误、Airline整数exact-match的0/1错误，或NormBench归一化分支激活Hamming错误；不能混用NLI标签与事件适用判定。没有可核验执行语义时mask该局部项，不能让生成器自判语义正确。无查询时不计算该项。格式/执行器故障是工程失败，不当成法律语义反例。

对同一源获取替代(a,b)计算：

`d_c(a,b)=ℓ_s(c[b])−ℓ_s(c[a])`；

`d⁻_j(a,b)=min_(c∈C_j)d_c(a,b)`，`d⁺_j(a,b)=max_(c∈C_j)d_c(a,b)`；

`w_j(a,b)=max(0,d⁻_j(a,b)−δ)`。

首版各任务均使用 `δ=0`、pair margin `m=0`；数值任务采用已固定的exact-match错误，不搜索阈值。比较时两个方向都可检查。只有全部已检查上下文同向改善才有正权重。偏好反转或上下文遮蔽为零时，不把期望上的优势当局部语义 gold。

令 `πθ(a|s,j)` 为生成式获取模型对该局部记录/差分动作的归一化概率。局部弱监督为：

`Lrobust = Σ_(j,a,b) stopgrad(w_j(a,b)) · softplus(m + logπθ(b|s,j) − logπθ(a|s,j))`。

`L_M1 = L_native_task + L_native_structure + λe L_native_evidence + λr Lrobust + λp L_prior`。

所有臂保留相同原生答案读出和可用结构/证据监督；M1仅用Lrobust替换潜在程序的弱获取MML，不能同时偷偷保留绕过门控的MML伪语义更新。分类/生成式原生任务loss与用于局部比较的0/1错误表是不同对象。默认 `λe=λr=1, λp=0.1`，先验来自同一256 TRAIN内的一轮原生监督初始化，所有臂一致并记账；随后3轮混合训练。无局部对比不取消原生任务训练。

`θ ← θ − η∇θ L_M1`。

- `L_native_structure` 使用实际有 gold 的源内容/角色/存在性目标；无该字段即 mask，不能由 teacher 伪装独立gold。
- `L_native_evidence` 只监督证据跨度/来源支持等真实标注的字段。证据没有明说模态、变量绑定或例外树时，不监督这些字段。
- `L_prior` 是对原生监督初始化模型在未获弱标签支持的源记录上的蒸馏约束，用于限制共享参数的间接漂移。它不提供新gold，也不证明先验正确。强对照使用同一先验及系数。
- 主机制是局部**偏好**学习，不把优胜候选改写成完整程序伪gold。单条记录的weak loss为零只意味着没有直接奖励；共享参数仍可能间接改变它，须测量语义漂移，不能宣称严格不变。

与MML不同，目标不追求让任何一条能解释训练答案的完整程序独占概率。它明确拒绝将需要依赖某个未定组合才能成立的偏好，作为源获取步骤的训练标签。

## 5. 为什么这不是普通 MML 或 KL 保留比例

有限例子仅说明更新差异，不充当法律模型。源获取选择为a、未定组合为c，执行签名 `y=a XOR c`，观察 `y=1`。先验 `P(a=1)=0.8`、`P(c=1)=0.9`，四个程序均已纳入，因而没有小beam偏差。

两个答对程序是 `(a,c)=(1,0)`，先验质量0.08，以及 `(0,1)`，质量0.18。Exact MML的后验 `P(a=1|y)=0.08/0.26=0.307692`；对a的logit上升梯度为 `0.307692−0.8=−0.492308`。它会把原本更受源先验支持的a=1推向a=0，以补偿更高概率的错误组合。

| 更新规则 | 对a的logit上升方向 |
|---|---:|
| Exact MML / 同答案类质量MML | −0.492308 |
| 仅答案支持约束的KL投影，保留类内比例 | −0.492308 |
| Hard EM | −0.8 |
| 答对程序均匀权重 | −0.3 |
| MML + 同一先验KL（初始化时） | −0.492308 |
| 只在c=0中做局部替换 | +0.2 |
| 只在c=1中做局部替换 | −0.8 |
| M1：共同上下文c=0、1 | 0 |
| 原生独立证据确知c=0后，M1 | +0.2 |

M1看到a的两个偏好方向互相冲突，因而不给局部a伪标签。它没有证明a=1正确；该正确性只能由原文对应监督或额外独立约束提供。

若因素a真的完全不影响输出，完整、因子化、精确MML原本就会给零梯度；**不拿这一情形冒充M1独有优势**。本方法针对的是“两个未知语义决策互相补偿、似然用一处吸收另一处错误”的情况。

已有 PR 是通用约束框架，当然能编码此处新定义的逐源反事实约束；这不等于标准答案支持约束已经给出相同更新。我们贡献的是获取对比的构造、跨补全符号判据及其局部训练使用，不声称发明了 KL 或稳健优化。

`check_m1_local_credit.py` 已运行9组精确分数场景及数值导数检查，结果见 M1_FINITE_CHECK.json。没有训练模型，没有付费调用。

## 6. 一个贯穿法律例子

目标文本：收到书面请求后应删除项目资料；履行约定审计必需的一份归档副本免于此义务；前项例外不适用于含第三方保密信息的资料。正确条件为 `b∧¬(e∧¬r)`，免除义务不等于授予无限保留许可。

如果训练只问 `b=1,e=0,r=0`，完整规则、遗漏e、误读r都可能得到“应删除”。M1仍逐段生成e/r内容；但这一个答案不允许把某个遗漏版作为整程序gold。真正完全未观察到的独立因素上，exact MML也不应产生信用，差异不在这里。

现在某条训练题涉及归档副本。局部获取有“r为例外的触发条件”与“误读r为相反条件”两个替代，而组合仍有正确嵌套和错误附着两个补全。如果前者只有在正确补全中胜出、后者在错误补全中胜出，M1保存这个冲突，不用一次碰巧答对固化错读。NormBench/ProofWriter等的原生局部结构监督先教会正确内容，M2自己的结构目标改善组合；当共同可行补全集中某个获取解释对已标注查询一致更好，M1才利用弱标签强化它。

这个链路允许强结构与弱答案数据共同训练，同时避免弱数据把强监督学到的局部语义拖向补偿解。该例是机制例，不能冒充五库都有相同三层标注。

## 7. 五库怎样提供监督，不要求人工补全五库

| 数据 | 可以直接利用的监督 | 不可擅自补成gold |
|---|---|---|
| NormBench | 原生unit、branch head/effect、condition tag/tree；M1用内容/角色，M2用组合 | 未公开的defeat、参数绑定、词级暴露时刻 |
| SARA | 原生案例输入输出及核验后参考执行；结构/角色span/参数对齐默认mask，仅已独立核实字段可开放 | 把256案例说成256独立法条；把有缺陷的程序当任意输入oracle |
| ContractNLI | 每合同多假设标签、给定证据跨度；按原生规范存在/蕴涵口径执行 | 完整合同程序、删除证据后的反事实标签、所有隐含事实 |
| ProofWriter | 原生事实、规则、proof/answer中实际可读的字段；合成来源属性如实报告 | 将合成模板覆盖说成真实法律迁移 |
| RuleArena | 每任务实际提供的规则文本、问题/答案及可审计的原生计算实现字段 | 未核原生字段的完整程序gold；同policy案例视作全新规则来源 |

ContractNLI尤其不能由生成器给自己产出的图判真。TRAIN证据能监督“这个查询需要哪些原文支持”：漏掉已标注证据的来源指针可被剔除，但仅覆盖证据不证明模态/例外/绑定正确。这样的对比只更新证据/指针字段，不把信用扩散到未标注语义字段。只有已经审计的原生查询执行映射，才可用相应TRAIN标签计算语义对比；其余语义loss继续mask。不把删除证据当成标签必翻转，也不读取其他冻结测试查询标签。

不同库共享 source-fragment proposal 和稳健对比训练；执行器及原生标签类型按adapter区分。单个库无需同时具备全部loss。若某库只有QA且零个可用稳健获取对比，它仍参加原生QA评价和可获得的监督，但必须报告其weak信用覆盖为零，不能写成所有库均展示M1贡献。

源级划分必须避免同源问题跨TRAIN/TEST：同一合同、规则世界、法条家族、policy实例的多个问题都属同组。SARA与RuleArena可用独立法源数量由数据审计决定；混合总量和每库测试数是样本计划，不自动构成五库均有32条未见法规。

## 8. 可启动的训练流程与无梯度问题

先在本次256 TRAIN内使用全部实际可用的原生任务、结构和证据监督做一轮共同初始化，再在同一固定256来源上运行三轮混合学习及共同上下文构造。初始化字段按原生监督mask；其优化量单列记账，来源没有超出256。

第一实现每个获取块保留至多两个主要替代，2–8补全；每轮只更新一批预先选定的源块。执行结果按图/配置/原生查询哈希缓存。同一候选与全部交叉执行提供给各对照，避免本方法暗享更多搜索。

没有可靠正负对比时：继续原生结构/证据监督，不把零梯度样本反复调用教师直到“产生正确标签”；生成器仍正常输出，预测错误照计。首轮就报告每库可执行比例、原生监督字段覆盖、稳健对比率、冲突率、零变化率和新增节点召回。若绝大多数弱样本没有有效对比，结论应是这次数据/模型下弱监督贡献有限，不能用多跑种子或扩大未授权标注来掩盖。

有限实现顺序：保留当前Goal和checkpoint → 加入按字段mask的多库监督适配 → 接通同源候选/动态节点及2–8共同补全 → 实现本节loss和账本 → 确定性检查 → 固定小批真实训练验证 → 按统一Goal的训练与冻结安排继续。不要因此清空已有成果或重开大重构。

## 9. 同信息强对照和必须交付的证据

统一正式矩阵固定为7个训练系统：Base（MML源获取+普通组合）、+M1、+M2、Joint、同候选HardEM、同执行向量ExecutionFilter、SQLoom式同容量组合对照。已有共享文字/增量/AST表示与原生字段适配给所有臂，作为共用底座，不再把它们单列成M1创新。各臂首次候选/对比预算、先验、源证据和实际优化步数相同，均可生成新节点。

同一固定缓存另外做单一completion、平均completion、robust局部信用的离线梯度检查；普通先验KL与类级MML的差异也在此核验，不继续扩展正式训练臂。执行过滤与MML获得相同交叉执行信息，不能给本法更多oracle或只给基线旧森林。正式数量以主方案一致矩阵为准。

研究交付核验三项：代码确实能生成缺失节点；完整记录实际训练是否存在非零、可复算的稳健局部更新及其数量；在本轮固定DEV评价中同时报告任务表现与可获原生语义指标。零覆盖或负结果仍须完成固定矩阵并如实交付，但没有正对比、没有更新、未解决或回退都不能算M1方法成功。需要报告真实解析正确率与新增/遗漏节点变化，而不能只报JSON可解析。五库冻结TEST在后续复核后开启。
