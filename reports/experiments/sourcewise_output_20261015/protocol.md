# 预先固定的依据输出结构诊断

Run ID：`legal_contractnli_sourcewise_output_probe_20261015_run01`。
在本矩阵第一次模型调用前固定；不是完整技能学习或论文主测试。

## 动机和来源

新真实训练案490再次出现指导正确、命中句可见但引用遗漏/混淆；此前历史也有同类现象。
这提示依据集合的执行/表达值得独立干预，不证明只有输出格式造成问题。
原任务将依据定义为每个原SPAN的多标签二元成员关系，包含应完整识别的冗余证据：
[数据作者规范](https://stanfordnlp.github.io/contract-nli/)、
[作者Span NLI BERT说明](https://github.com/stanfordnlp/contract-nli-bert)。
同时核对了历史保留的作者dataset/encoder/loader代码，commit
`058c56fd62d56897bb4fcfbf1be71b17aee3a79c`；其span_labels提供实现依据。
本实验只是受此启发的冻结LLM原生输出参数化，不复现其BERT训练，也不声称借来其完整算法。

## 四条件与信息边界

list_empty、list_skill：现行按命题返回原choice/spans/reason/used_skill_ids。
sourcewise_empty、sourcewise_skill：同一单次共同回答先对每个原SPAN输出支持/反对哪些公共命题的依据归属，
无归属输出空数组；随后输出原17关系、同样的短理由与技能ID。
系统只对模型明确输出的SPAN×命题成员关系转置成原spans列表，绝不新增/删除边、推断法律标签、
因NotMentioned自动清空依据或在非法输出时改用旧答案；原生响应逐字保留，评分视图单独标识。
这一干预同时改变输出参数化及源跨度先行的生成顺序，不称纯单个字段或token效应。

模型、全文、17原命题、原Gold、评分、采样、库及实际原查询相同；同8192输出和32768上下文。
因接口文本和输出长度不同，不能称严格token/算力相等，实际花费必须列出。
不拆成17次调用，不增加规划器/绑定器/模型/裁判，不限制律师引用全文任意原SPAN。
空库采用相同接口，不能把接口给空库的收益归到技能学习。

技能库来自已完成工程核验490的真实一次教师更新，固定全部三条原技能/原查询，不编辑内容，
不是17技能末次M8。该教师已经见过490原文/Gold/实际before；未见本矩阵四个合同及结果。
新教师调用为零不表示技能训练成本为零；来源教师已花16,171输入/1,790输出tokens，单独披露。
