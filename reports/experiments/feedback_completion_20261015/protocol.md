# 失败保全后的显式检查点分叉：B4、六条件后续来源及回执消融

本协议在任何分叉教师调用及后续来源回答之前冻结。全部是开发实验，不是正式测试。

## 为什么另起 Run

原 grounded-feedback run 在 B4 教师输出后、发布前因 coverage_review 的互斥引用检查停止。
实际保留 44 次律师回答、7 次教师调用（其中 B4 输出没有成功发布）。
其 6 项普通差分编辑独立通过原子编辑结构验证，但 81 项强制自报审计含混合引用。
不改写该回答或旧失败状态，也不把这些未发布编辑沿用为新库。

根因修正：新 B4 教师保留完整 source/Gold/真实历史、逐条原文问题寄存器及完整依据目标，
但仅要求正常差分编辑，不再强制生成/校验 coverage_review 自报表。
真实技能结构、作用域、查询参数、容量和原子编辑验证一项不放松。
这修正冗余审计故障面，**不证明技能效果问题已解决**。
前三批曾使用该审计输出，第四批改为简化输出；因此该分叉是明确修订过协议的开发性完成，
不能冒充从头到尾同一预注册学习干预或独立学习重复。

## 真实复用与新调用

- 仅继承旧 Run 的 B1–B3 库/历史/汇总、B2保留回答、B4更新前回答及空库对照，共44个物理回答。
  每个实际公开回答与原生回执按内容/ID核对，文件哈希固定，不生成替身记录。
- 继承已完成的静态1次/source-only4次教师所发布的两个独立有效末次库；旧参考任务整体因父失败停止，
  但这些教师及发布工件本身完整。它们来自相同8案，不含律师轨迹/后续来源，不重新调用教师。
- 新调用：B4两组各1次教师（2次）；B4更新后4次律师，B1保留4次律师；
  六条件×后续8来源48次；固定M4六条件×另外4来源24次。总计 **80次新律师、2次新教师**。
- 全链实际物理律师44+80=124；教师旧学习7+旧参考5+新学习2=14，其中1次未通过发布。
  不把复用计为新调用，不隐去失败教师/token成本，不改账本或伪造旧缺失历史。

## 固定信息边界

沿用8个训练来源490/334、88/331、238/245、262/588及各学习器自身真实历史。
标准组 B4 正常差分教师；逐条组 B4 为上面的简化输出修正，不给任一组对方轨迹。
静态组只见公共任务；source-only组只见同一8来源/Gold，无律师轨迹。
四个自适应/静态库均取末次发布，不按分数选择或回滚。
后续8来源325/206/204/375/388/322/163/104，六条件strong_empty、empty_receipts、
standard、grounded、static、source_only；这些是开发来源而非未暴露的官方测试。
单独的回执/示例消融来源273/416/261/487，六条件strong_empty、empty_receipts、
compact_scope、literal_scope、demonstrations_only、skills_plus_demonstrations；均未进入本次8案学习。
回执实验沿用此前零调用即因父失败终止的固定消融假设，不根据后续答案调整。
两非空条件使用本分叉最后的grounded M4；只将索引回执替换成同执行器的原文回执，
保持无损编码、技能内容/指导、查询/邻居、作用域和输出Schema相同。
原文重复导致输入token增加，明确报告，不称等token的单因素因果检验。

示例条件借鉴[ExpeL作者实现](https://github.com/LeapLabTHU/ExpeL/blob/e41ec9a24823e7b560c561ab191441b56d9bcefc/agent/expel.py)
的真实成功记忆，复用项目中已恢复的 success_memory_corpus 和整来源成功组件检索函数。
只用逐条组自身8训练案的真实before/after回答中经原Gold核对联合完全正确的组件；
不伪造Gold示例、不使用retention/对照/后续来源、不将局部成功冒充整份17题成功。
同源成功组件无损归并，保留逐组件原生provenance，past-only TF-IDF替代作者MPNet，
固定最多3个来源示例、单示例4096 token，当前技能加示例总记忆8192 token，整例超长则按声明跳过，
不截断或合成答案。记忆目录在任何后续来源评分前建立；检索不看当前答案/Gold。
这是 **ExpeL启发的法律示例机制消融，不是完整ExpeL复现或我们新发明的算法**；
原生规则计数/批判学习的完整适配比较仍欠缺，不因借用这两个函数就宣称赢了既有方法。
新接入的两条件在任何本分叉教师/律师调用前固定，较原零调用即终止的四条件版本新增8次律师，0教师。

## 执行与评分

单一独立后台 worker 完成上述阶段，冻结同一个原8B PID/启动标识、原输出任务、
seed45、temperature0.6、top_p0.95、top_k20、max_output8192/context32768。
不引入新模型、fallback、planner、外部法律判定、训练时空库效果准入或答案修复。
所有原始输出不可变保存，无效/截断保留在分母；容量不够则失败，不截断或换案。
B4与保留属于已见训练分析；48个后续回答全部生成后才打开其评分文件并保存主阶段完成记录。
随后不论主阶段分数如何都执行固定消融，24个回答全部完成后才打开其独立评分文件。
两阶段在本协议及源码中一起预先冻结，没有根据主阶段结果调整消融。
若独立消融发生容量/传输错误，保留失败，不把已完成的六条件主阶段冒充未完成或全链成功。
原Gold非中性依据成员P/R/micro-F1、原始分类准确率、联合完全正确与逐案修复/破坏；
至少区分8和4个来源的独立单位、单一学习工件、训练拟合与迁移。
不宣称独立学习稳定、显著优于ACE/ExpeL或完成论文正式实验；后两方法仍待忠实适配比较。
本次修复不通过绕过旧错误实现接续；新教师是公开计费的新协议调用，旧失败永久保留。
官方DEV/TEST及原24个保护来源均不用于调优。
