# 法律技能更新的共享解释区分证据合成

> 本文件保留方法与查新依据。当前实现顺序和推进条件见 [PLAN.md](PLAN.md) revision 6 及[跨库实施](CROSS_DATASET_IMPLEMENTATION.md)。[原协议](protocol.json)对应已完成的冻结轮次。

## 结论

这个方向可以收敛为一个有明确实现对象的**专业化训练证据合成算法**，而不应宣传为新的通用反事实归因理论。简单的“SMT合法变更+区分输入+文本渲染”本身不足：ICSE2010的区分输入合成、受因果约束的counterfactual generation、法律蜕变测试都覆盖了这些组件。可以投入的具体新增对象是：**在事实依赖与允许语义解释共同约束下，自动合成解释作用域一致的源案例组及其允许输出关系，把真实候选技能更新暴露为违反或符合关系，而不拿终答反推事实。**解释不完备可以来自字段语义审核尚未完成，不意味着真实法律文本本身必然含糊。

不把候选程序彼此不同当正确性oracle。正确性证据来自事先审核的源字段/法条语义约束及其允许解释族；模型执行只负责被检查。

## 输入：必须已有，不能让训练过程补猜

1. TRAIN源文本x，带源ID、法规版本、场景/实体绑定、明确字段的证据span；未知字段有独立unknown/completeness标记。
2. 有限语义描述K：基本变量、派生字段方程、关系约束、例外/优先级、作用域、允许的原始字段变更及不可变字段。每条都标明来源是explicit source、official task assumption或人工审核。不能使用当前待修技能的猜测充当K。
3. 解释变量必须拆分为两层：**law_scope**内的法条/定义解释λ，以及每个独立来源母本**root_id**的未知案件事实ηᵣ。λ仅在相同法规版本、定义及适用语境内共享；ηᵣ仅在同一mother的衍生源组内共享未编辑字段。两个独立案件即使用同一法条，也不能共享unknown ownership、payment date等案件事实。某字段被允许干预时，对该衍生案例覆盖该原始值，并重算其派生闭包，不继续强迫它等于母本。未完成语义审核导致的多个允许解释与真正法律解释分歧都可表示，但报告须区分来源。
4. 冻结执行模型；教师提出的有限候选技能更新u，分别修改读者、规则、两者或不修改。候选是持久技能patch，不是从gold直接替换中间消息。
5. 确定性局部渲染器及编辑许可。只能变更明确span/结构化字段，必要派生字段按依赖更新；文本中没有出现的payment date不能擅自写入原样例。

K/Θ不充分的来源仍保留原生训练和评测，但不自动生成该类证据。不能强行规定五库所有样本都适配。

## 算法

### 1. 编译可实现的源变化

将被允许变化的基本事实标为D，计算派生闭包cl(D)，并生成两份或少量多份源记录x₁…xₖ。每个xᵢ带law_scope与root_id。记完整语义赋值ω=({λₛ},{ηᵣ})，先按scope/root分别赋值，再应用该衍生案例的允许干预并重算派生字段。对每个允许ω同时施加：

    well_formedω(xᵢ)
    derived_fieldsω(xᵢ)
    same_law_version_and_entity_binding(x₁,…,xₖ)
    xᵢ[f]=x[f]  for f outside cl(D)
    scopeω(xᵢ) is handled explicitly, never silently assumed true

若某允许解释下案例脱离技能作用域，reference结果必须保留off-scope；不能把它误当规则错误。合法不等于获得权利/资格，约束只规定案例内部一致。

用有限枚举或SMT寻找最低编辑成本的可实现案例组。内部标签变化若无源记录原像，记录UNREALIZABLE，不执行模型干预。

### 2. 合成允许输出关系，而非指定唯一金标

令Referenceω是K中审核语义的局部计算，输出可以是原生答案，也可以是明确的来源忠实投影（例如显式支付金额、是否真的引用某个例外）。Ω是上述两层作用域及干预约束下的完整赋值集合。

    Σ_K(Q) = { (Referenceω(x₁),…,Referenceω(xₖ)) : ω∈Ω }

这是一个允许输出签名集合。关键是一个作用域正确的ω计算整个tuple。**不能**给每个衍生案例重新挑法条解释或未编辑案件事实，那会掩盖错误；同样不能把独立案件的η强制相等，那会产生虚假违规。独立案件的事实赋值可以形成笛卡尔积，共享法条λ仍只选一次。

例如同一未确定阈值只能是3000或3600，金额从3200增加到3500。合法签名为(1,1)或(0,0)，并不知道单例绝对答案；下降签名(1,0)却不属于任何共同解释，因而可以确定拒绝。这个特例就是普通单调蜕变关系；它不单独构成创新，完整算法的目标是自动合成带作用域、依赖、例外和跨组件投影的这种关系。

对于不确定源语义，投影可以返回U。将U强制变成True不属于合法修补，除非提供独立来源依据。输出关系引用训练目标以外的信息时，不得假装它来自终答标签。

### 3. 按能排除的更新选择案例组

对候选u，用可执行的符号局部模型预测候选签名vᵤ(Q)，或复用已有真实执行记录。目标为：

    最大化可排除候选对/更新类的数量，减去源编辑成本与调用成本
    排除证据是 vᵤ(Q) ∉ Σ_K(Q)，不是 vᵤ(Q) ≠ vᵥ(Q)

符号缺陷模型只是选例启发式。实际冻结执行模型的响应必须重新计算vᵤ；与预测不一致时记为缺陷模型失配，不能据预测给真实更新计功。

实现：枚举小规模D与有限案例组；缓存Σ；以位集记录每组能排除哪些候选；在固定成本下使用加权覆盖选择。若规模扩大，可用SMT求候选、再以反例指导检查θ，直到所有允许解释均被覆盖。普通SAT/MaxSAT、覆盖算法均作为现有工具，不声称新求解器。

### 4. 外部技能更新

冻结执行器在选定源组上运行现有技能与候选技能，得到真实签名。教师得到“哪组源变化违反哪条关系、原文span和合法解释范围”，再修改对应读者/法条技能；保存证据约束与patch。候选必须满足已累计关系及源忠实约束，再按原生TRAIN/DEV结果选择。仅通过关系不能宣称全任务正确。

持续保留Ωᵤ={ω：u在全部已观察源组上的真实输出符合该ω}；同一law_scope共享λ，同一root_id共享未编辑η，新独立案件建立新η，不能每组重新挑有利法条解释。Ωᵤ为空时拒绝该候选；非空只是尚未证伪，不是判定该候选为正确理论。

## 不可识别必须显式判定

三种情况不同：

- **能够拒绝错误更新**：存在合法Q，使某候选签名不属于Σ_K(Q)，另一候选仍属于。训练信号成立。
- **仅能看到候选分歧**：候选签名不同，但各自均被某允许θ支持。不能决定哪个正确；需要源级审核消解相关θ，或者保持不更新。
- **终答不可区分**：在所有允许源干预上，两个组件修补的组合函数相同。比如读者取反、消费者再取反，与两者均恒等，在所有布尔输入上终答相同。追加终答案例永远不能定位该修哪层；必须查看中间来源忠实投影。没有这一额外证据就合并为一个行为等价类。

有限域可通过穷举给出不可识别证书；SMT只在完整编码下UNSAT才意味着不存在区分组。超时/不支持不是不可识别证明。

## 已执行的确定性原型

命令：`python prototypes/legal_distinguishing_pairs.py`。

1. 派生净额=工资+奖金；只改变奖金时自动更新净额，保持年龄/工资。年龄65的法规边界有两种解释，不能稳健归因；年龄66可构造区分漏读奖金与错误规则的源对。
2. 两个组件修改但终答函数完全相同：穷举确认终答不可识别。
3. 使用现有真实TRAIN SARA来源 `bb6b0bc1…` 的原始句子，将唯一`$3200` span替换成`$3500`。输出保留原句、改句、span、输入哈希；其他字节完全不变，没有增加支付日期。用合成不确定阈值演示共享解释可以排除下降签名，而逐case选择解释会错误接受。**阈值是机制示例，不声称是该SARA题的真实税法，也没有使用其native答案或调用模型。**
4. 作用域检查：两个独立案件的未知ownership允许(T,F)；同一mother仅修改无关金额的两个衍生案例不能由(T,F)解释。若允许显式修改ownership，则可以与母本不同，并必须更新依赖的permission。原型分别验证了跨案错误共享和同案错误独立造成的虚假拒绝/接受。

原型证实源编辑、派生闭包、共享解释、不可识别这四个确定性部分可实现；它没有证明真实模型会遵循技能，也没有原生指标提升。

## 最邻近工作与不可回避的控制

- [Jha et al., ICSE2010](https://www.microsoft.com/en-us/research/publication/oracle-guided-component-based-program-synthesis/)：SMT合成区分候选程序的输入已存在。本方案不占有“区分输入”，新增对象是源依赖、法规解释共享、未知源属性与技能更新信用之间的具体编译。
- [Mahajan et al.](https://arxiv.org/abs/1912.03277)、[Karimi et al., NeurIPS2020](https://proceedings.neurips.cc/paper_files/paper/2020/hash/02a3c7fb3f489288ae6942498498db20-Abstract.html)：因果可实现性和不完全结构知识已有。本方案是训练证据，不是建议现实当事人采取行动；这种目标差异本身不够，需证实共享解释关系与更新选择产生额外有效信号。
- [Synedrion](https://arxiv.org/html/2509.13471v1)：法律高阶蜕变关系、LLM生成测试和按反例改税法程序已经做过。其关系类别以比例、跳变、饱和等为主，由agent生成。本方案应比较相同源预算下的这些关系、MC/DC及普通mutation，证明允许解释族的自动关系合成能抓到它们覆盖不到的错误，而不是仅给出更多测试。
- [SCOPE](https://arxiv.org/html/2610.31062v1)、[DAAF](https://arxiv.org/html/2609.32498v1)：给它们同一案例组、候选patch和语义关系，排除额外监督不公平。若差异都消失，则贡献是证据合成器，不能重复包装为独立归因方法。

## 建议论文定位

推荐精确定位为“针对具有未消解法律解释的外部技能更新，合成来源可实现、解释一致的训练证据”，允许使用成熟求解组件。工作量在统一语义约束表示、自动源组/关系合成、等价与不可识别处理、真实弱模型技能进化适配，而不是新造一个通用information-gain公式。和M1的独立性：M1优化技能可执行表示，M2优化哪些有来源依据的训练证据能淘汰错误更新；M2必须能作用于固定的原始表示，M1也必须能在普通训练下单独工作。
