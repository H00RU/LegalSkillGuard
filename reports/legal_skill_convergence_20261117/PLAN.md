# 法律技能进化：两项方法统一执行方案

**2026-11-18 修订，revision 2。** 两项方法保持不变：M1「法律消费者约束的关系接口学习」、M2「共享语义约束的对照监督合成」。目标是让冻结弱模型更可靠地执行法律技能，并用可信关系监督改进外部技能更新，最终提高原生任务指标。教师与外部技能库保留，不做参数更新。

本文件、[跨库实施与验证](CROSS_DATASET_IMPLEMENTATION.md)、[数据选择](DATA_SELECTION.md)、[protocol.json](protocol.json)和[服务器 Goal](SERVER_GOAL.md)构成当前执行合同，替代本包11月17日的数据安排和推进条件。算法细节、查新和历史证据仍见 METHOD_1.md、METHOD_2.md、RELATED_WORK.md、CURRENT_CODE_AUDIT.md。旧结果、账本和暴露记录保留，不恢复旧候选队列。

## 1. 已确定的研究对象

当前问题不是“模型不会输出 JSON”，而是法律规则需要的事实关系与弱模型实际能读出的表示不匹配，以及中间语义不完整时容易把错误经验写进技能库。

- **M1 改变执行接口。** 从法律消费者的依赖生成关系、对象分组和作用域读法，同时合成配套解码器，再以冻结读者的实际表现学习可复用接口。
- **M2 改变更新监督。** 从独立审核的局部语义与合法源变化生成共享解释下的允许输出关系，约束教师的技能更新，不为每个变体猜一个完整金标。

现有确定性原型证明部分合成操作可运行；新两方法的真实模型收益尚未获得。当前代码已有有限域接口合成骨架，但生产主要覆盖 Airline 单变量桶与 OE 部分求值。复用这些资产，接通新增机制；不重写已有基础设施。

## 2. 两项方法必须实现的增量

### M1：关系接口与解码器共同学习

输入为审核后的消费者族 F、上下文 c、来源约束 W、冻结读者 R。外部技能项保存 `(H, reader_prompt, D, scope, proof_receipt, provenance)`。

1. 扩展现有 `residual.propose`：从比较、聚合、连接键、条款作用域生成联合关系与分组候选；同一通用合成器处理各库，适配层提供任务语义。
2. 合成 H 与 D，验证声明域内 `D(H(w),c)=F(w,c)`；发现相同编码却对应不同消费者结果时拒绝候选。未知世界保持耦合，不补造事实。保证针对已声明消费者，不假装证明整篇法律文本正确。
3. 对合法候选做同源、同冻结模型读取，以来源忠实性、原生任务表现和实际成本选取。整题最终答案不得作为读取字段；固定格式选择、加ID、单字段分桶保留为基线。
4. 将候选生成、选择、版本更新及后续来源复用接进 `InterfaceActor → BatchTrainer → skill_library`；消费者变化时重验接口。无需每批强行创造新技能。

**非 Airline 的实现重点固定为主体/资产/诉求绑定，以及合同条款/例外作用域。** 不能只接五个输入适配器就称跨库方法成立。具体路径、实质变换回执和强对照见跨库实施文件。

### M2：共享语义下的关系监督合成

1. 从原文、官方任务条件及独立审核得到局部约束 K；待更新技能不能为自身正确性背书。
2. 在有限编辑语法内生成可在原文实现的源变化，保持未变内容并更新派生依赖。法规变量仅在同一法域/版本共享，案件未知量仅在同一母来源的衍生组内共享。
3. 合成 `S_K(Q)={(F_ω(x1),...,F_ω(xk)): ω满足K}`，同一 ω 解释整组。逐例独立补全、单解释标签作为控制；全未知、恒定输出或仅通过关系不算正确学习。
4. 用真实模型输出违反允许关系的记录指导教师修订外部技能；原生TRAIN标签锚定正向学习。候选分歧可以选例，不能充当真值。关系无法区分的更新保留为等价，不无休止加调用。

至少实现数量/聚合与主体或条款作用域两类关系。加性抵消原型是接线起点，不是全部贡献。自然部分审核与人为遮蔽中间标注的诊断分开报告。

## 4. 实验如何闭合

**共同底座。** 冻结 Qwen3-8B，thinking关闭；教师沿用服务器当前有效配置。修复默认条件遗漏、截断、schema/执行器不一致并同步所有臂。复用现有程序、原始响应、177份部分参考和账本，但先核对版本、语义及来源暴露。单题教师生成、测试oracle、训练金结构均不能偷偷成为主方法独占输入。

**固定小试。** 从锁定128 TRAIN里按结构预选每库4例，共20例；不按结果换题。用来检查机制接通、真实读取、非 Airline 变换、监督来源、恢复及公平控制。小试不要求显著提升，不作为每库涨分闸门。正式五臂恢复同一小试前公共库；公共代码修复同步，方法特有的小试技能不预装任何臂，各臂在128来源中重新学习，曝光统一登记。复用缓存必须满足同模型、同提示/接口/输入/库状态。

**正式矩阵。** 五个完整训练臂：普通教师技能学习底座、仅M1、仅M2、M1+M2、匹配的外部强对照。机制控制只在固定20例及其合法衍生组上执行，不自动扩成十余个完整训练臂。外部强对照按小试中的同信息、同预算比较一次锁定；披露该选择过程，不在TEST后换对手。静态初始库/空库仅作B0与最终推理参照，不额外训练。

清单同时锁定各库的假设、问题/类别、视图集合和聚合方式，明确全任务或固定子任务；不强制扩大MAUD到全部类别。各臂使用同一128母来源、同顺序、同任务信息和可比教师预算，均从共同底座开始；旧方案“128中只有96参与配对学习”的角色分配不沿用。所有128进入训练流程，不适用某机制的来源走共同底座并保留在分母中。保存B0/B1/B2/B4/B8五个快照及五库DEV学习曲线；默认以B8作为正式冻结版本，不用每库挑不同批次制造组合优势。接口的局部选择仅在TRAIN内，DEV仅按固定协议评估和选正式配置，不作教师逐题纠错材料。

**评价。** 分库报告原生指标、来源级完整正确、机制适用率、读取/绑定错误、有效与有害更新、实际调用/token/耗时/费用。OE保留官方EC/EV指标，Airline金额精确匹配，ContractNLI原生三类及证据指标，MAUD原生分类指标，Diversity按官方balanced accuracy并附accuracy；不把不同单位直接平均成“总准确率”。原生评估单元与母来源聚类置信区间同时说明。

跨库学习另用B8固定DEV上的“屏蔽其他库来源技能”推理对照，记录技能来源和调用；不新增训练轮次。不把混合训练后的五个分数直接称作跨库迁移，也不把案件留出称作法规留出。

## 5. 连续推进与完成标准

实现与数据锁定 → 固定20例真实比较 → 一次128来源完整训练及DEV矩阵 → 冻结后五库分别TEST → 贡献归因与论文初稿。服务器自行核验并接续，不要求用户在每阶段转交复核。

**单库低分、无提升、回退或小试不显著不触发stalled/blocked。** 开发阶段主动根据真实失败改进关系语法、证据定位、未知处理、候选选择和更新准则，保持两项核心机制；优先解决会改变指标的输入、绑定、候选生成和更新问题；零散失败记录后继续其余来源。明确实现错误可自主定点修复；如果改变了比较条件，所有受影响臂使用同一修复重算并记账，不能只重算主方法的错题。完整训练后按预定矩阵评价，不为达到预设正结果加数据、种子、模型或新方向。

能执行、能独立评分且证据真实时继续整体研究；若一条机制仍无实质触发，应定位并实现缺失模块，不能把只改格式当作完成。仅在关键输入/评分持续无效、核心代码无法执行、真实资源不可用或有具体证据推翻机制时暂停受影响路径；保留其余可进行的工作，不因一次类型错结束目标。

Goal完成要求：两方法真实生产实现；固定完整训练与测试；非 Airline机制证据及独立消融；强对照和成本；可复现代码/配置/数据哈希；论文方法、实验、结果表和局限初稿；更新交接文件并推送。报告分别给出“交付是否完成”和“两项贡献得到怎样的支持”。不能只交诊断或小试即完成，也不能把效果不理想改写成已证明创新。

常规实现、必要局部重构和定点修复自主推进；不新增每轮修复授权门槛，调用连续记账，沿用真实资源授权。旧96/100等历史试运行限制不自动套用于本目标，也不因此新增付费授权。
