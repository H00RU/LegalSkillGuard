# 跨库实施与验证合同

2026-11-18。与PLAN.md和protocol.json同效力；本文件把已有原则落实到代码和证据，不增加研究方向。

## 1. 一个合成器，五个任务适配器

复用 `FiniteModule / compile_pair / witness / residual.propose`。适配器提供局部语义域、消费者依赖、证据定位、允许源编辑及原生评分映射；候选生成、合法性检查、真实读者选择、更新与冻结由共用实现完成。不得为每库手写一个最佳最终接口再把五个接口选择称作学习。

| 库 | M1实际增量 | M2实际增量 | 原生任务边界 |
|---|---|---|---|
| OE | 绑定owner—asset—use/share，按合法消费者保留共同额度依赖；由依赖生成联合资格关系 | 固定所有权/制度下改变单项资产与金额，计算共享上限和资格的允许关系 | EC/EV与原生默认条件不变；不能把unknown改true来涨分 |
| ContractNLI | 从定义、主体、义务/动作、例外的局部依赖生成关联读取和解码；保留NotMentioned与明确否定差别 | 对独立审核的定义/局部例外作可实现变化，联合约束受影响与不受影响的假设 | 17项假设按原生规则评分；不是把Entailment包装成一个“事实”字段 |
| MAUD | 区分普通经营义务、负面义务、同意要求和各自例外；联合生成作用域关系 | 对选定条款条件变化，保留其他条款及同一交易假设，约束分类向量 | 保留完整相关上下文；不得把不全片段错误算作接口贡献 |
| Airline | 超出已有按袋记录和单重量桶，学习尺寸/重量联合关系、必要分组及解码 | 从合法数值变化生成费用关系与共享不变部分；包括非线性分支 | 原生收费程序只作独立核验；不能作为只有主方法可用的预测oracle |
| Diversity | 原被告角色、州籍相等关系、claim→(plaintiff,defendant)归属及同对诉求聚合；生成跨角色比较矩阵/有身份的聚合读法 | 在角色/州籍或单项诉求变化下合成管辖条件关系，未知共享范围与同对聚合绑定 | answer、parties_are_diverse、aic_is_met金标仅供评分/训练监督；不得直接喂给读者 |

优先完成非 Airline 两条生产路径：**OE或Diversity的主体/诉求绑定，以及ContractNLI或MAUD的条款作用域**。两条都必须有可复算的真实TRAIN实例；它们是实现覆盖要求，不是规定两个库小试必须涨多少分。其他库也运行共同接口和原生评分，不能被静默跳过。

合同消费者不等于把整份合同预先完美形式化：从已审核且可执行的局部技能和固定假设族起步，保护所声明输出，未覆盖部分明确退回共同底座。任务的证据span可以用于TRAIN审核；DEV/TEST金证据不提供给推理。编译保持F与F本身法律正确是两项检查，不能互相代替。

## 2. 什么算M1实质变化

每条代表性生产链保存：原文/来源hash → 原消费者依赖 → 自动生成的候选H → 合法性回执/碰撞见证 → 配套D → 同冻结模型的真实读取 → 原生结果 → 保存的技能版本 → 后续不同母来源上的调用。

所需字段：`source_id, dataset, semantic_change_kind, consumer_dependencies, original_schema_hash, candidate_schema_hash, candidate_origin, decoder_hash, scope, proof_receipt, source_fidelity_status, actual_reader_response, native_score, skill_id, learned_from_sources, reused_on_sources`。非法候选另存`counterexample`。无见证可得时记none，不伪造。

JSON重命名、字段重排、加ID/引文、截断修复、删提示废话、固定三布局选择、已实现单字段桶都单列为基线。实质变换应改变**由消费者约束决定的关系表示、对象分组、作用域或保留的语义区别**，并有相应解码/消费者适配；不要求H必须不可逆，也不要求每次D字节都不同。已有正确按实体接口是必要强对照，不故意让对照混淆实体。

对弱模型，字段更少不必更容易。记录关系误读、角色/范围绑定错误、unknown、完整原生正确；按库同时给适用子集和所有来源分母。没有收益时区分“方法没生成候选”“候选合法但读者不改善”“局部改善被其他错误抵消”，据证据修具体模块，不能只归因模型太弱。

## 3. 两项独立归因与控制范围

完整训练固定五臂见PLAN。以下控制限定在固定20例小试及合法衍生组，使用同一原文、公共修复、冻结模型、审核语义和相当调用预算；不自动扩成额外完整训练。

**M1控制：** 正确固定关系接口；仅schema/格式优化（PARSE式）；静态部分求值/单字段桶；同候选池的静态最短接口；完整M1。必要的同候选池普通搜索复用同一批读者响应作离线选择诊断，不额外重复请求。比较自动关系生成与格式优化的差别、真实读者选择与静态选择的差别。通用求解器不是创新，现有方法拿到本方法生成的候选后选中同一结果，并不单独否定关系生成贡献。

**M2控制：** 普通原生标签更新；SCOPE/SkillEvoReg式候选驱动验证；Synedrion式高阶关系；同K和源编辑池下的单解释、逐例独立补全与共享解释合成。控制必须有相同语义信息，不能靠主方法多看标注获胜。外部实现、复现适配与自建近邻控制分别标记，不能把简化控制说成复现原论文成绩。

M2每组保存`K来源及审核版本、共享变量作用域、原文编辑与派生闭包、允许签名、真实模型签名、更新前后技能、违反位置、原生标签表现`。至少保留一类“逐例均允许、整组却不存在同一共享解释”的非平凡关系；它可先由确定性候选验证，但实际学习效果必须由真实模型和真实更新证明。不得以拒绝全部更新、关系为空/全域或全部unknown刷通过率。

外部强对照在小试后按协议一次锁定：在相同公共底座上对两项方法最近的可执行比较中选同口径小试总体表现最强者，平局取成本低者，再平局固定名称排序；选择用全部20例而非只挑方法适用题，以预先锁定的各库0—1原生效用的等权平均排序；该数值只用于选对照，不作为混合总准确率。该臂从同一初始化重新训练。披露适配范围。全量五臂和两组机制控制共同支撑差异性，不把一个较弱整系统对照当作全部查新证明。

## 4. 数据、学习曲线与迁移

小试20是128 TRAIN的子集，预先按结构选择。原有已读材料、教师范例、缓存、历史技能的来源集合均登记；使用同一共同初始化，所有臂享有相同允许历史信息。正式各臂恢复同一小试前公共库，任何臂都不预装方法特有的小试技能；只同步公共代码修复和相同允许历史材料；真正完全相同的请求才能复用缓存。提示中的额外few-shot来源也计曝光，不能通过外部基线提示引入额外母来源。

主矩阵中所有128来源进入各自批次。训练前缀的教师更新仅看当时已进入的TRAIN，不读取未来批次标签；共同初始化中的历史信息另列，不能把本项目曲线描述为模型从未见过这些来源的严格在线学习。B0/B1/B2/B4/B8固定快照均评估同一80 DEV；正式默认B8冻结。全量B8 TEST各库32，未适用/失败来源保留在分母。

在B8的既定DEV增加“去除仅由其他库学得的技能”推理消融，不另训模型。共同初始技能保留；多库共同产生的技能记录mixed，不假装已精确拆分贡献。保持相同检索规则/预算，记录实际长度与调用，不靠填充无效文本追求字节一致。按库记录跨库技能命中和结果变化；没有迁移就如实报告，不能把共享代码说成跨库学习。

## 5. 不以小试涨分决定能否继续

小试负责生产可运行、语义契约与控制可比，正式训练负责回答有效性。单库低分/负增益、零命中或小试不显著都是结果，不是自动停工条件。将实际故障与算法局限分开后继续完整矩阵；缺失的非 Airline核心模块必须自主实现，不得由fallback伪装完成。

非 Airline实质收益的最终证据应含：合法关系接口实际改变了读者行为，真实读取/绑定改善，分库全量原生效果及与强对照的差值。这是最终贡献验收，不是小试逐库涨分闸门。按PLAN先进行最多3轮成体系的TRAIN/DEV优化，之后冻结验证。若到达边界仍不支持两项贡献，保存负结果并停止扩展，研究Goal保持未达成；不能把“评价交付齐全”混同“研究目标达成”，也不能无限换题直到正分。
