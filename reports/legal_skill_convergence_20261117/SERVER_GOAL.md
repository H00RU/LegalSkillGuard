# 服务器工作方式：普通对话推进 M1

当前用普通对话推进 M1，原 Goal 保持暂停。上下文压缩或恢复后，先读服务器工作目录内的 [运行交接](../../docs/NEW_CHAT_HANDOFF.md)，结合独立作业、日志、源码和检查点确认实际进度。交接负责记录进度，本页规定当前工作方式。完整 [研究方案](PLAN.md)、[接续配置](continuation_protocol_20261119.json)和[原冻结协议](protocol.json)仍是实验依据。M2 继续挂起，M1 比较中的 M2 条件固定。

## 运行完整训练

- 已有同版本、同条件的训练在跑时接续现有作业。已有经核验的 B8 和五库 DEV 结果时复用本轮终态。需要启动或恢复时，使用现有入口和独立作业，从兼容断点按协议完成 128 来源、8 批训练与五库固定 DEV 评估。沿用模型配置和连续账本。
- 启动或接续后，在交接中记下源码与配置、作业 ID、复现命令、日志及产物路径、最近有效检查点和下一步。运行程序逐批留存原生指标、逐来源结果、教师调用及复用、候选采纳与技能实际使用记录。核实作业可独立运行并已推进后结束本次对话回合，运行期间由作业写进度。

## 训练结算后复盘

- 用户发来普通消息后，复用本轮结果，逐库核对原生指标、同信息同预算对照、失败来源与技能演进。根据实际证据修复 M1，按改动影响范围决定复用兼容断点或从首个受影响批次重跑。新一轮有明确修订或运行依据才启动。
- 五库分别报告效果、覆盖、退化与费用。原冻结 TEST 及曝光记录保留，调试和选择只用 TRAIN/DEV。更新同一份运行交接，记录结论、证据和下一步。
