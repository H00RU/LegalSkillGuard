# Native support/refute execution-contract diagnostic

Declared prospectively on 2026-10-17, after completion and full preservation of
`legal_contractnli_native_grounded_fixed_tool_continuation_20261017_run02`.
This is a finite development diagnostic, not another independent learning run,
official TEST, method comparison, or a claim that the root cause is solved.

## Evidence and question

The completed fixed-tool B4 comparison has skill-minus-ordinary label +1/102,
joint exact -1/102 and true evidence -4 members. All seven lost true members
occur on Gold Contradiction questions predicted NotMentioned by the skill arm;
five were previously correctly classified, two were previously wrong Entailment.
This does not prove a faithful internal mechanism. Evidence acquisition and
retention remain separate problems: 29 missing Gold members are outside both
candidate pools, and both arms miss evidence on correctly classified questions.

Test whether making the model explicitly distinguish supporting evidence from
opposing evidence reduces this execution failure, and whether any improvement
exceeds the same intervention without skills. Do not edit a case-specific rule,
bank, source query, annotation, retriever or legal hypothesis.

## Frozen inputs and prospective intervention

Use all six already exposed B4 development contracts, in the original order:
430, 290, 622, 613, 383, 92. For each use both ordinary_M2 with no skills and
the exact last published 17-record bank, not a better earlier version. Reuse the
actual previous complete native request's user string byte-for-byte, including
full original NDA, all hypotheses, candidates, scores, named skills and source
receipts. No new fit, source reselection, teacher or weight update. The previous
response is not supplied as an instruction or used to construct the new answer.

Only two common input changes:

1. Replace the old four-field ordering sentence and append the same concise
   support/refute definitions to the common system message of both conditions.
2. Expand the original two-way coherent schema into three branches, adding
   `hypothesis_supported` and `hypothesis_refuted` as the first two fields:
   true/false -> original Entailment; false/true -> original Contradiction;
   false/false -> original NotMentioned. All three combinations are available
   for every question. The original choice, original index domain, evidence
   requirements, reason and allowed used IDs remain identical per class.

The lawyer judges both booleans from the exact original hypothesis and source.
The host never evaluates a semantic predicate, maps a generated partial answer,
reads Gold to select a branch, or repairs a verdict after generation. Original
`choice` is generated literally by the lawyer and scored directly. Empty source
hits do not establish NM; mere absence of support does not establish refutation.
The schema expresses only a generic three-way consistency invariant, not a
contract-specific answer or an executable learned verdict rule.
