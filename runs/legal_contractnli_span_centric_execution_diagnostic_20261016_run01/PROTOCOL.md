## Native answer and scoring fidelity

The native object first has `span_membership`, with a required key for EVERY
original zero-based SPAN and an explicit list of public hypotheses to which the
model assigns that fragment. Empty lists remain empty. `decisions` then gives
each hypothesis's original relation, short public reason and scoped skill IDs.
The actor still decides every membership and label from the complete source.

The observation archives the actual native response separately from the lossless
original-coordinate view. The view only transposes explicit `(span,hypothesis)`
memberships into a set for each hypothesis. It does not use Gold, candidate
scores, labels, skills, neighbours or any semantic judgement to add/erase members.
It never overwrites native content or fabricates another native response ID.

Unlike the old per-hypothesis `anyOf` grammar, the span-centric schema cannot
hard-enforce cross-object relation/evidence coherence. It is required in the
public instructions; any actual inconsistency remains uncorrected and is counted
and scored under the ORIGINAL label/span-set metrics. Report this constraint
difference rather than claim a pure field-order intervention. Invalid/truncated
outputs retain their native failures and original-score penalties, with no retry.
